# A diagram fence inside a blockquote never renders

Status: shipped in [v0.109.0](../../release/release-v0.109.0.md).

Record before the release: built on 2026-10-22 on the seat's branch; the section Built 2026-10-22 holds the evidence; it closes at the GA as shipped.

Record before the build: raised for v0.109.0 on 2026-10-22 by the lead, from the review seat's reading of the table-press item's range; closes in the round.

## What was seen

`diagramSource` in `web/packages/workspace-app/src/editor/widgets/diagram.ts` hands the renderer the fence interior's whole document lines, a blockquote's `> ` markers included, and `mermaid_render.ts` passes `source.trim()` to `mermaid.render` with no prefix stripped. A mermaid or mermaid-to-excalidraw fence inside a blockquote fails mermaid's type detection (mermaid 11.17.2 in Node on the quoted source: "No diagram type detected matching given configuration for text: > pie title Pets ..."; the same source at the top level and in a list item passes detection), so every quoted diagram shows its error face; the error names no line, so a press on the face takes the column-less fallback.

## Desired contract

A diagram fence renders the same inside a blockquote as at the top level or in a list item, and a renderer error on a quoted fence names the line and column of the fence's own text.

## What to do

Strip each interior line's container prefix up to the fence's column before the source reaches the renderer, the rule `codeTextStart` applies to a code line, and add each line's stripped prefix back to the column the renderer reports (the line needs no offset: the strip removes no line, and `parseErrorPos` carries the trim adjustment), so the caret on an error face lands where it does for an unquoted fence; a quoted fence whose code lines hold only their markers then has an empty source and, like an empty top-level fence, gets no widget; pins red first at the parent on the source a quoted fence hands a mocked renderer and on an error position's offset, with one mutant per guard.

## Boundaries

`widgets/diagram.ts` at `diagramSource` and the error-position path, the render entry if the stripping belongs beside `source.trim()`, and their tests; the editor's `design.md` diagrams paragraph where it states what the renderer receives. Changed with it: the table-press item's pin for a quoted fence whose one code line holds its marker alone, which gets no widget once its source is empty, and the doc comment above `placeCaretOnErrorLine`, which says the renderer reads a quote's markers as source; the face press's step then stops inside the interior for every fence that has a widget, so its bound guards an input no fence reaches, recorded as such. Not changed: the press and caret rules of the table-press item otherwise, the walker, the renderers' own parsing.

## Acceptance

1. Pins red first at the parent: a quoted fence's source reaches the renderer without its markers; an error column reported on a quoted fence maps back to the document's column; a quoted fence holding only its markers gets no widget; one mutant each.
2. `make web-check` green at the commit; check 180 alone three times at the landing in the integration guest.

## Lead's rulings 2026-10-22

The lead's words in task 32:

> **R1, where the strip lives: `diagramSource`.** The source it returns is each interior line past its container prefix, by the rule `codeTextStart` applies to a code line: for each line from `openLine + 1` to `closeLine - 1`, drop `min(fenceColumn, prefix)` characters where `fenceColumn` is the opener's column (`openFrom - lineAt(openFrom).from`) and `prefix` is the length of the line's leading run of spaces, tabs and `>`; join with `\n`. The strip removes no line, so `openLine`, the line count `placeCaretOnFirstCodeLine` and `placeCaretOnErrorLine` take from `source.split("\n")`, and `scanErrorLines`'s accent keep their meaning. The empty check `source.trim()` runs on the stripped source, so a quoted fence whose code lines hold only their markers has no widget, like an empty top-level fence. `mermaid_render.ts` and `excalidraw_render.ts` keep `source.trim()` and `parseErrorPos` as they are: the stripped source is also the face cache's key, the copy affordance's source and the viewer's, so the strip belongs before all of them, not beside the render call. Share the rule with `codeTextStart` (one helper for the prefix length, or `codeTextStart` itself over the line) rather than a second regex.

> **R2, the column maps back.** In `placeCaretOnErrorLine`, with `textStart = codeTextStart(line, fenceColumn)` as today, the caret with a reported column is `min(textStart + errorCol - 1, line.to)`; without one it stays `textStart`. The line needs no offset (R1 removes no line; `parseErrorPos` carries the trim adjustment). The doc comment above the function changes with it: the renderer receives each code line past its container prefix, and the column it reports counts from that line's text start. The error face's listener at 456 to 461 is unchanged.

> **R3, the face press's bound.** `placeCaretOnFirstCodeLine`'s loop ends inside the interior for every fence that has a widget, since R1 leaves a widget only to a fence with a line of text; its fallback to the first interior line is a guard no fence reaches. Keep the code; say so in one sentence of the row's closing section. The table-press item's press and caret rules are otherwise unchanged.

> **R4, the pins, red first at the base** (`diagram.test.ts`, the existing harness; each on its own assertion): (1) acceptance 1a: a mermaid fence inside a blockquote (`> ```mermaid`, `> pie title Pets`, `>   "Dogs" : 3`, `> ````) renders a face, and `mermaidLib.render`'s second argument is `pie title Pets\n  "Dogs" : 3` (the markers and one space gone, the code's own indentation kept); red at the base on the argument carrying `> `. Add the excalidraw arm in the same test if the mock at 45 exposes its source (`parseMermaidToExcalidraw`'s first argument); if not, say so. (2) acceptance 1b: the same quoted fence with a renderer answering an error that names line 1, column 5; a press on the face lands the caret at the code line's `from + 2 + 4`; red at the base, where it lands at `from + 4`. A top-level control in the same test keeps `from + 4`. (4) the table-press case "a quoted fence whose one code line holds its marker alone" at 724 to 729 leaves the `test.each` (it has no face to press once its source is empty) and a quoted fence with text takes its place: `> ```mermaid`, `> ^pie title Pets`, `>   "Dogs" : 3`, `> ```` with `within: "Blockquote > Document"`, if no such case is in the list already; the caret rule is unchanged for it, so it is green at the base and at the tip. ## Built 2026-10-22

Its doc comment and the editor `design.md` describe the same source and column contract. `placeCaretOnFirstCodeLine` is unchanged: every fence with a widget has a line with text after its prefix, so its loop stops inside the interior and its fallback to the first interior line guards an input no fence reaches.
