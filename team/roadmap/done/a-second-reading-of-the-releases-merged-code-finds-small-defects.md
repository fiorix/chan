# A second reading of the release's merged code finds small defects

Status: shipped in [v0.127.0](../../release/release-v0.127.0.md).

Record before the release: raised by the owner on 2026-11-10, before the GA: "spawn a couple of reviewers for the frontend and backend code we're merging onto v0.127; i suspect they may find more small issues, and tightening of the code, updates to the docs". Three read-only readers took everything merged since v0.126.0 (`028f179b7..40959b57e`): the web packages and the manual; the crates and the top-level docs; the desktop, the gateway, packaging and CI. None found a defect that blocks the release. Between them they reported 12 small defects, 16 places to tighten and 20 documents that no longer matched the code. The code fixes were made the same day on four branches, one commit to a finding, each with a test shown red without its fix where a test can pin it, and merged into the integration branch: the gateway and packaging (`4f06db720`, merged as `a80424db8`), the web app (`8482c4d9a`, merged as `2d40eb607`), the desktop (`ccc7a350c`, merged as `aa031e0a1`) and `chan metrics` (`dba36a428`, merged as `afdbfa6f7` and `3dba12a14`). The documents the readers found behind the code (the manual, the design notes, the agent guides and the release skill's Windows step) and a handful of stale comments were corrected on `docs/v0127-review` (`6fdc428e5`, six commits) against the code as merged, and merged as `e43c98c60`. The owner ruled the same day on what the readers left open, and then closed the release to new work: what was not fixed by then is in v0.128.0.

## What was there

- **The web app.** A body theme command run in a window without a workspace stored a table holding only the surface it set, so "Dashboard theme: dark" in a terminal window, offered there since this release, dropped the Editor and Terminal themes for every window; a stored body theme did not reach a terminal window's Dashboard or terminal either. The terminal menu's Find row showed the page find chord (Ctrl+F off macOS, none in a browser) where the terminal's is Ctrl+Shift+F. In the terminal's find bar Find next had no working chord on the Linux and Windows desktop: the key bridge leaves Ctrl+G to a focused terminal tab and nothing in the bar took it. A restart with the find bar open left the bar over a terminal it had not searched.
- **The desktop.** A second launch answered while the first desktop was still restoring its windows, or a Dock click on macOS in that time, opened a standalone terminal that was saved and came back at every launch. A handoff listener that failed to start dropped the single-instance claim, so a second desktop could run beside the first. A launch right after Quit waited 5 s for a drain whose own bounds add up to 13 s, and then exited 0 with no desktop left. A minimized window's row in the Window menu did not restore the window.
- **`chan metrics`.** After `chan devserver stop`, which leaves the unit file, and a `chan devserver run` on another port, the command dialed the unit's port and found nobody. `--watch --json | head -n1` panicked on the closed pipe. `--watch` lost a Ctrl-C that arrived during a read. An idle Varlink client ended the adapter with status 1. A failed first scan of the chan home was printed as a "last completed total" with its error hidden, on the command and on the Dashboard's Metrics slide. A view of a later schema was reported as a missing field, not as an unsupported schema. A `--url` that already named `/api/metrics` was read as `/api/metrics/api/metrics`. The command led `chan -h` and had no long help, and `cs dashboard --help` contradicted itself about the carousel preference and the slide ids.
- **The gateway's delivery.** The database roles suite, which Gateway CI runs since this release, passed with a grant removed: it asked `has_table_privilege` about comma lists, which is true when any one listed privilege is held, named six tables nowhere, and counted any psql error as a refusal. The sdme driver that runs it locally had no contract test and left its guest behind when a create was interrupted. `gateway-ci.yml` declared no `permissions`.

## Contract as built

1. A body theme write merges the one surface over the table the server holds, and a window without a workspace applies the stored body themes.
2. The terminal menu's Find row shows the terminal find chord. In the find bar the Find next and Find previous chords step, where the desktop's key bridge leaves them to the page. A restart closes the find bar and keeps its query.
3. A desktop asked to come forward, or reopened from the Dock, opens no terminal while its boot is restoring windows or a window has a record and no native window yet. A desktop whose listener cannot start keeps its claim. A launch beside a desktop that says it is shutting down waits up to 20 s for the endpoint, boots when it comes free and exits 1 past that. A Window menu row restores a minimized window before raising it. The single-instance contract is restated in [its item](a-second-desktop-launch-runs-beside-the-first.md).
4. `chan metrics` on Linux tries the recorded port when no listener of the caller's is at the unit's pinned address, under the same ownership check. Its output ends with status 0 when its reader is gone, and one Ctrl-C ends a watch whenever it arrives. An idle Varlink client, and one that stopped reading or left, end the adapter with status 0. A failed scan prints its error, on the command and on the slide, and names a last completed total only when there is one. The schema version is read before the view is decoded, and `docs/metrics.md` states the rule for readers. A `--url` may name the route. The command has long help and is listed beside `ps`.
5. By the owner's rulings: the scan duration is `scanMs` on the wire, beside `sampledAtMs` and `elapsedMs`, before the schema's first release; and privacy mode hides the Metrics slide's host name and chan home path, in the form the launcher uses for computer names and paths.
6. The manual covers the Metrics slide and `chan metrics`, find in a terminal, the tmux title bar and the pane list's window name, privacy mode, sharing a devserver by link, and what a second start of the desktop does; `chan-metrics` has a design note; the design notes of the CLI, the server and the web app describe metrics, find, the Dashboard's slides and the handoff's endpoint claim; the agent guides name Gateway CI's packaging job and the roles suite, and the release skill's Windows step names a build that makes `chan.exe` first.
7. The roles suite compares every privilege the two application roles and `PUBLIC` hold on the schemas, tables, columns and sequences of `public` and `tower_sessions` with an exact list, in both directions, and counts a refusal only as SQLSTATE 42501. Each run also drifts nine grants and requires the check to name exactly those. The sdme driver has a stand-in contract check under `make sdme-contract-check`. Gateway CI's token is read-only.

## Boundaries

- No grant changed. The roles suite at the base was shown to pass with `UPDATE` on `api_tokens` removed and with identity's `INSERT` on `api_token_audit` removed; the exact suite fails on both and names the table and privilege.
- Left for v0.128.0 by the owner, with the [small findings](../v0.128.0/small-findings-of-the-v0127-second-reading-are-still-open.md) collected in one row: [a launch beside a desktop that does not answer shows nothing](../v0.128.0/a-launch-beside-a-desktop-that-does-not-answer-shows-nothing.md), [the Windows handoff pipe](../v0.128.0/the-windows-handoff-pipe-takes-clients-early-and-collides-across-accounts.md), [coming forward to a minimized window](../v0.128.0/coming-forward-to-a-minimized-window-may-not-activate-the-app.md) and [the unused-token test](../v0.128.0/the-unused-token-test-reads-its-counters-before-a-cut-could-run.md).
