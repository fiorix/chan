# A terminal with no session moved to another window arrives as a bare terminal

Status: shipped in [v0.109.0](../../release/release-v0.109.0.md).

## What was seen

By source: a terminal tab that holds no session id travels to another window as its kind and its title alone, and the target window opens a bare terminal in its place (`web/packages/workspace-app/src/components/Pane.svelte` 918 to 936 and 1054 at the round's integration branch). Its group, working directory, spawn command and environment are dropped, and nothing tells the user. A tab holds no session id before its first session frame and after its session has ended. A hand drag is slower than a local socket's first frame, so the cases a person can reach are a tab that cannot connect (the server restarting) and a tab whose session ended.

Not established: a reproduction; how often either case is met; what the target shows for a tab whose session ended.

## Desired contract

A terminal moved to another window arrives as what it was, or the target says what it could not carry.

## What to do

Reproduce both reachable cases in a browser with two windows; then decide between carrying the tab's own fields in the cross-window payload and a notice at the target, with the rule that a command's environment does not travel through a shared channel.

## Boundaries

`components/Pane.svelte` (the cross-window payload and its receiver), the tab constructors in `state/tabs.svelte.ts`. Not changed: the same-window move, which clones the live tab.

## Acceptance

1. Both reachable cases reproduced or shown unreachable, with the engine named.
2. The decision recorded here, and pinned at the store level and by one browser check with two windows.

## Built 2026-10-22

A terminal tab with no session moves to another window with the session snapshot a reload writes (`crossWindowTerminalSnapshot`), its group and working directory beside it, and `left`, the names of what does not move: `"session"` always, `"command"` when the tab holds a start command and `"environment"` when it holds a spawn environment, never their values (`crossWindowPayload` in `web/packages/workspace-app/src/components/Pane.svelte`). The target's drop rebuilds it through the reload's restore in `openMovedTerminalInPane` (`state/tabs.svelte.ts`), which shares one placing helper with `reattachTerminalInPane`; the tab starts a new shell under its title, group, working directory, profile, Details card, Rich Prompt draft with its caret, height and bubble, and Team Work draft, and keeps no session id, no negotiated keyboard protocol and no controlled flag, which belong to a running session (a snapshot from this build holds none of them; one from another build might). The target shows a persistent status in W1's words (`movedTerminalStatus`); an older build's `{kind, title}` payload arrives under its title with the session named. The source's drag-end treats both moves alike, marking the tab moving and closing it with force, so a tab with no session leaves without the "still running" confirm, and the terminal's close sink (`closeTerminalForTab` in `components/TerminalTab.svelte`) keeps a moved tab's Rich Prompt draft, for the live move as for the move with no session (W2). The workspace app's design text gains the section "A terminal moved to another window", and TD-03 of `scripts/e2e/scenarios/tab-drag-and-drop.md` says what a move with no session does.
