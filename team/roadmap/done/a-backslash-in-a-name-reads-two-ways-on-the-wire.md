# A backslash in a file name reads two ways on the wire

Status: shipped in [v0.101.0](../../release/release-v0.101.0.md).

Record before the release: raised during v0.101.0 on 2026-09-26 by the independent review of the frontend dedup order that unified `parentDir` and `basename` (`dev/v0101-team/reviews/review-Frontend-4.md`, finding 5, in the development tree). A source reading against `main` at `cdd266b09`; not reproduced.

## Owner ruling

Accepted on 2026-09-26 as the lead recommended, with the raw name as the one spelling: `\` is a legal character in a POSIX name and the one-level listing already keeps it, so the recursive walks and the index keys stop rewriting it on Unix, pinned by a Unix-only test that lists, walks, searches and graphs a workspace holding `a\b.md`; the SPA's `basename` copies then fold onto that one rule in the frontend dedup rounds. ## What was seen

On Unix a file may be named `a\b.md`. chan-workspace keeps that raw name in the one-level listing (`crates/chan-workspace/src/rooted_fs.rs:864`) and rewrites `\` to `/` in the recursive walks and the index keys on every platform (`crates/chan-workspace/src/fs_ops.rs:841`, `:876`, `:1950`, `:1990`). The SPA therefore receives `a\b.md` from `/api/fs` and `a/b.md` from the tree walk for one file, a spelling that names no file on Unix, and search, the graph and the report never hold the file at all (corrected below). Its own `basename` helpers disagree with each other on the same name (`state/format.ts` splits on `\`, seven kept copies do not). No single client-side rule can make the name read the same on every surface while the server sends two spellings.

**This account was corrected on 2026-09-28** by the order that built the Rust half, whose first part read every site (`dev/v0101-team/followups/followup-Runtime-Lead-22.md` in the development tree, "The outcome" and section 2) and whose pins showed it at the base, red first (`dev/v0101-team/reports/report-Runtime-33.md`, "Red first"). The paragraph above said that the tree walk, search and the graph sent `a/b.md` for such a file, so that one file had two spellings. On Unix the rewrite did not give the file a second spelling: it made the file unreachable through every store derived from the walk. At the base every recursive walk, the index key, the watcher's event path, a removal's key and the report's walk rewrote `\` (`crates/chan-workspace/src/fs_ops.rs:877`, `:2027`, `crates/chan-workspace/src/watch.rs:1786`, `crates/chan-workspace/src/workspace.rs:2098`, `crates/chan-report/src/walk.rs:236`, at `b39274a1a`), and every writer of a store reads the file back through its key, which named no file. So the tree walk, `/api/fs` without a directory, filename and workspace search and MCP `list_files` sent `a/b.md`, a path that read back as not found; content search, the graph and the report held nothing for the file; the fs graph's scope for it answered 404; and a read of the raw name, `a%5Cb.md`, already worked. The pins that show each at the base are listed under "What shipped". A real `a/b.md` beside it met three faults of the same cause, closed below.

## Desired contract

One spelling of a name crosses the wire on every route, and the SPA's path helpers follow that one rule.

## What to do

Decide the spelling (the raw name, since `\` is a legal character in a POSIX name and the one-level listing already keeps it; the walks and index keys then stop rewriting it, or the rewrite is documented as the contract and the listing follows it), fix the side that disagrees, pin it with a test that lists, walks, searches and graphs a workspace holding `a\b.md`, and then move the SPA's `basename` to the one rule so the seven kept copies fold. Windows never produces such a name; the test is Unix-only.

## Boundaries

`crates/chan-workspace/src/rooted_fs.rs` and `fs_ops.rs`, the wire tests in chan-server, then `web/packages/workspace-app/src/state/format.ts` and the kept copies the frontend dedup report lists.
