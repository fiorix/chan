# Bug reports

> Status: shipped in [v0.75.0](../../release/release-v0.75.0.md): every report closed by the v0.75.0 bug-fix round (see bug-fixes.md).

- Editor: 
  - On pages with tables, we cannot click the line after the table, especially if what comes after the table is a heading
  - We need to teach agents via `chan dump-skill` that markers like `@pagebreak` and `@today` are only for the live editor. They do not work if the agents write files with these markers. They have to write the materialised version instead, e.g. the `<hr class="chan-page-break">` for `@pagebreak` and the date formats we support for `@today` and `@date`
  - The editor debounce on devserver works great when the network is stable and fast, but flakes when the network is slow; I want to try to reproduce by adding latency between the frontend and backend while smoking via the headless browser, this should be reproducible and we have to fix it
  - On mermaid code blocks that contain errors (and we often get this from agent-generated mermaid diagrams because they include special characters like ',' and ';' and '-' and those don't render, they error) we cannot freely navigate the codeblock with the arrows: i think it is correct that the codeblock points which line has the error when we click to edit the code block, but if we press arrow UP the cursor jumps over to the line before the diagram begins, which is extremely counter productive for users editing, and frustrating because they cannot click on the line with the error too: the mouse click lands on the line *after* the error in the code block, so effectively the only way to edit the error is pressing arrow BACK all the way to the previous line in the column where the problematic character is
  - Slide deck:
    - There seems to be an empty line before each '#' header in preview and present; meaning the first '#' renders with a very large top margin, pushing all the contents of the slide down
    - When we export the slides to PDF, the size of the diagrams still change in relation to how they show in preview and presentation mode
- More on network flakes, but this time about the `chan devserver --join` and the sensitivity of the health checks; when the network is less stable, the control terminal seems to be very sensitive to missing heartbeats, to the point that when I am running for example `chan devserver --restart` on a stable network the terminal quickly flips through the `reconnecting` but shortly reconnects... on slow networks, the --join lags and we end up terminating the join early and forcing the user to close the control terminal and reconnect manually clicking connect again
