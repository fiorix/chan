# A save in chan's editor sends three watch frames for its temporary files

Status: built on 2026-10-22 on the seat's branch; the section Built holds the evidence; it closes at the GA as shipped.

## What was seen

The core's atomic writer (`crates/chan-workspace/src/fs_ops.rs`, `atomic_write_stream_in` and `atomic_create_in`) writes through cap-tempfile: an unnamed temporary file, linked under a UUID name beside the target and renamed onto it. Under inotify that is an open and a modify on a `#<inode>` path, a create on the UUID name and a move pair under one cookie. The watch path's dispatch (`crates/chan-workspace/src/watch.rs`) has no rule for the writer's names, and the server bus's self-write origin (`crates/chan-server/src/bus.rs`, `event_self_write_origin`) notes the target only, so every save in chan's editor sends three watch frames: a `#` path modified, a UUID path created, and that path renamed onto the target. The bus's no-frame rule for a window-noted modification never meets them, since the save reaches it as a rename. Each frame takes the page's generic branch: per autosave a workspace request, a relist of the target's directory, a dropped link-kind cache and a graph cue, and, to read at the build, a co-viewer's changed-on-disk flag. The graph-refresh item's reading counted 45 frames, 15 of each, for 15 autosaves over 13 s of typing. By cap-tempfile's source the same class holds on macOS and Windows (a randomly named file renamed onto the target, without the `#<inode>` event); neither was run.

## Desired contract

On Linux a save in chan's editor reaches the watch path as one event on the target. On Linux a save that replaces a file sends no frame while its windowless note is live; a save that creates one reaches every window as one `Created` carrying the writer's window, as every creation does. Reserved temporary-file events reach no page. On macOS, Windows and FreeBSD, target events keep the backend's shape and count, as recorded in the build's limits.

## What to do

A design first, read by the review seat before code, since the reserved name and the dispatch rule are a contract across the writer, the watcher and the bus: the writer names its temporary file under a reserved `.chan-` leaf beside the target, which the scope policy excludes, opened create-new; the dispatch turns a rename from such a name onto an included path into a modified or created event of the destination and drops the temporary's own events; a watch pin (one event, on the target) and a bus pin (a window-noted save sends no frame); the macOS and Windows watchers read for the same rule.

## Boundaries

`crates/chan-workspace/src/fs_ops.rs` at the writer's naming, `crates/chan-workspace/src/watch.rs` at the dispatch, their tests, and the server's bus pins. Not changed: the write's durability (the rename stays), the scope policy's other rules, the page.

## Acceptance

1. The design read by the review seat; the watch pin and the bus pin red first at the parent.
2. The chan-workspace and chan-server suites green at the commit.
3. The graph-refresh item's reading driver run at the commit beside the base: 15 autosaves send no generic-branch frame, with the counts recorded here.

## Lead's rulings 2026-10-22

From the lead's ledger, 06:59Z, on the design, ruled and dated 2026-10-22 (the row's "What to do" stands; these fix its open points):

- "R1, the namespace. The reserved prefix is `.chan-write-`, for the capability writer's temporary, `atomic_create_in`'s stage directory and the ambient `atomic_write`, at any depth; one shared predicate (`is_atomic_write_temp_name`, which recognizes the reserved prefix and nothing else: the UUID and `#<inode>` shapes it names today go, since nothing writes them any more); the scope policy returns its hard exclusion for a reserved component before the ignore and negation rules; a stage's subtree is excluded whole; no cleanup by age and no deletion of an entry the writer did not create."
- "R2, create against replace. The kind of the published event is the writer's to tell, not the dispatcher's to guess: `atomic_write_stream_in` already stats its target to capture its metadata, so it knows whether it replaces or creates (`write_text` creates known-text paths), and it says so in the reserved name (the one excluded prefix, then a fixed marker for a creation; the designer picks the spelling). The dispatcher maps a rename from a reserved source onto an included destination to `Modified` of the destination, or `Created` of it under the marker, by the name alone. Reason: the bus forwards a window-noted `Created` with attribution and sends nothing for a window-noted `Modified`, so one kind for both would hide a new file from the other windows' listings, and `Created` for both would send a frame for every window-noted replace, which the row forbids."
- "R3, Q1 (the platforms). The portable contract stands as the row states it. The temporary's own events are dropped by name on every platform, stateless. The target's one event: on Linux the dispatcher keeps a small bounded memory of reserved rename sources keyed by notify's tracker (the inotify cookie): a `From` with a reserved source is remembered and dropped; the `To` whose cookie it matches becomes the normalized event and the cookie is forgotten; a `Both` with a reserved source is dropped whatever its cookie (the existing exclusion of a filtered source does that); a `To` matching no remembered cookie is the arrival it is today. The memory holds a fixed small number of cookies (the designer names it; sixteen covers the writers one process runs at once) and evicts the oldest, so a `From` whose `To` never comes costs nothing; a cookie evicted before its `To` leaves that publication as an arrival (`Renamed` with the destination alone), still one event on the target with its kind unnormalized, and the design states that loss. The memory is the dispatch's own state, Linux only by cfg. On macOS (FSEvents `Any` per path, no association) and Windows (separate `From` and `To`, no tracker) the target's one event keeps the shape the backend gives it (macOS `Any(target)` on the `(Some, None)` arm the consumer stats; Windows `To(target)` as an arrival); no adjacency matching; the row records as those platforms' limit that the kind is not normalized there and a window-noted publication is forwarded with attribution as every rename is today; both by source, run on none, as the row says."
- "R4, Q2 (metadata). Taken: the preserved mode and xattrs are applied to the temporary through its open descriptor before its fsync and the rename; the published target is not touched after the rename; failures stay best-effort as today, with the mode and xattr pins kept."
- "R5, Q2 (the standalone surfaces). Taken for the watcher: `is_temp_churn` recognizes the reserved names through the shared predicate (its ticket condition stays), its pin moved to the new shapes, the ordinary-user-file controls kept. Not taken for listings: `RootedFs::list_with` shows what is on disk, so a crash orphan under the reserved name is visible in a listing, excluded from the index and the watch, and removed by hand; the row records that as the limit (a listing change is a page-visible change outside the row's boundaries, and the orphan's name says what it is)."
- "R6, the other destinations. As designed: a reserved-source rename onto an excluded destination produces no event; onto a directory a `Created` directory event with the registration kept, never described as a save; reserved-only events of every kind dropped; the ordinary rename path, its cookies, the generation and the loss handling unchanged."
- "R7, pins, mutants and the proof. The red-first pins as designed (the real Linux save under the owned watcher with the included sentinel as the fence; the bus pin with the raw index receiver and both page receivers), the deterministic backend traces with the cookie memory's cases (two reserved renames interleaved within the memory, one past its size, a lost `To`, an unrelated rename reusing a cookie value after eviction, the Windows and FSEvents sequences), one mutant per guard as the design lists them plus the memory's three (never forgetting, never remembering, a `To` matched without its cookie), the standalone fixture moved to the new shapes with its controls. ## Built 2026-10-22

The design was accepted with the rulings above. The built namespace is `.chan-write-`, hard-excluded before repository ignore and negation rules. Capability temporary files and create stages are exclusively owned, collision-bounded and cleaned up on failure; the ambient atomic writer uses the same reserved prefix. Writability probes exclusively create and remove a reserved name on every platform. The capability writer applies preserved mode and xattrs through the temporary descriptor before fsync, closes it before the same-parent rename, and fsyncs the parent; its creation marker comes from the preflight existence stat.

On Linux the dispatcher retains sixteen reserved `From` cookies, consumes a matching `To` before destination filtering and emits one target `Modified`, or `Created` for the `new-` marker, without rename endpoints or cookie. It drops the redundant reserved-source `Both`, preserves directory registration and ordinary rename behavior, and leaves a missing or evicted association as an arrival. The standalone mutation bus drops events whose every named leaf is reserved without requiring a ticket, including read-time probes; it preserves empty and mixed-path events and ordinary UUID and `#123` user files. The directory-listing behavior is unchanged.

The earlier measurement's 45 frames remains its observation. Its third frame was the UUID `From` half, not a paired rename onto the target: editor flushers reserve windowless, so the target-bearing `To`, `Both` and metadata events were already suppressed. The earlier driver's path-only reading did not establish the co-viewer's changed-on-disk consequence. The bus pins here record both endpoints and complete event lists.

The original-parent pins at `abada744fc8a9b51868406f9ce63888e0390bfdd` failed on their assertions: both real-watch save arms, the reserved probe, both real bus save arms, and both standalone reserved-filter pins, each cargo run exiting 101. The bus pins assert the entire raw index list and both page lists before an included sentinel, with its exact positive-control frame asserted on each receiver in the target's subscribed directory. A replacement expects one raw `Modified` and no page frame; a window-noted creation expects one raw `Created` and one attributed frame on each page receiver. The test note window spans its bounded collection; production note expiry is covered separately.

Focused checks passed as `ubuntu` in `chan-v0109-runtime`, with two cargo jobs and test threads, denied Rust warnings and disk-backed temporary and target directories. Stage one passed 85 `fs_ops` tests and the probe, ambient-writer and create-stage integration pins, with fmt and crate clippy exiting 0. Stage two passed 12 deterministic dispatcher traces, 6 real-watch integration checks and 37 watcher tests (the 37 include the 12 traces), with fmt and crate clippy exiting 0. Stage three passed 37 bus, 10 standalone mutation and 8 standalone watcher tests, with fmt exiting 0; the real standalone pin covers both creation and replacement, preserving attribution to writer and viewer. Seven stage-one, fourteen stage-two and five stage-three separately compiled mutants failed their named assertions, each cargo status 101. In particular, omitting the writer's creation marker fails both the real-watch creation pin and the real bus creation pin. All mutated sources were restored and hash-checked.

Limits: on macOS, Windows and FreeBSD the temporary's events are dropped by name; the target's events keep the backend's shape and count, not established by source (FreeBSD: a removal of the target and the parent's catch-up `Created` per file); run on none. A process death or power loss can leave a reserved file or stage directory visible in listings, excluded from indexing and watching, for manual removal. Recovering a replacement-shaped orphan by renaming it inside chan normalizes it to a window-noted `Modified`, so other windows see it at their next relist; a creation-marked source retains `Created`. A standalone Linux replacement leaves one of three target echo allowances unspent inside the 1.5-second ticket tail, so a genuine external change there can be swallowed. A save whose note expires before delivery is unnoted. Copy stages and terminal-upload temporaries are outside saves and keep their names.
