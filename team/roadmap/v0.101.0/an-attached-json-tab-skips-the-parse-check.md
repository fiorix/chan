# A JSON tab attached to a document session skips the save's parse check

Status: accepted for v0.101.0 by the owner on 2026-09-27; raised during v0.101.0 on 2026-09-27; read in code and not reproduced, a source reading at `3f60c072d`. "What was seen" was corrected and completed on 2026-09-27 from a code map of the client and of the server's document sessions (`dev/v0101-team/int26-docs/codemaps/json-tab.md` in the development tree, read at `836d2508a`, nothing run), with each line read again at `d1fe06c86`.

## Owner ruling

Accepted on 2026-09-27 for v0.101.0 as the lead recommended. The shape of the fix is still to be ruled: keep `.json` tabs out of document sync, the smaller, which gives up live co-editing of `.json` files, or have the authority hold back its flush of a `.json` document that does not parse, which needs the server's document sessions read first. It is asked of the owner when the order is cut, once those sessions have been read.

On 2026-09-27, with those sessions read, the owner ruled the shape, the third of the ways "What to do" lists: the save's check is dropped for `.json`, so a `.json` buffer is saved as typed on every editor path, as any other text file the editor autosaves, and the tree view says when it does not parse. The check stays for a drawing in source mode. "Desired contract" and "Acceptance" below were written before this ruling and are rewritten to it when the order is cut.

## What was seen

The workspace app refuses to save a `.json` buffer that does not parse. `performSaveOnce` in `web/packages/workspace-app/src/state/tabs.svelte.ts` runs `validateJsonBuffer` on a `.json` or Excalidraw tab and, when the buffer does not parse, sets "JSON parse error" on the tab and writes nothing (`:5788-5797`). The comment above `performSave` gives the purpose: invalid JSON written to disk would surface as a parse error the next time a tool or the app's own viewer reads the file, too late to recover the typo, so the write is refused at the editor boundary (`:5726-5731`).

That check comes after the hand-off to a document session. For a tab attached to one (`isDocAttached`, `:5689-5692`: attached, connecting or reconnecting), the save asks the registered session delegates first and, when one answers `saved`, returns before the check (`:5763-5773`). The document sync delegate (`registerLiveSessionKind` in `state/docSync.svelte.ts:1302-1314`) asks its session to flush, which pushes any edit not yet sent and waits until the authority has confirmed every local edit and reports itself clean (`flush`, `:434-455`; `checkFlushWaiters`, `:1189-1203`), and answers `saved` when that succeeds. Neither reads the buffer. While a tab is attached its edits reach the authority as they are typed, as collaboration updates, and a save means a flush rather than a write (the module's doc, `:1-7`). For such a tab the check runs only once its session no longer owns its saves: after a failed flush has degraded it while its socket is still open, or after the session has stopped for good (a CRLF document, a document too large, a refused attach, a registry close or the capability off), where the classic path resumes (`isDocSavePaused`, `tabs.svelte.ts:5694-5707`, asked at `:5787`; `isOutagePaused`, `docSync.svelte.ts:365-374`). This sentence is corrected: it named the failed flush alone.

A `.json` tab in source mode attaches. Document sync is on by default (`DOCSYNC_DEFAULT_ON`, `:71-75`) in a workspace window (`docSyncEnabled`, `:133-149`), and `isDocSyncEligible` takes a tab in source or wysiwyg mode whose path is editable text and not an Excalidraw scene (`:156-164`); `.json` is editable text (`TEXT_EXTENSIONS` in `state/fileTypes.ts:71`, `json` at `:163`). A `.json` tab in its default mode, the `pretty` tree (`defaultModeForPath`, `tabs.svelte.ts:107-112`), does not attach. Excalidraw scenes never attach to document sync, but a scene in canvas mode attaches to a scene session (`isSceneSyncEligible`, `state/sceneSync.svelte.ts:115-123`), whose save delegate also answers `saved` before the check (`:1005-1012`), so a scene's check runs only on the path without a session; the scene authority writes its own serialization of the scene, which is JSON by construction (`serialize_file`, `crates/chan-server/src/scene_sessions/scene.rs:552-588`, used at `crates/chan-server/src/scene_sessions/mod.rs:1067`). This sentence is corrected: it said that a scene's check always runs.

**What the server writes, and when.** Each typed character is pushed to the server's document session, which accepts the batch at the matching version having checked only the change set and its byte budget, commits the text, marks the session dirty and fans the update to every attachment, the sender's echo confirming its edit (`DocAttachHandle::push`, `crates/chan-server/src/doc_sessions/mod.rs:1312-1378`). The tab then reads clean although the disk does not hold the text yet, since its saved text follows the confirmed one (`writeSaved`, `docSync.svelte.ts:1152-1156`, called at `:1116`). A flusher wakes every 200 ms (`FLUSH_TICK`, `doc_sessions/mod.rs:95-97`; `spawn_flusher`, `:2262-2293`) and writes every session, attached or not, whose dirty mark is 800 ms old (`DOC_FLUSH_DEBOUNCE`, `:78-80`; `flush_pass`, `:1662-1683`). The mark is stamped when the session turns dirty and later edits do not move it (`mark_dirty`, `crates/chan-server/src/collab_sessions/mod.rs:117-130`), so the 800 ms run from the first edit not yet written, not from the last. The write puts the whole text on disk atomically when the file has not changed underneath (`flush_session_locked`, `doc_sessions/mod.rs:1815-1870`; `write_text_if_unchanged`, `crates/chan-workspace/src/rooted_fs.rs:694-723`). Nothing on that path parses the text or reads the extension: the write checks that the path is editable text and the text's UTF-8 and byte budget (`rooted_fs.rs:701-703`, `:478-499`), and the session module's one use of `serde_json` outside its tests serializes its frames (`doc_sessions/mod.rs:376`). A test pins the timer's write with no client action (`flush_debounces_writes_and_stamps_token`, `:3656-3684`). So in a workspace window a malformed `.json` typed in source mode is on disk about a second after it is typed, with no save, by the two constants and not measured. A close or a switch to the tree releases the session, at once for a close and after a 250 ms linger for a switch, and the last detach asks the flusher for a write at once (`tabs.svelte.ts:3563-3567`; `release`, `docSync.svelte.ts:550-561`, the linger at `:77-82`; the handle's drop, `doc_sessions/mod.rs:1434-1455`). The tree's hint then says that saves are blocked until the buffer parses (`src/editor/JsonPretty.svelte:47-53`), which for such a tab is false: the text is already on disk.

**What a save adds: nothing to the write.** The client's frames are a push, a pull and a cursor (`ClientFrame`, `crates/chan-server/src/routes/doc.rs:46-70`), and none asks for a write, so a save's flush waits for the timer's write or a detach's and never asks for one; it gives up after 4 s with no frame or 30 s in all and degrades to the classic path (`DOC_FLUSH_TIMEOUT_MS` and `DOC_FLUSH_CAP_MS`, `docSync.svelte.ts:98-109`). The workspace app has no save command, `app.save` being left out on purpose since the autosave covers the write (`src/App.svelte:1446`), and the autosave is not scheduled for an attached tab (`App.svelte:261-268`).

**What the check's refusal does where it runs.** The refusal sets the tab's error, which replaces the whole editor with an error placeholder under a red toolbar line (`src/components/FileEditorTab.svelte:1280-1283`, `:1320-1321`). A close saves a dirty tab first, and when the check refuses, the close returns with the tab still open and dirty and says nothing of its own (`confirmCloseTabs`, `tabs.svelte.ts:2854-2878`, the save at `:2871` and the refusal at `:2877`). With no save command, the autosave is where a tab without a session meets the refusal (`App.svelte:266-267`). No test in the workspace app asserts the check's refusal, attached or not: "JSON parse error" appears once in the app, where the check sets it (`tabs.svelte.ts:5794`).

## Desired contract

A `.json` buffer that does not parse reaches disk from no editor path: attached to a document session or not, the tab says the JSON does not parse, as a save without a session does, and the file keeps the last content that parsed.

## What to do

Decide the shape first. Two meet the contract: keep `.json` tabs out of document sync, as Excalidraw scenes are, so every save takes the path with the check; or have the authority hold back its flush of a `.json` document that does not parse, and have the session's save report the parse error on the tab. The first is the smaller and gives up live co-editing of `.json` files; the second keeps it and needs the server's document sessions read first. Withdrawing the item instead leaves attached `.json` tabs as they are, and then the check's comment should say that it guards only the path without a session. Red first: a `.json` tab attached to a session in source mode, a buffer that does not parse, a save, and the check shown to be skipped.

A third way, which the reading above makes possible and which changes this item's contract: drop the check for `.json`, so every editor path writes a `.json` buffer as it is, as the attached path already does. It is the smallest change, the check's `.json` arm and the comment above `performSave` (`tabs.svelte.ts:5726-5731`, `:5788-5797`) and the tree's comment and hint that saves are blocked (`JsonPretty.svelte:7-10`, `:50-53`), and it removes the refusal that replaces the editor and holds a close on the path without a session. What it costs is the desired contract above: a `.json` that does not parse would reach disk from every editor path, and the typo would surface only when the tree or another tool reads the file, which is what the check's comment says it exists to prevent. The Excalidraw arm of the check would stay.

## Boundaries

`web/packages/workspace-app/src/state/tabs.svelte.ts` (`performSaveOnce`) and `state/docSync.svelte.ts` (`isDocSyncEligible`, the save delegate) and their tests; for the second shape, the server's document sessions (`crates/chan-server/src/doc_sessions/`, `routes/doc.rs`), read above for what they write and when. `.json5` and the other JSON-like formats stay outside the strict check. Excalidraw scenes are unchanged.

## Acceptance

1. In a workspace window with document sync on, a `.json` tab in source mode whose buffer does not parse shows the parse error on save, and the file on disk keeps its last content that parsed, pinned by a test that drives the attached path, or, under the first shape, by a test that such a tab never attaches.
2. A test pins the check's refusal on the path without a session.
3. A `.json` buffer that parses saves as it does now, attached or not.
