# The terminal tenant answers for a registered home workspace

Status: accepted for v0.101.0 by the owner on 2026-09-26; raised during v0.101.0 on 2026-09-26 by an independent reading of the fix for [a-hung-root-stalls-desktop-close-and-quit](a-hung-root-stalls-desktop-close-and-quit.md), widening two items raised the same day, [is-root-mounted-answers-from-the-first-tenant-the-key-finds](is-root-mounted-answers-from-the-first-tenant-the-key-finds.md) and [the-canonical-key-query-counts-the-terminal-tenant](the-canonical-key-query-counts-the-terminal-tenant.md), which it absorbs; read in code and not reproduced, a source reading against `main` at `ef33cb0f3`.

## Owner ruling

Accepted on 2026-09-26 as the lead recommended: a lookup that asks about a workspace finds only runtimes holding one, on the `found_by` lookups and both collision checks, pinned with the terminal tenant up on both hosts; a registered home workspace mounts and resolves like any other. It is built with [is-root-mounted-answers-from-the-first-tenant-the-key-finds](is-root-mounted-answers-from-the-first-tenant-the-key-finds.md) and [the-canonical-key-query-counts-the-terminal-tenant](the-canonical-key-query-counts-the-terminal-tenant.md), which are instances of the same lookup and land with it.

## What was seen

The shared terminal-only tenant stores the home directory as both of its keys, and every by-key lookup in `WorkspaceHost` that goes through `found_by` counts it: `hosted_for_key`, and so `open_or_get_registered_workspace`, hands it back as the existing mount of a workspace registered at the home directory, and `open_workspace`'s pre-check and insertion check refuse that workspace with "workspace already mounted". Both hosts mount the terminal tenant before they restore workspaces, so a home-directory workspace cannot mount while chan runs. On the desktop, turning such a workspace on hands back the terminal tenant's launch URL and its windows resolve to that tenant. On the devserver, the mount attempt succeeds with the terminal tenant's token and prefix, and the next save finds no tenant at the record's prefix and turns the row off. The two narrower holes raised before (the by-root query reading the first matching runtime; the canonical-key query counting the tenant in the window feed, the devserver list and the health probe) are instances of the same lookup. `is_workspace_mounted_by_key`, added with the fix for [a-hung-root-stalls-desktop-close-and-quit](a-hung-root-stalls-desktop-close-and-quit.md), is the one lookup that counts only runtimes holding a workspace.

## Desired contract

A lookup that asks about a workspace finds only runtimes holding a workspace; the terminal-only tenant is never the answer for a registered root, and a workspace registered at the home directory mounts and resolves like any other.

## What to do

Give the `found_by` lookups and both collision checks the workspace-only filter `is_workspace_mounted_by_key` has (or key the terminal tenant so no registered root can match it), then pin, with the terminal tenant up: a registered home workspace mounts on both hosts, its windows resolve to it, the window feed, the devserver list and the health probe read it, and the by-root query answers true. It closes the two absorbed items.

## Boundaries

`crates/chan-library/src/host.rs` (`found_by`, `hosted_for_key`, the collision checks, the by-root and canonical-key queries) and its tests; the devserver list in `crates/chan-server/src/devserver.rs`.

## What shipped

Landed on 2026-09-27, with [is-root-mounted-answers-from-the-first-tenant-the-key-finds](is-root-mounted-answers-from-the-first-tenant-the-key-finds.md) and [the-canonical-key-query-counts-the-terminal-tenant](the-canonical-key-query-counts-the-terminal-tenant.md), which it closes. The change is in `crates/chan-library/src/host.rs` and `crates/chan-library/design.md`; the devserver and the desktop gained tests only, and no route handler changed.

- **The marker.** A runtime records at construction whether it holds a workspace (`HostedWorkspaceRuntime::holds_workspace`): true for the runtime `open_workspace` builds, false for every terminal-only tenant `open_terminal_tenant` builds, the shared one and each command tenant alike. It is a field and not a read of the workspace cell, because the cell can be empty during a storage reset.
- **Every lookup by root or by key.** `found_by` answers only for a runtime that holds a workspace, and every lookup by root or by key goes through it: `hosted_for_key` and so `open_or_get_registered_workspace` and `is_canonical_root_mounted`, `live_workspace` and `is_root_mounted`, `mounted_canonical_root` and `mounted_root`, and through those a row's status, the starting mark, the health fold, the window feed's filter (`window_in_live_feed`) and a workspace window's tenant and leader (`workspace_window_live`, `tenant_leader`). `is_workspace_mounted_by_key`, which the desktop's on-set snapshot asks, keeps its body, which also reads the cell, so a runtime whose cell a storage reset left empty still reads as not mounted there.
- **The collision checks.** Both of `open_workspace`'s checks, the one before the tenant is built and the one at insertion, refuse a root only when a runtime that holds a workspace goes by it. Both prefix checks still refuse a taken prefix whatever holds it, and a terminal tenant's publication checks only its prefix, as before.
- **Close and removal by root.** The close and the removal by root (`close_workspace_for_root_locked`, behind `close_workspace_for_root` and `remove_workspace_for_root`) and `mounted_prefix_for_root` find only runtimes that hold a workspace, so an off or a forget of a workspace registered at the home directory no longer closes the shared terminal tenant, nor is refused for its live terminals.
- **A close of a runtime that holds no workspace writes no lifecycle row.** `close_workspace_impl` marks closing, arms its cancel guard and clears the lifecycle row only for a runtime that holds one. The terminal tenant goes by the home directory's key, which a mounted home workspace now goes by too, so a close of the terminal tenant by its prefix would otherwise have shown the home workspace closing and then removed its degraded row. No production caller closes a terminal tenant that way; the guard is pinned with the home workspace mounted and unavailable beside it, for a close that completes and one that is cancelled.

What a workspace registered at the home directory now does, with the shared terminal tenant mounted first, as both hosts mount it: it mounts under its own prefix beside the terminal tenant, and a second registration hands back that mount; its windows resolve to its own tenant, token and leader; every by-root and by-key query finds it beside the shared tenant and two command tenants; while it is not mounted it reads stopped, can be marked starting, its windows stay out of the live feed and are kept, and a failed health check publishes nothing for it; and its off or forget reaches no terminal tenant. Pinned in the library's tests (`home_workspace` in `host.rs`), with a test that a workspace still cannot mount at the terminal tenant's prefix. On the devserver (`home_workspace` in `crates/chan-server/src/devserver.rs`) and the desktop (`home_workspace` in `desktop/src-tauri/src/embedded.rs`), with the terminal tenant up and the home registered and not mounted: the home's row reads stopped and off with no token, a close and a forget of it by root leave the terminal tenant mounted and a terminal window minted before them resolving with its token, and on the desktop a home row the overlay holds on is written off by the on-set snapshot (`snapshot_workspaces`).

Not pinned, or not run:

- The mount of a home workspace is pinned in the library only, with a stand-in builder that indexes and watches nothing. The devserver's and the desktop's tests pin what answers for a home that is registered and not mounted, because their real builders would index and watch the home directory. An off or a forget of a mounted home workspace, which closes that workspace's own tenant, is read in code and not pinned on any host.
- The pin of the check before the build, `the_precheck_accepts_home_beside_a_terminal`, catches a regression of that check only where the home directory's path is already canonical: the terminal tenant stores the home directory as `dirs::home_dir()` spells it, and that check compares that spelling.
- Each filter site, and the close's lifecycle guard, was broken in turn and shown to red its own pins. Which other pins each break also reds was not measured, so the pins are not shown to be isolated.
- Windows and macOS have not run these tests yet. The Windows arm runs the library's and the desktop's tests and macOS runs all three; their first run is CI after this change.
