## What shipped

Landed on 2026-09-26, from the multi-selection ruling (the ledger's FB-06 and FB-03). Delete on the Files tree acts on the whole selection behind one confirm that names the count, and says "permanently" in a window with no workspace; it sends one delete per path, reports a partial delete as "deleted N of M" with the first refused path and its error while the refused rows stay selected, clears the selection after a full delete, and closes the tabs under a deleted path. In a workspace a path under a selected directory folds into it; a window with no workspace deletes every selected path deepest first, since its route deletes only a file or an empty directory. A tree refresh that fails after the delete is reported beside the count. The expand chevron no longer arms the rubber band that cleared a multi-selection. Download and Rename keep the cursor row, as the ruling says.

Two of the editor's defects landed on 2026-09-27. In `web/packages/workspace-app`:

- **A `.json5` file opens as source text.** The strict JSON test (`isJson` in `src/state/fileTypes.ts`) no longer claims `.json5`, so such a file no longer opens in the JSON tree, which could not parse it, and the strict JSON save check, which refused its comments and unquoted keys, no longer runs on it: it saves through the plain write with its text as it is. `.json5` stays editable text.
- **A pasted inline image is named from its mime type** (`dataUriImageMetadata` in `src/editor/paste_html.ts`, used by both naming sites and the decoder). The extension is the mime's subtype, `svg` for `image/svg+xml` and `jpg` for `image/jpeg`, whose subtypes are not the extension, and `png` when the mime has none. It was the subtype of whatever preceded the data URI's first semicolon, so an SVG with no parameters was named with part of its payload, a base64 SVG `svg+xml`, and a JPEG `jpeg`.

Pinned by a state-level test that a `.json5` buffer with a comment and an unquoted key saves through the plain write with its bytes unchanged (`src/state/tabs.test.ts`), and by four rich-paste cases, a parameterless SVG, an SVG whose payload holds a semicolon, a base64 SVG and a JPEG, that dispatch a paste into a real CodeMirror view and read the name and type of the file handed to a mocked upload (`src/editor/paste_chan_html.test.ts`). No browser was driven: that a `.json5` tab opens in source mode is read in code (`defaultModeForPath` in `src/state/tabs.svelte.ts`), the upload is mocked, and neither the server's storage of the attachment nor the browser's rendering of it was exercised.

Four more of the editor's defects were fixed later on 2026-09-27, in `web/packages/workspace-app` (lines at `7504a5f9c`):

- **A failed or oversized image upload is named, and the batch goes on.** An image over 50 MiB was skipped with no message, and a failed upload was logged to the console only and abandoned every image after it. Each now puts "Image NAME exceeds the 50 MiB upload limit; skipped" or "Image upload failed for NAME; skipped" on the status line (`notify`, `src/state/notify.svelte.ts:1-7`) and the batch continues with the next image; only the upload itself sits inside the catch, so a failure to insert is not reported as a failed upload (`uploadAndInsertAll` in `src/editor/bubbles/image_drop.ts:246-307`, the notices at `:265` and `:287`).
- **The images of a multi-image drop land where they were dropped.** The batch moved its insert position only by its own inserts, so an edit typed or received while an upload was pending put the images still uploading at stale offsets. Each batch's position is now mapped through every change to the document, its own inserts included, by a view plugin kept outside the editor's writable compartment, so a read-only toggle during the upload does not drop it (`uploadPositions`, `image_drop.ts:235-244`, installed at `:254-259`).
- **A file picked into an existing link keeps a working destination.** Picking `My Photo.md` into a `[label](...)` slot wrote the path with its raw space, which a Markdown parser does not read as a link; only the inline-code slot encoded it. Both slots now percent-encode the path by segment (`fileLinkInsert` in `src/editor/bubbles/wiki.ts:701-712`, `encodeRelPath` in `src/editor/links.ts:55-60`).
- **The outline jumps to the heading picked in the rich editor.** The rich editor counted headings in its syntax tree while the outline counts them by its own rule, so where the two disagreed, as on a heading indented by spaces, which the outline leaves out, the jump landed on another heading. Both editors now jump to the outline's source line (`jumpTo` in `src/components/FileEditorTab.svelte:423-426`; `scrollToLine` in `src/editor/Wysiwyg.svelte:875-886`).

Pinned in `src/editor/bubbles/image_drop.test.ts` (both notices with the batch continuing, and an edit between two uploads), `src/editor/Wysiwyg.imageDrop.test.ts` (a pending upload across read-only toggles in a mounted editor), `src/editor/bubbles/wiki.test.ts` (a name with a space in either slot) and `src/components/FileEditorTab.test.ts` (an indented heading skipped by the outline, in both modes). No browser was driven. The notices are read at the notification bus and the upload is mocked; whether an insertion error is kept out of the upload's catch is read in code; the position tests apply real CodeMirror changes, and the lane's report ran each 200 times as it is and 200 on one CPU, but they run no collaboration connection, and an editor torn down during an upload is not covered; the link tests read the produced source, not the backend's graph edge or the browser's navigation; the outline tests read the selected offset, while the scroll is read in code, and the outline's own rule for what it lists as a heading is unchanged.

Nine defects of the app shell, the panes and the file tree were fixed the same day, in `web/packages/workspace-app`, under `src/components` where no other path is named:

- **Enter answers the focused button of a confirm dialog.** Enter anywhere in the dialog confirmed it, so Tab to Cancel and then Enter confirmed. Enter on a button now clicks that button, and Enter elsewhere in the dialog still confirms (`onKey` in `ConfirmModal.svelte:25-31`).
- **A tab dragged over another pane's body offers its edge split.** The body's drag-over handler read the drag's payload, which browsers do not expose during a drag, so the edge split never fired. The panes of a window now share the drag's source, recorded when the drag starts and cleared when it ends (`localTabDrag`, `Pane.svelte:4`, set at `:824` and cleared at `:919`), and the body accepts a drag by that record and the drag's type and scope (`onBodyDragOver`, `:1118-1133`).
- **A tab dropped in its own strip lands where the indicator shows.** The indicator sat on the hovered tab's slot while the drop moved the tab to that index after taking it out of the strip, so it landed on the other side of the indicator. The indicator now allows for the removal (`:1201-1208`; the reorder at `:1232-1236`).
- **Spiral Spokes keeps drawing.** Its step kept growing until the opacity reached zero, after about seven minutes, and the pane stayed blank from then on. The step now wraps to the start when the opacity reaches zero (`wrapSpiralSpokesStep` and `SPIRAL_SPOKES_STEP_PERIOD`, `spiralSpokes.ts:9-13`, applied at `SpiralSpokes.svelte:73`).
- **Concentric Pulse's drawing is bounded.** Its ring radius grew with the pane's aspect ratio, to six-figure vertex counts per frame on a wide, short pane by the frontend review's measure. The radius is now capped at twice `CONCENTRIC_PULSE_MAX_RADIUS`, 1140 units (`ConcentricPulse.svelte:47-50`, `concentricPulse.ts:6`), and the square pane is drawn as before.
- **The inspector's report and backlinks no longer refetch on a directory relist.** Both effects read the tree's entry object, which a relist of its directory replaces, so a change anywhere in that directory refetched the report and re-streamed the backlinks. They now read the entry's path and kind, and the report, for a file, also its modification time (`FileInfoBody.svelte:175-177`, read by the effects at `:389`, `:395` and `:717-732`).
- **Copy Path reports a clipboard that did not take the path.** It said "Copied path" when the clipboard API was absent, having copied nothing. It now goes through the shared clipboard helper, which reports an absent or refused clipboard as a failure and writes through the desktop's native clipboard (`copyPath` in `FileTree.svelte:765-772`, `copyTextToClipboard` in `src/state/store.svelte.ts:663-682`).
- **The tree dims a file by the server's kind.** A row was drawn as view-only by its suffix, so a text file with an unusual suffix that opens editable looked read-only. A row now keeps the kind the listing gave it and asks by that kind, and falls back to the suffix only while the kind is pending (`FileTree.svelte:483`, `:1480-1482`).
- **A tree closed during a rubber-band drag lets go of the window.** The band's two window listeners were removed only on mouse up, so a tree unmounted mid-drag left them, and a later mouse up could clear the selection. Teardown now removes them too (`detachBandListeners`, `FileTree.svelte:1294-1299`).

Each is pinned by a mounted or state-level test that the lane's report shows failing before its fix (`dev/v0101-team/reports/report-Clients-17.md` in the development tree; `ConfirmModal.test.ts`, `Pane.test.ts`, `spiralSpokes.test.ts`, `concentricPulse.test.ts`, `FileInfoBody.svelte.test.ts`, `FileTree.selectionMenu.test.ts`, `FileTree.mediaOpen.test.ts`, `FileTree.selection.test.ts`). No browser was driven and no pixel was read, so what each fix looks like is read in code, not seen:

- No browser gesture was driven for either tab drag. A drag whose end never fires leaves its record until the next drag starts; the drop still checks its own payload (`onBodyDrop`, `Pane.svelte:1142-1150`).
- On a pane wider than about 2.4 to 1 the pulse's rings stop short of the ends: the uncapped radius passes the cap there. Nobody has looked at it on a display.
- The spiral's test reads the draw calls and the step, not pixels or a frame rate; the tree's dimming is read from classes and titles.
- The inspector's test measures requests: whether a flicker was visible, and whether the tab's own autosave was one of the triggers, is not established.
