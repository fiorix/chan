## What is there now

Read at `342dbe791`; the GTK arm of the raise is unchanged since the readings (`git diff a4ac4a7b9 342dbe791 -- desktop/src-tauri/src/raise.rs` changes comments only).

- A second launch that finds the desktop running sends `Request::Activate` (`crates/chan-server/src/handoff.rs:238`, built by `activate_request`, 1997-2002), which carries a protocol number and a version and nothing of how the launch was started. Nothing in the desktop or the server reads `DESKTOP_STARTUP_ID` or `XDG_ACTIVATION_TOKEN`.
- The desktop answers with `come_forward` (`desktop/src-tauri/src/single_instance.rs:699-730`), which raises through `raise::raise_window` (`desktop/src-tauri/src/raise.rs:57-70`). On Linux tao 0.37.2's focus call presents the window with `GDK_CURRENT_TIME`, which GTK replaces with the time of the last input chan received; the module comment of `raise.rs` says so, and that a window manager that prevents focus stealing weighs that time against the user's last input elsewhere.
- Under metacity 3.58.1 in a guest, a second launch from a shell (no startup id) after the user clicked another window: with the chan window clicked before, restored 10 of 10 and focused 0 of 10, minimized or behind the other window, before and after v0.129.0's raise fix, the window left `_NET_WM_STATE_DEMANDS_ATTENTION`; with the chan window never clicked, focused 10 of 10 after the fix; under openbox, focused 10 of 10. GNOME's mutter on X11 is expected to behave as metacity; not read. Not read either: a second launch from the desktop's menu entry. `chan-desktop.desktop` names no `StartupNotify` and the `chan-term`, `chan-edit` and `chan-files` entries set it false (`packaging/distros/shared/`), so a launcher may give such a launch no id either.

## Desired contract

1. A second launch passes on the activation it was started with, `DESKTOP_STARTUP_ID` or `XDG_ACTIVATION_TOKEN`, in its request, and the desktop presents the raised window with it, so a window manager that prevents focus stealing gives that window the focus.
2. A launch that carries neither, from a terminal or from a menu entry that asks for no startup notification, gets the focus as well: it sends the time it was started at in the form a startup id carries one, which is later than the input that started it.
3. A desktop never presents with a time of its own making, so a raise nobody asked for gets no focus it would not get today; a desktop that predates the field still reads the request.

## Boundaries

- The `Activate` request gains one optional field (the enum has no `deny_unknown_fields`, so an older desktop parses it); the second launch's side in `single_instance.rs` reads its environment, and on X11 the X server's time when it has no id; `come_forward` and the GTK arm of `raise.rs` apply the id to the window before presenting it. The review's shape: an X11 id of the `_TIME<timestamp>` form for a launch with none.
- Rejected when v0.129.0's raise was built, and not here: presenting with the X server's current time from the running desktop, which defeats the window manager's rule.
- Not here: macOS and Windows, which the shipped raise row covers; a launch given paths (`OpenPath`) and `chan-term`'s `OpenTerminal`, which by reading meet the same rule and can take the same field once it exists; Wayland, where the token is the only route and nothing has been read.

## Rulings for v0.131.0, 2026-11-14

The owner answered the decisions document for v0.131.0 (`dev/v0131/decisions.md`, point 13.2) on 2026-11-14: "as you recommend".

- The field is one optional string on `Activate`, carrying the launcher's id verbatim or the `_TIME<timestamp>` form for a launch with none.
- `OpenTerminal` takes the same field in this row, since a warm `chan-term` started by a hotkey meets the same refusal and its desktop entry sets `StartupNotify` false. `OpenPath` waits.

- The field is a wire shape: two reviewers read the range.

## Implementation, 2026-11-14

The first implementation stage carries optional `startup_id` strings on `Activate` and `OpenTerminal`, with omission preserving the prior wire shape and older readers ignoring the field. The launching desktop and shell-only `chan-term` capture one value before their retries: `DESKTOP_STARTUP_ID`, then `XDG_ACTIVATION_TOKEN`, otherwise the X server timestamp on an X11 session. The pure Rust X11 connection reuses the already locked x11rb dependency. Its socket operations share a 500 ms deadline; local Unix and numeric or localhost TCP displays are supported, while DNS display names return no timestamp. Local Xauthority file reads are outside that socket deadline.

The GTK receiver applies a supplied id on the main thread only for X11. It restores and presents directly using the id's timestamp, with the same numeric parsing rules GTK uses, so a delayed request does not acquire a newer display-wide input timestamp. A timestamp-free id uses GTK's existing input time. The id follows a requested terminal through its native build, including an `Activate` that must mint a terminal. Raises without an id, other platforms and `OpenPath` keep their prior behavior.

The baseline enum dropped both fields in the red tests (`dev/v0131-team/evidence/Desk131/raisefocus/protocol/red-startup-id.log`). Capture selection began with a no-behavior stub and four assertion failures; its implementation has nine passing focused tests (`capture/capture-tests-final.log` under that evidence root). Desktop source checks failed before forwarding/application existed. Timestamp tests exposed the absent parser and then GTK's hexadecimal grammar; an independent comparison of 385 inputs against the installed GLib conversion found no mismatch after the ASCII-whitespace correction. The combined server test run passed twelve checks but could not bind the transport-test socket in the host sandbox (`Operation not permitted`); that transport test requires the isolated guest run.

This is not the row's closing acceptance. The committed scoped gate, the base/tip openbox and metacity readings (including launcher-supplied ids and warm terminal windows), and the mutation stage remain pending. Stage 2's draft is `dev/v0131-team/evidence/Desk131/raisefocus/request-draft.md`; its native driver has not run. The lock gains two dependency edges without new package versions; the merged lock needs the Nix hash harvest and re-pin before a milestone push.

## Built, 2026-11-14

The launch activation now reaches both `Activate` and a warm `OpenTerminal` through the optional `startup_id` field. The launcher supplies its existing id or reads the X server time before the handoff; the X11 desktop applies that supplied timestamp before presenting the requested native window. The ordinary raise does not obtain a new timestamp from the desktop. Protocol and subsystem documentation are included with the implementation at `df2578662`.
