- Reaching a devserver through the gateway rather than over loopback breaks three input surfaces that work locally, reported from live use on 2026-08-04 and not yet reproduced under a controlled run. Paste does not work in either the terminal or the editor. The Rich Prompt opens but renders no editable area, so there is nowhere to type; the bubble's chrome appears while its composer does not. The launcher cannot open the Computers section at all, failing with a permission error on chan-desktop's access to chan-library. The three may share one cause or three: paste and a missing editor surface both smell like a browser capability that a cross-origin, non-loopback context withholds where the local hop does not, while the Computers failure is an authorization result from a different layer and may be unrelated. Grounding needs the actual console and server-side errors from a gateway-served session, per surface, before any of it is specified; the tunnel path is described in `crates/chan-tunnel-proto/design.md` and the gateway workspace in `.agents/gateway.md`.
