- `tenant::tests::one_deadline_aborts_and_joins_every_stuck_task` (`crates/chan-library/src/tenant.rs:387`) asserts a wall-clock bound, `elapsed < grace * 3` at `:412` against a 100 ms grace at `:405`, so it measures the host scheduler as much as the code under test: on a machine at load 20 across 8 cores it measured 390 ms and failed, while passing 12 of 12 runs in isolation on the same commit. The bound cannot simply be widened, because the behaviour it discriminates is one grace period against grace multiplied by the four stuck handles, which lands near 400 ms; a bound above that stops detecting the regression it exists for. Move it to `#[tokio::test(start_paused = true)]` so tokio's virtual clock advances deterministically, the pattern already used at `crates/chan-server/src/devserver.rs:2801` and `crates/chan-server/src/control_socket.rs:4226`, `:7095`, `:7579`.
