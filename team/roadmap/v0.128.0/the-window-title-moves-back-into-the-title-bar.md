# The window title moves back into the title bar in title-bar-tabs mode and reads like a devserver's

Status: raised by the owner on 2026-11-11 and built outside the team by the owner's Mac agent from the lead's order (`dev/owner-order-title-bar-window-title.md`, base 1c822268d), handed to the team as an intake the same day; accepted for v0.128.0 by the owner's own hand.

## What is there now

With tabs in the title bar (Settings, Global, Title bar tabs; macOS and Windows), v0.127.0 put the window's title into the pane tree widget's heading, because the title bar hides its own title in that mode (`team/roadmap/done/a-tmux-windows-title-bar-is-empty-when-tabs-sit-in-it.md`). A local window was titled `<house glyph> <absolute path of the workspace> Terminal 1`, where a devserver window reads `<arrow icon> {host} / {workspace} Window 1 [label]`.

## Desired contract (the owner's words, with his decisions at the build)

1. A workspace window with no tabs open, local or remote, shows its title in the bar next to the pane tree button, in the drag area, display only.
2. When the first tab opens the title slides to the right end of the bar, left of the side toggle, and the strip takes the space to its left; closing the last tab brings it back. The slide is animated, cut under reduced motion and at boot restore.
3. The title keeps a reserve on the right (250 px, or 40 percent of a narrow bar) as a floor, not a cap: the title shows whole and gives way to the tabs first, then the strip overflows with its fade; at rest a long title ends in an ellipsis and rolls on hover.
4. A local window reads `<arrow-down glyph, U+2193 U+FE0E> local / {workspace} Window N [label]` (`{workspace}` is the folder's name, as Computers names it, never the absolute path), a local terminal window `<glyph> local Terminal Window N [label]`; the devserver form is unchanged. The library's own title is the machine-neutral tail (`chan Window 1`, `Terminal Window 2`), built by `chan_library::windows::window_title`, and the desktop's OS title is that tail with the machine in front, so the OS title ends with what `cs window list` prints; `cs window list` appends ` [label]` at print time, `--json` unchanged; stored rows are recomposed on load, control and tmux-marked rows keep their titles.
5. The pane tree heading, which existed only in this mode, is removed outright; a tmux window's bar shows the window title between the pane name and the tmux badge.
6. Computers keeps "This machine" on the card; the All windows rows read `local / chan` and `local`.

## Boundaries

- Changed: the desktop's OS window title and what reads it (the Window menu, `GET /api/windows`, the `titlebar-window-title` event), the launcher's All windows row detail, `WindowRecord.title` and the `cs window list` table. Left alone: the web-shared window label, the browser document title, the command launcher breadcrumbs, control terminal titles.
- Known limits, by the owner: two workspaces with one folder name list alike in `cs window list` but for the window id (`--json` carries the path); a devserver on an older release lists old-form titles in the local table; a Windows devserver seen from a Unix desktop shows the full root in the OS title; control rows read `Control Terminal - NAME` in the OS and `Control Terminal` in the library. No migration of stored rows.
- Follow-up for the team: the desktop's window-number counter and the title-override field feed no title now and can go.

## Acceptance

1. On the owner's Mac: the title next to the pane tree button with no tabs, the slide on the first tab, the fade and the roll with a long title, the new local text, privacy mode, light and dark, the tmux bar; validated by the owner locally and against a lima aarch64 devserver.
2. Unit tests of the title composition, the bar's two states and the reserve, the pane tree without the heading; `make web-check` green; the desktop and library crates' fmt, clippy and tests.
3. The design documents and the manual's title bar tabs page say the new arrangement.
4. The Linux GTK reading in the lead's desktop guest (the lead's intake duty, since the owner reads macOS alone).
