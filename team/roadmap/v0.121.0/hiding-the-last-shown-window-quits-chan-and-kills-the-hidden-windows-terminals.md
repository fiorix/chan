# Hiding the last shown window quits chan and kills the hidden windows' terminals

Status: raised by the owner on 2026-11-01 after it ended a screencast dry take ("if we're hiding the last local window and there are terminals open, we cannot close chan - we must refuse until there's at least one window open"); filed as [fiorix/chan#8](https://github.com/fiorix/chan/issues/8); drafted for v0.121.0, with contract 2 decided by the owner on 2026-11-02 (the section Decisions); not started.

## What is there now

On chan-desktop 0.120.1 for macOS, a workspace window whose terminal ran an agent session was hidden with `cs window hide`, a throwaway standalone window was hidden the same way, and one standalone terminal window was left shown. `cs window rm <shown window> --force` destroyed the last native window and the desktop exited at once, with no prompt: every hidden window's shells were killed, the agent session among them, and the next `cs` call answered `the server closed the control socket before answering`.

Hiding takes the same path. `bury_window_now` (`desktop/src-tauri/src/serve.rs`) buries a `local::` record through the watcher view, whose reconcile closes the native window, so a hidden local window has no webview. When the last native window is destroyed Tauri requests an exit, and the `RunEvent::ExitRequested` arm in `desktop/src-tauri/src/main.rs` counts the workspace webviews that remain; with none it runs `begin_normal_shutdown` and skips the quit confirmation that a menu Quit goes through. `desktop/design.md`, Quitting, documents it: closing the last native window exits chan on every platform and the exit handler runs the clean shutdown without a prompt; buried windows keep their hidden records and restore hidden at the next boot, but their terminals do not survive the process. Nothing checks for live terminals before the last window goes.

## Desired contract

1. Hiding the last shown local window is refused while any terminal session of the library is alive. `cs window hide` exits non-zero with a sentence that says why and what to do (show or open another window first); the close-confirm overlay's Hide and the launcher's Hide action and `h` key refuse it the same way, with the reason shown where the gesture was made. With no live terminal the hide behaves as today.
2. The same holds for `cs window rm` and the overlay's Close on the last shown window while hidden windows hold live terminals: refused with the reason, as the hide is, and not routed through the quit confirmation. `cs window rm --force` overrides the window's own live shells, as today, but not this refusal.
3. `desktop/design.md`, Quitting, states the guard next to the last-window exit it qualifies.
4. Tests pin the rule where it is decided (shown local windows counted against live sessions) and the `cs window hide` refusal; the last-window exit with no live terminal keeps its current test.

## Decisions

The owner's word of 2026-11-02 on contract 2, between refusing and asking through the quit confirmation, on the lead's recommendation to refuse: "refuse". That `--force` does not override the refusal follows the owner's words in the status line ("we must refuse until there's at least one window open").

The owner's word of 2026-11-02 on the close of a window whose last tab closed, which the review left to the owner beside the close-window command it asked to guard: "i think f2 as recorded is fine.. if the user gets the dialog and still choses to close, they should know the app will close". That close stays outside the guard, as the Closing records.

## Closing

The rule is decided once, in `desktop/src-tauri/src/last_window.rs`: `refusal` answers a gesture from the shown windows other than its own, the library's live terminal sessions and the gesture's own window's sessions, and `check` reads those from the running desktop. A shown window is a native `local::`, `lib-` or `control-terminal-` window that is neither buried nor flagged for a hide under way; the About window does not count, since closing it as the last window ends chan with no guard. A hide of the last shown window is refused while any session lives, its own included; a close is refused while sessions other than its own live; a control terminal hides in place, so its hide is never refused. With no live terminal nothing is refused.

The library-wide count needs no new host query: `EmbeddedServer::live_terminal_sessions` sums `tenant_terminal_session_count` over the host's mounted prefixes, the per-tenant count the reversible workspace off path already reads, so the workspaces, the shared terminal tenant and every control terminal's tenant are counted. A window's own sessions are the `cs window rm` guard's `live_terminal_count` for a `local::` window and its tenant's count for a control terminal; a devserver window's sessions live on its devserver and outlast the process. Nothing in chan-library changed.

Every named gesture asks the rule. `cs window hide` and the launcher's Hide and `h` key reach `window_ops::hide_window`, which refuses before it flags or closes anything; the bridge's 409 body already reaches the launcher's corner notice through `reportError`, so the launcher needed no code change. `cs window rm` and the launcher's Close reach `window_ops::close_window`, which asks before it discards or destroys. The control socket's `cs window rm` now asks the desktop before the host discards, as the launcher's close route already did, so a refusal leaves the row and its shells alone, and `--force` passes the window's own live-shell guard but not this refusal; a row the desktop discarded itself still reads as removed. A desktop error other than `NO_DESKTOP` now fails the removal instead of being swallowed. The close prompt's Hide gets the refusal from `hide_window_from_close_confirm`, and its Close asks the new `close_window_refusal` command before `discardWindowSession`, which would reap the window's terminals; a refused choice keeps the prompt up with the sentence in a `role="alert"` line, and a hide refused from the chord or the command deck shows it in the status bar. The close-window command (`app.window.close`: Cmd+Shift+W on macOS, Ctrl+Alt+W elsewhere, the host's close command and the close button of a devserver window that is not connected) and the command deck's Close window ask the same way: `flushAndCloseWindow` takes the caller's discard and runs it only once the desktop has not refused, and a refusal discards and closes nothing and goes to the status bar. `desktop/design.md`, Quitting, states the guard next to the last-window exit, and the `cs window` help states both refusals.

Verified by tests, red first against the base code (assertion failures read, not exit codes): the rule's three pure cases and its reading of the mock desktop with real PTYs spawned through a tenant's `POST /api/terminals` (`cargo test -p chan-desktop --bin chan-desktop last_window`, 9 tests: 4 red on a never-refusing stub, and the pending-hide test red before shown windows left out a flagged hide); `hide_window`, `close_refusal` and the close prompt's Hide on the mock runtime, and a pin that `close_window` asks before it discards or destroys (`window_ops`, `tests::the_close_prompts_hide...`); the control socket's order and pass-through (`window_rm_stops_on_the_desktops_last_window_refusal_with_or_without_force`, `window_rm_beside_a_desktop_removes_the_row_it_listed`, `window_hide_answers_the_desktops_refusal`; both rm tests red on the old order, where the host had discarded before the desktop was asked); the overlay and state module (`CloseConfirmOverlay.actions.test.ts`, `closeConfirm.test.ts`, 5 red); the launcher's Hide button and `h` key (`WindowRow.test.ts`, `Library.deck.test.ts`, red with the row's error report muted); the close-window command, the command deck's row and a chord assigned to it, each refused and each answered `null` (`App.windowClose.test.ts`, red on the old discard-first close: the desktop was never asked), and `flushAndCloseWindow` with a discard (`closeConfirm.test.ts`). Six more mutations of the asking close (the discard before the ask, a refusal not returned, no status line, the close-window command and the deck row back on the old two calls, a prompt cancelled meanwhile not honored) each failed a named assertion. Eight mutations of the guards (buried windows counted, control terminal hide refused, own sessions zeroed for local and control windows, other shown windows ignored, and the guard removed from each of `hide_window`, the prompt's Hide and `close_window`) were each killed. The existing `the_last_window_closing_exits_the_desktop` test is unchanged and passes: the exit handler was not touched.

Open: chan-desktop was not run on this host, so no gesture was exercised on a real window; the macOS hand check follows the merge. The page's own close of a window whose last tab closed (`closeEmptiedWindow`), the red dot on a window with no tab or while it reconnects, and the About window's close do not ask the rule and still end chan as the last window goes; whether the emptied window's close should ask, leaving an empty window shown, is the owner's call. A devserver-served page from an older chan does not ask before its Close, though its Hide is still refused by this desktop; a page on an older desktop finds no `close_window_refusal` and closes as before. A close racing a hide of the other last window is not serialized.
