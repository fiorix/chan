# Release v0.117.0

Shipped 2026-10-31 from `0.117.0-ga`: the release commit `cbb33d000` (the pins, lockfiles, hashes, specs and documents) and two commits over it, the second the tagged tip, which gate the tmux foreground fallback to unix and name libelf in the static FreeBSD link after the candidate's CI run and Release dry run went red on Windows and FreeBSD (see Validation). The release commit sits over two merges into `main` at `a7a46b0fe` (the tip of `main` since the v0.116.0 publication record): `84784bf17`, the `--no-ff` merge of `v0117/tmux-card` at `0e45cb690`, forty-four commits over `main` that carry `v0117/terminal-opacity` at `01fc52921`; and `c698c130b`, the `--no-ff` merge of `v0117/file-browser-ui` at `520ee28b5`, one commit over the opacity tip; then `703c0609f`, a one-line fix to browser check 195 found at intake. The version ships six of its nine rows with no release candidate, by the owner's words of 2026-10-31: "from here there will be no rc, it's ga and tag.. you can go all the way so long the gates are green" and, when the file browser branch was committed, "i want to include v0117/file-browser-ui in this release as well"; the three unbuilt rows were put to the owner in one survey and carried by the answer "Carry all three to v0.118.0 unbuilt (Recommended)".

Three streams met in the cut. The terminal opacity branch was built on the Linux host on 2026-10-30 by one lead with two building agents and a read-only auditor: the opacity on every window's terminal tabs, ghostty as the default backend, the ghostty paste and Ctrl+V fix and the select popups' colour scheme, plus the report and trace of the ghostty idle-keys row. The tmux control-mode client was built in stages: the protocol crate through the docs pass (stages 2 to 7) on Linux as `v0116/tmux-protocol`, then rebased onto the opacity tip and finished on the owner's Mac as `v0117/tmux-card` (stage 8, tmux's panes without tabs, and stage 9, the connection as a card in Computers), with the hand tests on macOS and over ssh on 2026-10-30. The Files tab's directory navigation and keyboard model was built by the owner's agent on the Linux host and committed on 2026-10-31 without a roadmap item; its item was written at the cut.

## What shipped

- `opaall`, Terminal opacity applies only to standalone terminal windows: chan-desktop builds every window transparent and marks its URL `transparent=1`; the page paints only terminal bodies at the live alpha and keeps every other surface of a workspace, devserver or control window opaque through the masked backdrop; the value is the desktop's own `server.toml` key, read and written through two Tauri commands and announced to every window, with the config watch's hook carrying a `chan config set` or a hand edit to every window as well; the Settings slider in a desktop window writes through the host, and in a browser tab says the setting applies in chan-desktop (`c239ef672`). Read by pixel in the Linux rig at 80 and 100 across a workspace window, a devserver window, a control terminal and a standalone terminal window.
- `ghdef`, ghostty is not the default terminal backend: `terminal.ghostty` defaults to true on every platform, the config reference, the Settings hint and the code comments say so, and a stored false keeps xterm.js (`c08b8b24e`). The whole browser suite on the host under the new default had the four reds it has at `main` and no other.
- `ghpaste`, ghostty drops an image paste and swallows Ctrl+V: `terminal/ghosttyPaste.ts` answers a native paste with no text as the empty bracketed paste when the program asked for bracketed paste, and sends 0x16 for a bare Ctrl+V on every OS; the tab's capture-phase paste listener and the custom key handler ghostty-web consults first do both, for the renderer host only (`c4fb67c31`). Browser check 94 gained a paste leg that is red against the previous component.
- `selscheme`, Select popups paint light in the dark theme off macOS: the workspace app and the launcher declare `color-scheme` on their theme roots, so the engine paints native select lists in the theme's scheme (`17bbe620f`).
- `tmuxcc`, tmux control mode has no chan client: `crates/chan-tmux` frames the control-mode stream with a decoder that pane content cannot cut short; the library's gate reads the marker a `tmux -CC` foreground prints, asks before honouring it for any program but a local tmux (`terminal.tmux.enabled`, `terminal.tmux.trust`), and runs the connection with a session per tmux pane and no PTY; each tmux window is a chan window of its own with tmux's layout as chromeless panes sized by tmux, a chan split asks tmux to split, focus follows, and Cmd+T and New Window each ask tmux for a window; the connection is a card in the launcher's Computers carousel, titled by its origin, with the windows as rows, `t`, `c` and the selection's end, and the control terminal as its hidden control row that becomes a plain terminal window when the connection ends. The hand tests passed on macOS and over ssh on 2026-10-30; FreeBSD is not hand-tested.
- `filesnav`, The File Browser shows a tree with no directory navigation or keyboard model: a Files tab shows one directory with breadcrumbs, history, a path field, a filter and folder-first sorting, a locations rail in wide panes and the tree kept in docked browsers; each surface owns its cursor, selection and range anchor; one composite-widget Tab stop with the desktop keys, independent marks and an optional Vim map kept per browser; a Files tab's directory, sort, selection and inspector settings are saved with the layout (`520ee28b5`). Read in Chromium by its builder; the browser suite's file-browser checks still drive the tree (see Validation).

## Retrospective

Highlights: the three streams merged as clean unions, the one conflict-prone pair of branches touching four files with no overlap. The intake run of a never-run check found its own defect in a minute and, once past it, a browser behaviour the card model had changed without anyone writing it down. Every unbuilt row left with the owner's words on it.

Lowlights: a branch shipped with no roadmap item until the cut for the second release in a row, and this one carried a known gap in the browser suite that its builder had written into the commit message and nobody had read before the merge was asked for. Twenty-three checks of the suite now fail before their subject, so the editor, graph, drafts and inspector checks prove nothing until they are migrated. The suite's gaps are test debt, not product defects, by the reading above; that reading rests on each red's first failing line.

Honest feedback: a feature branch that changes a surface the browser suite drives should run the suite before it is offered for a release, and a release that takes a branch on the day should budget for reading its known gaps.
