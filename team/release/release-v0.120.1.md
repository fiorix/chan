# Release v0.120.1

Shipped 2026-11-01 from `0.120.1-ga`: a no-rc patch over v0.120.0 for two defects the owner found on the day of that release and two the Windows reading found, built from `main` on the owner's macOS machine by one agent with two subagents and on the Linux host by the Windows reading agent, each on its own lane, and cut by the release lead on the Linux host from those lanes merged into `v01201/int`.

## What shipped

- `cardscroll`, the Computers card does not scroll with the mouse and cuts its last workspace: the deck's turn moves from the ring onto each slot, so the front card stands on the identity transform on a flat layer that WebKit scrolls under the wheel; the scroller's end padding and end scroll padding share one length, so the last row ends clear of the border by wheel and by keys; pinned by two launcher tests, the browser suite's new check 197 (twelve workspaces, wheel to the end, keys to the last row) and the agent's WKWebView and Chrome readings at the base and the tip (`e5a5a0231`).
- `tmuxfight`, a tmux pane drag starts a fight between chan and tmux: the window-size ask follows the pane tree's box alone (a resize observer in `App.svelte`, the area kept in `state/tmuxWindowSize.svelte.ts`), re-armed 150 ms after the last fold change while the box has moved, and held from a divider's press until the layout answering its release or a one-second bound; a fold change inside an unchanged box asks nothing. Pinned by five mounted cases and the store's unit tests, a mutation per guard, the agent's three-drag reading against a real tmux, the owner's hand reading on the merged desktop build, and the lead's own drag reading at the base and the tip (`f961b82dd`).
- `winkeys`, two Windows key sequences on the ghostty engine (a dead-key apostrophe lost before Enter or Tab on US-International, Alt+Numpad sending stray ESC sequences), from the Windows reading of ghostty findings 7 and 9 that v0.120.0 shipped without: two Windows-only arms in the ghostty key listener: a plain Enter while a dead key is pending keeps its default so the browser types the character first and the CR goes with Enter's own line-break input (or its keyup, focus loss or the next keydown), and Alt-held numpad digits are cancelled as an Alt code; pinned from the event shapes read on Windows 11 with Chrome and Edge 156 (8 of 75 tests red on the base, 17 mutations), read on the owner's Windows guest with a debug build on the host and the textarea in Chrome and on the host in Edge, Tab after a dead key still dropping the character (`609245a38`).

## Retrospective

Highlights: three defects found on the release day shipped the same day, two built on another machine by an agent the owner validated beside and one by the Windows reading agent from the readings v0.120.0 had shipped without, each with red-first tests, mutations and a real-surface reading the release lead could replay on the Linux host; the integration branch, its gates and the cut tooling were prepared while the lanes were still being built, so each lane waited only for its own review. Lowlights: the lead's first real-tmux reading failed before any reading because the second worktree lacked the browser suite's dependencies, a setup step the worktree recipe now names; the two macOS lanes and the lead's roadmap commit added the same row files, an add/add at every merge resolved by taking the lane's row. Honest feedback: the cut tooling still carries one hand step between the pin and the build (the pin patch and its digest), which belongs inside `pin-and-lock.sh`; and a patch whose lanes come from three agents on two machines needs the lane's base stated in its hand-back, since one lane stood on the GA commit and the others on the record commit.
