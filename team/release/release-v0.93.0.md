# Release v0.93.0

Status: GA 2026-08-18. No candidates. The round's scope was one migration, one renderer decision, and one investigation; what it also produced was a shipping blocker found inside the round's own change, a test-harness fault that would have read as a broken migration, and the first measured flake rates this project holds for its load-sensitive test population.

## What shipped

- **One filesystem namespace, reachable from every window.** File content and transfers move to `/api/fs`, rooted at the serving tenant's capability root: a workspace tenant resolves paths from its workspace, a standalone terminal tenant resolves them from `/`. `cs download` and `cs upload` now reach any path the shell's uid can access from a workspace window and a standalone terminal window alike, under the same readability preflight, atomic writes, admission bound and transfer ceiling in both. The URL means one thing and the tenant decides the root, which is why this could not be fixed by relaxing a check: `strip_leading_slash("/etc/hosts")` yields `etc/hosts`, a relative path a workspace tenant would resolve inside the workspace. `/api/files` remains a compatibility alias, documented in `design.md` and `.agents/gateway.md` as removed in v0.94.0. The migration touched 243 live references across 73 files, against an item that estimated roughly five.

- **A Linux desktop AppImage uses the WebGL terminal renderer where its driver supports it.** The AppImage bootstrap already decides whether to keep WebKit off its dma-buf renderer, which it does for the NVIDIA proprietary driver, and `shouldUseWebglRenderer` now follows that same decision instead of refusing WebGL on every Linux desktop. The decision travels on the window URL the desktop builds, not through the server's environment, because a remote devserver serves its own shell and cannot observe the desktop client's WebKit environment. Delivery is deliberately AppImage-only: `.deb`, `.rpm`, Nix and source builds do not run that bootstrap, emit no signal, and keep the DOM renderer on every driver.

- **The desktop liveness probe test has a mechanism and a structural repair.** Close-on-exec acts at exec, not at fork, so a concurrent `Command::spawn` anywhere in the test binary leaves the forked child transiently owning a listener the test has already dropped, and the connect the test expects to be refused succeeds honestly. The stale socket is now created in an exec'd helper, so the parent never owns the descriptor and no concurrent fork can inherit it.

## Team and process

A five-member team ran the round: a lead plus Transfer (the filesystem namespace), Renderer (the Linux WebGL decision), Probe (the liveness investigation), and Gate, which owned the build container, wrote no source, and owned every verdict. Lanes were file-disjoint and every build went through Gate, because two `make` runs against one target directory both crawl on a file lock and the second looks like a hang.

Two lane boundaries moved during the round on evidence rather than on plan. The `/api/files` blast radius reached `desktop/src-tauri/src/native_transfer.rs` and the separate `gateway/crates/devserver-proxy` workspace, both outside Transfer's declared lane and both behavioural dependencies of the rename, so both moved into it; the gateway workspace later produced a real red that the root formatter cannot see. And Probe's mandated instrument, `scripts/e2e/one-cpu-test-series.sh`, hard-coded `-p chan-workspace` while its target test lived in chan-server, so the instrument was parameterised by package.

Coordination was the round's largest tax. An idle codex TUI never goes output-quiet, so the poke queue's drain signal never fires and a message to a busy lane sits indefinitely once that lane goes idle. Five restarts were needed, each discarding a lane's context. The mitigation that worked was requiring every lane to journal richly enough to resume from a cold restart, which turned each restart from a loss into a pause.

## Validation

The full `make pre-push` gate ran on the committed tip in an isolated in-container clone, with both production bundles built first. The browser-smoke suite ran as a delta against a measured baseline at `1d2762e6`: 32 pass, 13 fail, 1 skip of 46. Four of the eleven checks the migration touches were red in that baseline and were individually re-run and classified before any of the round's work was judged against them.

Two genuine code reds surfaced across the round's integrated gates, both repaired: a rustfmt break in the separate gateway workspace, which the root `cargo fmt --check` passes over entirely, and a stale in-tree guard asserting four `DefaultBodyLimit::disable()` sites where the alias legitimately makes eight. Two web guards failed for the same reason, both stale source-pins.

One gate red was read as a harness fault and was not one. A clone without a built `web/dist` embeds nothing, so `serve_static` served no shell and the round's new renderer test failed its status assertion before reaching the assertion it exists for. The lead called that a harness problem and had Gate populate the bundle before gating, which made the local gate green by removing the condition a clean checkout runs under. The release dry run then failed on both the Linux and macOS arms with the same assertion, `left: 404, right: 200`, because `cargo test` is the eighth `pre-push` step and `make web-check` builds the bundle at the twelfth. The test carried an undeclared dependency on a build artifact the gate produces four steps later, and it was the only test in that module reaching `serve_static`. It now asserts the injection where the bundle exists and the absent-bundle status where it does not, so neither arm passes without asserting something, and both arms were run on this machine under both conditions before the fix was pushed. Gate had separately voided the entire `cargo test --all-targets` run that shared the unpopulated clone rather than only its failing step, while keeping the guard defect that run had surfaced, because that one was independently confirmed from committed source.

## Retrospective

**Highlights.** The round's best catch was made by a lane against its own change and against the lead's explicit clearance. Renderer had been told, with reasoning, that the NVIDIA path carried no new risk. It read the bootstrap instead of the doc comment and found that `linux::prefer_system_gui_stack` returns before `set_webkit_env_defaults` when the process is not an AppImage, so a two-state signal would have reported WebGL available on `.deb`, `.rpm`, Nix and source builds including NVIDIA, which is the blank-grid failure the item exists to prevent. The signal became tri-state, and the repair also strips a renderer value already present on a URL so an attachment cannot smuggle one into an undecided window.

Probe was asked for a mechanism and produced one outside the flaky test, with a standalone probe holding a child in `pre_exec` and `strace -ff` recording `connect(...)=0` while the child is held and `ECONNREFUSED` after `execve`. When the rig then failed to reproduce the target naturally, 15 runs of 1,145 tests with `nr_throttled_delta=5557` and the target passing 15 of 15, it reported the finding rather than claiming the four unrelated reds. The statistical acceptance was replaced with a deterministic one: 20 of 20 forced runs report live on the old construction, 20 of 20 refuse on the repaired one under the same held-child condition.

Instruments were proven before they were trusted. Probe demonstrated its parameterised rig going red on a deliberate failure before accepting any green from it. Gate captured every verdict in a status file rather than from a wrapper's exit code and hashed each log. The history repair refused to move the branch until `git diff <old tip> <new tip>` was empty, and that check caught a botched rebuild during rehearsal.

**Lowlights.** The lead cleared the NVIDIA risk by reasoning from two doc comments that were true only inside an AppImage and said so nowhere. Checking the decision logic without checking whether the decision runs is the same error the item itself is about, one layer up: every signal above the pixels agreed and every one was wrong.

The lead routed a test failure to a lane as a probable routing defect, with an instruction not to adjust the assertion, while Gate was reading the full log and the fixture and reaching the correct answer. The test was new in this round and had simply been written with the wrong expected body. Sending a lane after a defect that does not exist is expensive, and the correction had to chase it.

The lead set an acceptance bar, red before green after, that was contingent on an untested assumption: that the one-CPU rig reproduces this defect at all. It does not. The bar was stricter than the item's and also unreachable, and a lane's close depended on it for hours before the finding branch fired.

The lead cleared a gate red as a harness fault and instructed the gate owner to populate the frontend bundle before gating. That removed the exact condition a clean checkout runs under, so the local gate could no longer see a real defect the round had introduced, and only the release pipeline caught it. The diagnosis of the cause was right and the conclusion drawn from it was wrong, which is the more dangerous of the two.

A verification script written by the lead reported a bodyless commit that did not exist, because `git log --format='%H %b'` puts multi-line bodies on their own lines and a one-word continuation looks like a bare hash. The instrument was wrong, not the artefact, which is precisely what the round spent its time telling everyone else to check for.

**Honest feedback.** Three separate times the decisive question was not whether something was proven but what happens when it fails. An unproven tunnel arm was acceptable because the chain falls to DOM at every link. A production race was tolerable because a second check downstream re-verifies. The NVIDIA signal was not acceptable, for the mirror-image reason, and that is the one the lead got wrong. The failure-mode question should have been the default from the first ruling rather than a pattern noticed at the third.

## Follow-ups

- Extend driver detection beyond the AppImage bootstrap so packaged Linux desktops can reach the accelerated renderer where their driver supports it. Today `.deb`, `.rpm`, Nix and source builds keep DOM on every driver by construction.
- Browser-smoke checks 59 and 62 disagree with the product about the transfer ceiling on unmodified code, in opposite directions: one receives a limit where it expects content, the other content where it expects a limit. Pre-existing, and it prevented an acceptance line from being read this round.
- The liveness mechanism reaches production and is bounded there. A desktop dying inside a child's fork-to-exec window leaves its socket connectable, which biases routing, but `try_handoff` independently requires a valid response, so the cost is a wrong initial route and up to a three-second timeout rather than a false success.
- Two further load-sensitive tests now have measured rates on a verified one-CPU cap: `reset_contention_does_not_starve_single_worker_runtime` at 3 in 15, and `broadcast_config_changed_refreshes_direct_terminal_spawns` at 1 in 15. These are the first measured rates recorded for that population.
- The ghostty-on-Linux default's stated rationale narrows now that a Linux desktop can carry WebGL. The default is unchanged and still defensible on its own measurement, which holds on both sides of the dma-buf switch.
- `scripts/e2e/scenarios/terminal-grid-rendering.md` carries hard-wrapped prose against the house rule. It predates this round, which matched the file's existing style rather than introducing the deviation.

## Known gaps

- All three pixel acceptance readings for the renderer item are unmeasured. The round's machine is a KVM guest with no display, no GPU and no WebKit2 typelib, where `--include-renderers` reports a confident 0.0% that means nothing was captured. Two of the three additionally require an NVIDIA proprietary-driver host, which was not available. The exact commands, expected numbers and disqualifying conditions are recorded for the host to run.
- No test drives the renderer signal through a registered tunnel into `serve_static` and asserts the returned meta tag. The gateway preserves generic path and query, and the desktop URL append and served-shell response are proven separately. The gap is safe because the signal is absent-means-DOM at every link.
- The liveness item has no natural before-and-after rate. The rig measured 0 red in 15 on unmodified code, so no rate comparison exists, and the deterministic forced-race result is not one.
