# Release v0.99.0

Status: GA 2026-09-19. One candidate, `0.99.0-rc1`. The release closes a thirty-cycle review fix loop that ran from 2026-09-11 to 2026-09-19 over a 2.58 MB static review of the Rust tree, plus a gateway security track the owner ruled item by item: 579 commits between the v0.98.0 tag and the release candidate. What a user sees is a devserver grant that is all-or-nothing, extension links bound to the session that opened them, reverse tunnels restricted to the owner's own desktop app, and a long correctness pass in which file operations that could lose data are refused or rolled back, a stalled mount or a stalled transfer stops wedging the rest of the system, and one bad lease or one damaged cache file costs one thing instead of a whole node. Staged on `0.99.0-ga`; the GA commit is the one carrying this report.

## What shipped

- **A devserver grant is one authority, and the grant model is written down.** A grantee holds the owner's authority on the devserver: the launcher library, windows, command launcher actions, `root=filesystem` transfers and extension writes. There is no viewer role and no read-only filesystem refusal, because the terminal data plane cannot contain a viewer, and the migration that dropped the roles is the file to read before anyone proposes putting them back. Reverse tunnels are the single exception: their two WebSocket legs are refused with 403 for the owner's browser session, for a grantee on any client, and for any session whose client the gateway does not state. An assertion signed before the client field existed verifies as an unknown client and never as the desktop, which is why this release wants the gateway host upgraded before the devservers and desktops.

- **Extension links are bound and bounded.** Anonymous extension capability links are gone: a link binds to the user who opened the tab, dies within the hour or on revocation, and cannot climb out of its extension, because the proxy now refuses any request on an extension path that holds a dot segment however it is spelled, percent-decoding up to four rounds before it gives up and refuses anyway. That refusal is what makes the containment claim true at the proxy rather than at the devserver's mercy.

- **Data-loss paths in the workspace are closed.** Renaming onto an existing file is refused rather than silently replacing it; a failed directory copy leaves nothing half-copied; promoting a draft into its own folder is refused rather than deleting it; a failed draft merge rolls back; a copy or move whose destination is inside its source, including through a symlink or a differently-cased name, is refused; a trashed file goes back where it was when its metadata write fails; a save whose file changed on disk while its body was uploading gets a conflict instead of overwriting the external edit; and a metadata export now snapshots the graph and the search index with the write journal and the rebuild marker captured between them, so a write that straddles the two snapshots leaves a record instead of an archive that imports as silently stale search.

- **A failure costs one thing.** A transient accept failure no longer takes down a node's tunnel listener or the fleet controller; a panic in one proxy's control session no longer stops the controller; a lease, admission or row the controller cannot verify kills or refuses that one tunnel instead of evicting every tunnel on the node every grace period; a proxy at its per-node limit or the fleet memory budget refuses one tunnel instead of dropping its control session; a heartbeat materializes a view only for rows that actually changed. On the workspace side, a semantic search during a rebuild cannot deadlock a workspace, one damaged vector cache file cannot take down text search, two processes cannot both hold a workspace's writer lock, an open under descriptor pressure fails after three seconds with a retryable 503 instead of hanging, and a hung network mount no longer stalls every other workspace while one mounts.

- **A dead or replaced workspace root says so everywhere.** A mounted workspace whose directory is removed or swapped reports as unavailable with a reason naming the path and the verbs that clear it, instead of reading as healthy while every file request through it answers 404. On Linux and macOS the state clears exactly when the original directory returns and never for a freshly created one; on Windows the check cannot tell a replaced directory from the original. `chan ps` shows it as degraded, `chan workspace status` prints the reason, both web surfaces draw it through one classifier, and on the owner's ruling the launcher's on route answers 200 with the workspace's row on every success, healthy or degraded, where it answered 204 for one and 409 for the other.

- **A whiteboard on a stalled mount is no longer announced as deleted.** The existence probe read every transport error as "absent", so a network mount or FUSE client answering `ENOTCONN`, `ESTALE` or `EIO` made the reconciler fan a removal to every attached client, drop the compare-and-set token and stop the flush clock. v0.98.0 fixed the document side of this; this release fixes the scene side.

- **The desktop and the CLI recover instead of stalling.** A window whose native build fails is retried; a gateway connect that cannot start sign-in is parked and offers Connect again instead of leaving the card in Connecting with no buttons; lifecycle requests on a slow devserver outlast the polling deadline in both directions; forgetting a workspace with live terminals over a gateway reports them and can be forced; a gateway whose stored credentials cannot be read shows the error; `chan upgrade` on Windows probes the rename before it moves the running image, holds a Ctrl-C listener across the whole replacement, and bounds every rename at ten attempts and 1.625 seconds of sleep on a sharing violation; and a quick `cs` command on macOS no longer fails with "Socket is not connected" when the server's close beats the client's half-close.

- **The gateway profile package installs beside its own release again.** Its `.deb` had declared a dependency on identity 0.78.0-1 in every release since that pin went stale, so an operator following the README was refused by apt and dpkg. The pin now moves with the release and the Linux gate asserts it.

- **Sixteen unreachable desktop commands, the outbound workspace windows and two legacy window label families are gone**, with the three macOS crates left over from a removed PDF module. None of it was reachable from any window: the default capability carrying the main-window set declares no remote scope, so the loopback-served launcher could never invoke them.

- **Contributor and packaging tooling.** `make pre-push` now fails when `Cargo.lock` is not the lock the Nix `cargoHash` pins were harvested for, which means every version bump, release candidates included, harvests the hashes rather than discovering a stale one at the tag; the gateway workspace's docs build under denied warnings; the gateway packaging isolation test is a step of every release; and the Windows CI test subset fails closed when a filter matches nothing or an `#[ignore]` hides a case it was meant to run.

## Team and process

The loop ran thirty cycles over nine days. The source was a static review of 1,216 findings: 22 high in its appendix and a "Start here" list of 25 highs, 177 mediums and 1,017 lows. **All 25 highs are fixed** (cycles 01 to 08), and **all 177 mediums are disposed of: 176 fixed and one closed as won't fix**, a duplicated set of tool descriptions the owner ruled not worth unifying. Several mediums were fixed in a reduced form where the review's own prescription would have changed behaviour, broken a contract or reintroduced a fixed bug; those reductions are recorded rather than quietly taken. The 1,017 lows are parked on the owner's ruling. Interleaved with the review, cycles 09 to 17 ran a gateway security track on the owner's rulings: the binary grant model, the extension link binding, the client-typed assertion and the reverse-tunnel restriction all come from there, and each one was a decision the owner made rather than an inference an agent drew.

The working shape was a lead plus a small number of workers, each on its own lane, with **every change read by an agent that did not write it before the lead integrated it**. The independent review is the load-bearing part of this process and it is why the loop is worth its cost: in the final cycle alone, 74 reviews were filed across 35 order families and 28 of them refused the branch they read. A refusal produced a follow-up order rather than a negotiation, and the lead verified the fix itself where it was a single sentence rather than spending another review round on it.

Integration was one batch at a time, ten of them in the final cycle. Each batch was cut as a stack on the current `main`, gated whole with `make pre-push` against a committed sha, accounted test by test against the previous batch's gate log, with the gateway Postgres suite and the real-gateway rig run on the integrated head before it landed. The accounting is a small thing that repeatedly paid: the gate reports a total, and comparing per-test-name keys against the previous log turns "the number went up by eleven" into eleven named additions, so a silently dropped test cannot hide behind a net-positive count. The release candidate's own gate showed zero per-key changes, which is exactly what a pin-only commit must show.

Three suites ran outside the gate because the gate cannot reach them. The gateway identity and profile Postgres tests run against a container the gate skips. The real-gateway end-to-end rig drives a real control service, proxy, tunnel and `chan devserver run` with signed owner and grantee sessions, and is the only test of that whole chain; it had been silently broken for about seven weeks earlier in the year because nothing ran it, so this loop ran it on the integrated heads. The multi-devserver zone suite had not run past its consent step since July: repairing it was its own order, and it now runs 222 assertions with no failures, exercising multi-devserver routing, fleet caps, tunnel reconnect and the watchdog and extension paths.

Two environment facts shaped the work more than they should have. The host has no Rust or Node toolchain, so every build and test ran in a container through a job wrapper that writes a status file, and **the verdict is the status file's last exit code, never the launcher's**. And disk was the binding constraint throughout: the shared cargo target directories dominated it, free space on the root filesystem fell under 16 GB more than once, and each time the fix was a pruning pass over stale test executables under the target locks, run only with the owner's word because it costs rebuild time.

## Validation

The candidate `0.99.0-rc1` was cut as a pin state on a tag-free branch, never as a tag, and validated four ways before the owner touched it.

- **The full gate on the candidate.** `make pre-push` green in 31m49s against the committed candidate sha, with a porcelain count of zero read before and after: 4,191 Rust tests passed, 0 failed, 6 ignored; 4,214 web tests; zero per-test-name changes against the previous integration's log; the Nix cargo hash check green against the regenerated lock; both built devserver smokes passing. The two mandatory platform checks ran on the candidate as well: the Windows cross-check green, and the gateway packaging isolation test green.

- **Four workflow dispatches, all with publishing off.** The release workflow's dry run is the only exercise of the macOS sign and notarize path off a macOS workstation, and it finished green on all 14 jobs, including the signed Windows packages and the notarized macOS desktop build. The branch's own CI run was dispatched because a release branch gets none automatically; every job was green except the two AUR cells, which refuse a prerelease version by design because Arch forbids a hyphen in `pkgver`. That run's Nix job is the only real verification of both harvested fixed-output hashes against a build, and it passed. Two downstream dry runs covered Docker and Cachix, both green with nothing pushed.

- **The artifacts were downloaded and counted, not assumed.** All 404 MB of the dry run's output was pulled down and listed against the 25 names the release metadata generator computes for this version, run from the candidate's own script. All 25 are present. **Fifteen match exactly**: the dmg, both Linux AppImages, the macOS app tarball and the Windows NSIS installer with their updater signatures, the macOS, two Linux musl and two FreeBSD CLI tarballs, and the Windows zip. The remaining ten, all gateway debs, differ in one character: cargo-deb writes a tilde in a prerelease version where the required list spells a dot. That difference cannot exist at a GA version and is read only when publishing, so it was recorded as a follow-up rather than fixed under the candidate. The two artifacts the owner asked for were inspected by hand: the static aarch64 Linux CLI is a stripped statically linked ELF carrying the candidate's version and build id, and the macOS desktop bundle carries its dmg, its app tarball and the signature.

- **The owner ran it.** The notarized macOS desktop build was installed and used against a v0.98.0 devserver, which is the new-client-against-old-server compatibility reading no test on this host can give, and against the static aarch64 CLI running in a Lima VM on the same machine. The owner accepted the candidate from that and ruled the GA.

The GA commit proves itself separately, because the version bump is the one change none of the above has seen: the release gate on the GA commit covers the web lockfile check, and the GA commit's own CI run is dispatched and required green before the tag, because its Nix job is the last moment either harvested hash can be verified while a repair is still possible.

## Retrospective

**The independent review is what this release is built on, and the thing it caught most was false prose.** Round after round, a branch whose code was correct came back not safe to integrate because a comment, a doc sentence or a commit body said something the code did not do. In the last two days alone that included a module comment claiming a scan touches "only statics, atomics and locals" while it reads every listed heap block, a sweeper comment claiming owner-side access checks never read a table the query visibly selects from, a doc claiming a constructor derives its directory from the running executable while the constructor takes any path, and a commit body claiming a bypass "does not type-check" when a struct literal in the same module compiles fine. Each was one sentence. Each would have landed as documentation that a future reader would reason from. The habit that came out of it is the one worth carrying: a sentence about behaviour is a claim, it gets a function and a line, and a reviewer re-reads the line rather than the sentence.

**Twice a review caught something a fix introduced rather than something it missed**, which is the harder and more valuable case. A gateway change that ensured a devserver's registry row did it inline before the admission response, bounded by a client timeout longer than the caller's whole budget, so a slow profile service would have failed every dial and every lease refresh and closed the tunnel at lease expiry; the review found it by reading the two timeouts against each other, and the fix detached the ensure onto its own task. The other was caught late: a recovery-state change shipped in one integration made a previously unreachable branch reachable, so a request landing in a narrow window was abandoned and readiness reported recovering with no claimant. That one was found, reproduced and fixed two integrations later, inside the same cycle that caused it. A loop that fixes review findings is still a loop that writes new code, and it needs the same suspicion pointed at itself.

**A collated record inherits its sources' sentences.** One integration's status row said a desktop reachability probe is sent uncredentialed. It is not: the function still copies cookies for the URL, and its own doc says so. The false sentence came from a lane's draft, was collated into a status row, and was read and inserted by the lead without being checked against the code, because the lead was checking the evidence numbers. It was caught two orders later by a different agent reading the code to write the changelog. The lesson is narrow and practical: when collating, evidence figures and behaviour claims need different checks, and a behaviour claim is checked against the function, not against the report that carried it.

**The landing check must re-read the lane's evidence, not only the gate's.** A lane's scoped job failed in the window between the integration gate and the end-to-end run, and the failure was found seconds after the push rather than before it. It turned out to be a pre-existing flake in a test that samples live lock state twice, its first failure on record and invisible on every CI platform, and it was parked with its diagnosis. The outcome was harmless; the process defect was real, and it is the lead's.

**Disk pressure was the round's steadiest tax.** Three trees sharing warm cargo targets, plus a Windows cross-check target and repeated full-workspace rebuilds, pushed the root filesystem under 16 GB free more than once. Nothing broke, because the gate watcher was given a free-space guard that aborts with a named condition rather than failing forty minutes in with a confusing error, and because pruning stale test executables under the target locks reclaimed more than twenty gigabytes each time. It is recorded here because it is a predictable cost of this working shape rather than an accident, and because the guard is the part worth copying: a resource limit that can end a long job should fail as itself.

**What went well beyond the reviews.** Every integration was gated against a committed sha with a porcelain count at both ends, so no green ever described a tree nobody would commit. The per-test-name accounting turned every gate total into a list of named additions. Three suites the gate cannot reach were run on the integrated heads throughout rather than once at the end. And the candidate was validated as a pin state through the real release pipeline, including the macOS signing path, before a tag existed, which is the whole point of the no-rc-tag rule: an rc that fails costs nothing to discard.

## Follow-ups

The deferred work is tracked in the project's parking lot. By theme, what is open after this release:

- **Gateway and extension containment.** Three proxy checks are load-bearing on WebKit and must not be relaxed, because WebKit attaches the session cookie to navigations and WebSockets started inside a sandboxed extension frame where Chrome does not. The reverse-tunnel trigger still has no requester check, so a shell on the devserver can address the trigger to the owner's desktop; the owner ruled it documented rather than changed for this release. Moving the tunnel token out of the dial header, or stopping h2 from retaining the decoded header for the connection's life, is parked on the owner's ruling. Expired principals' extension bindings linger in memory until the next issue, bind, resolve or snapshot, bounded by the caps.

- **Tunnel and relay lifetimes.** An admitted tunnel's h2 connection outlives its tunnel and is polled until the peer closes the TCP. Some WebSocket bridge setup errors end the client socket without a Close frame, so a browser sees an abnormal closure. The desktop's reverse-tunnel data adapter couples both directions in one loop, which a full-duplex bulk transfer can deadlock.

- **Workspace and recovery residuals.** A persistently failing recovery action retries back to back inside one coordinator activation; an indexer dropped mid-pass strands its claimed recovery slot; reconcile repairs a graph-present, index-missing file only for non-Markdown text; re-adding a workspace whose directory was replaced still reports success while the workspace stays dead. The metadata export's in-doubt capture, and the degraded-root reporting, each left review risks that were read but not tested.

- **Operator-facing edges.** The gateway's own documentation now states the idle timeouts an nginx edge needs, because a stock edge silently ends every idle tunnel about once a minute, and states that a TLS-terminating edge holds the bearers it forwards. A terminator refusal loses its text behind `grpc_pass`. The required-assets list spells a prerelease gateway deb with a dot where cargo-deb writes a tilde.

- **Test quality.** A handful of assertions were found that cannot fail: source pins matching their own test text, a default-command test with no discriminating case, and a blocking-pool assertion that proves a handler awaited something pending rather than that its synchronous work ran on a pool thread. Several were fixed in the round; the general problem, that a check which passes by doing nothing looks exactly like a check that passes, is the one to keep watching for.

- **Known flakes.** A launcher unit test whose workspace poll timer can fire after its environment is torn down; a Windows installer smoke that can hit a sharing violation moving the running executable; a reverse-tunnel peer-close test that is timing fragile; a route test that samples live lock state twice and can disagree with itself. Each costs a rerun, and each is recorded with what is known about it rather than reclassified as a failure.

- **Untriaged.** The review's 1,017 low findings have never been triaged, by the owner's ruling. They are the largest single body of unexamined work the review left behind.

## Known gaps

- **Nothing in this release was observed on a screen.** The release host is a headless KVM box with no GPU and no display. The degraded-workspace row's amber in both themes, the close-confirmation cards and every other visual change rest on unit tests and on reading. The owner's macOS install covers the desktop app in general use and covers the compatibility reading against an older devserver, but no one has looked at the specific colours this release changed.

- **Windows behaviour is proven by CI and by unit tests, not by hand.** No Windows host exists in this environment. The cross-check type-checks the release CLI crates for a Windows target and builds two test binaries without running them; the rest is the hosted Windows CI runner, including the installer smoke that performs a real self-replacement. Nothing anywhere delivers a console Ctrl-C to a Windows `chan upgrade`, so the interrupt guard's suppression, repeated presses and restore rest on the runtime's source and the platform documentation rather than on an observation. Ctrl-Break, closing the console, a logoff or shutdown, and any external kill still end the process mid-swap, leaving the previous executable at its backup name.

- **The gateway is Linux-only and its Postgres tests are outside the gate.** They were run against a container on every integrated head, but a green gate says nothing about them.

- **The deploy order is load-bearing.** Upgrade the gateway host first. Behind a gateway that predates this release, a new chan refuses every reverse tunnel including the owner's desktop, because the assertion states no client, and extension tabs fail because the devserver refuses a nil subject. Nothing else breaks and no data is at risk, but the order is not optional. After upgrading, reload any browser tab kept open across the upgrade: a stale tab hides several command launcher entries until it reloads.
