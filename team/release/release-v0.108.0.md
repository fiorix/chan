# Release v0.108.0

Shipped 2026-10-21 as the one GA commit on `0.108.0-ga` over the candidate `0.108.0-rc0`, the commit `chore(release): 0.108.0-rc0` (`7d5932799`, sixteen files: ten manifests of version pins, three lockfiles, the two Nix files with the harvested hashes and the lock digest), which sits on `main` at `033b45700`, and four test-only commits above it: `a92e90437` (the `chan` crate's config CLI test still pinned the program status default as off, which the rc0 gate's first run found; the branch that moved the default had run the library and server suites only), and `ff8f52045`, `5585f96ff` and `6f145d74c` from the candidate's browser runs (below). The candidate's CI and dry runs ran at `a92e90437`; the three later commits touch only browser check scripts, which no CI job runs. The version held twenty-three rows: nineteen it opened with at the v0.107.0 cut (ten carried, eight raised at the cut, one raised just after the tag), and four raised by the owner on 2026-10-20. The four ship; the nineteen are carried to v0.109.0 by the owner's word at the cut ("we are done with all roadmap items for this version"). One change outside any row, a Search workspace entry in the pane menu, ships on the owner's word of 2026-10-21.

The round was run differently from the team rounds before it. The owner raised four items for review on test servers, a coordinator session briefed one agent per item (two Claude Opus seats and two Codex seats), and each agent worked alone in its own worktree and branch off `4e9a68c8c` with its own test server, which the owner forwarded with `cs tunnel` and reviewed directly, making each decision in the agent's tab. A coordination map named the files each item owned and the rule for each shared file; the coordinator merged each branch when the owner passed it as done and then cut the release.

## Retrospective

Highlights: the owner saw every change on a running server before it merged, and the decisions are in the items in the owner's words; the throughput measurement came before the default moved, as the item asked; one agent per item in its own worktree let four items move at once with no merge conflict.

Lowlights: a merge with no conflict still broke behaviour where two branches read one value differently, and only reading both branches' readers found it; the coordinator's first item text for the sketches made two claims about p5.js (a negative sphere radius, default edges) that the agent measured false; a Codex seat's sandbox and the coordinator's own client refused some setup steps (worktree creation, agent spawns), which the owner ran.

Honest feedback: a coordination map that names shared files is worth keeping, and it should also name shared values (a preference, a label) that more than one item reads or renames.
