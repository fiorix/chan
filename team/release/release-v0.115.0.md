# Release v0.115.0

Shipped 2026-10-29 as the one GA commit on `0.115.0-ga` over `2e24fc21f`, which descends from the base `079038557`, the tip of `main` at the cut. Above the v0.114.0 publication record `3931bf610` stand the browser check 95 row (`7afe0ac85`), the merge `cac9a678c` of `v0115/altbr` (pane navigation and the splits off macOS, the manual's Super note, the pane row and the Super decision), the merge `84a245801` of `v0115/cs-tunnel-multi` (`cs tunnel` with several specs), the bookkeeping commit `079038557`, and `2e24fc21f`, which repairs the one red the merged tree carried (the section Validation). The version ships three of its four rows with no release candidate, by the owner's words "initiate the release, ga and tag, no rc"; the fourth, browser check 95, moves to v0.116.0 unbuilt.

The Super row came from v0.114.0 by the owner's word. Its readings in two QEMU guests ended in the owner's decision of 2026-10-28 that Super is not a supported modifier on the Linux and FreeBSD desktop, and the manual says so. The pane row was raised the same day from the owner's use of the Linux desktop, where Ctrl+[ stopped at a terminal, and widened to the splits; the `cs tunnel` row from the owner's use of `cs tunnel`, where two forwarded ports cost two terminals, and decided as one request carrying every spec, a cap of 32, ranges and all-or-nothing.

## What shipped

- `superk`, Super has no tested path as a shortcut modifier on Linux: decided unsupported. WebKitGTK never reports Super to the page (Super arrives as its own keydown and the key pressed with it arrives bare, read in an Arch Linux guest with Plasma 6.8 on Wayland and a FreeBSD 15.1 guest with Xfce on X11), GTK under the page does see it, so support would need a native key handler in chan-desktop, and the desktops take many Super chords first. The owner's words: "i think the super key on freebsd and linux is far less effective than it is on the macOS and not worth the work from chan's side". The manual's Settings page says a binding cannot use Super on the Linux and FreeBSD desktop (`5b91668c0`); no key bridge change was made.
- `altbr`, Pane navigation stops at a focused terminal on the Linux and Windows desktop: off macOS `osChord` names Alt+[ and Alt+] for the pane commands and Ctrl+Alt+/ and Ctrl+Alt+? for the splits, `shouldEscapeTerminal` loses its native Control arms, and the key bridge's bracket and slash arms return first off macOS, so neither Control nor Command with an unshifted bracket or slash is claimed there and the workspace app's existing Alt and Ctrl+Alt handlers serve the desktop (`10f0b8868`, `36349be6c`); `desktop/design.md` and the manual's Navigation page say so. Ctrl+[, Ctrl+] and Ctrl+/ stay with a focused terminal (ESC, Group Separator, Unit Separator) by the ruling of 2026-09-27, and macOS is unchanged. Read on the FreeBSD guest with a debug build of the branch: Alt+[ and Alt+] moved between two stacked terminal panes and `cat -v` printed `^[^]` for Ctrl+[ then Ctrl+].
- `tunmul`, cs tunnel takes one spec per invocation: `cs tunnel SPEC...` takes one or more specs, each side a port or an inclusive range (`parse_specs` in chan-revtunnel); one wire request carries every expanded spec; `TunnelRegistry::admit` registers a command's tunnels under the devserver's cap in one lock or refuses them whole, naming the counts; the control socket sends one `tunnel_open` per tunnel, waits for every listener under the one 10 s ready window, answers one acknowledgement in spec order, and ends the group together; `[tunnel] max_live` in `server.toml` (`server.tunnel.max_live`, default 32, zero selects the default, captured per tenant) feeds the cap; the status lease names every pair (`2749431a6`). Found while smoking: the ready window's expiry answered the generic error line and exited 1 where the help said 124; it now exits 124. The desktop, the SPA and the WebSocket legs are unchanged.

Beside the rows: the config reference's `tunnel.max_live` row says the key is not surfaced in Settings, in the words the settings doc inventory test requires (`2e24fc21f`).

## Retrospective

Highlights: two readings in disposable desktop guests (Plasma on Wayland, Xfce on X11) answered a keyboard question the code could not, and closed a row by decision in a day rather than by a build nobody could test. The `cs tunnel` lane found and fixed its own exit-code gap while smoking the real binary, and its guest run caught a channel too narrow for the whole suite that a filtered run had hidden.

Lowlights: a row added to the config reference reached `main` red because the lane's checks did not include the workspace app's test suite, where the inventory test lives; the red surfaced in `main`'s CI after the merge and cost the cut a repair commit.

Honest feedback: `docs/config-reference.md` is a frontend test input; a lane that edits it owns `make web-check`.
