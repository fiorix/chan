# Release v0.98.0

Status: GA 2026-08-25. No candidates. Four roadmap items: an empty table cell stops breaking the editor's grid, the retired `cs` link card leaves pre-flight, a new slide deck says how to add a slide, and `chan serve PATH` ends with a window on every route. The round also folds in a merged branch that keeps a workspace on a flapping network mount openable, and fixes the two defects that branch brought with it. Staged on `v0980-roadmap`; the GA commit is the one carrying this report.

## What shipped

- **The editor's table grid keeps the columns the source has.** `@lezer/markdown` emits no `TableCell` node for an empty cell, so a header row of `| | |` reached `extractTable` as zero headers and the guard dropped the whole widget, while a single empty cell among labelled ones passed the guard and collapsed that column, shifting every later cell left. The widget now reads each row from its `TableDelimiter` positions: a segment between two adjacent delimiters is a cell even when blank, and a segment before the first or after the last is a cell only when it carries text. That reproduces the parser's own cell count on rows with and without outer pipes, on escaped `\|`, and on ragged rows. The empty and whitespace-only headers, every empty-cell position, and the escaped-pipe row are pinned against what `renderMarkdown` produces for the same source, which is what stops the editor and the export from drifting apart again; the outer-pipe-free and ragged rows are pinned to their existing widths instead, because the export normalizes a ragged row to the header width and equality there would assert behavior the editor deliberately does not have. From `ebd9eeb6`.
- **The `cs` link card leaves pre-flight.** Every supported install now creates `cs` on its own: `install.sh` links it, `install.ps1` writes `cs.cmd` and a Git Bash shim, the deb, rpm, AUR, Homebrew and Nix packages ship a symlink beside `chan`, and chan-desktop writes and self-heals `~/.local/bin/{chan,cs}` on every launch. The card fired only where that automation had not run, which in practice meant a developer running out of `target/debug` being handed a shell command for a name they could already reach. `POST /api/preflight/cs-link`, the `cs_link` and `cs_dismissed` snapshot fields, their client types and calls, and the `cs_dismissed` editor preference are gone; the preferences loader ignores unknown keys, so a library whose file still carries `cs_dismissed = true` loads unchanged and drops the key on its next save. From `64f86d64`.
- **`chan config` has no read-only key left.** `editor.cs_dismissed` was the only `ConfigValueKind::ReadOnly` entry, so retiring the card left that variant with no producer, which is a `dead_code` error under the gate's denied warnings. The variant, its alternative in the settable-keys filter, and its `write_config_key` arm go with the key, which makes the config reference's existing claim literally true: every scalar leaf is reachable through `chan config get/set`, and `editor.shortcuts` is the sole collection exception. From `8b5cc226`.
- **A new slide deck says how to add a slide.** The seed carries one bullet under `# Slide 1` naming the `@pagebreak` marker, so the answer is on the page rather than only in `chan-shell`'s export help and `EDITOR.md`. The frontmatter block is unchanged and the caret still lands at the end of the heading. The bullet cannot become a page break: the marker sits in backticks, so the line's non-whitespace content is neither `@pagebreak` nor an `<hr>` carrying the page-break class, and the inline-code range is also what keeps the `@` from opening the contact bubble as the caret crosses it. The seed's tests moved from a prefix-and-containment pair to exact equality on both the frontmatter block and the body, which is what makes an extra line below the heading visible. From `9bf5cd01`.
- **`chan serve PATH` ends with a window on every route.** Turning a workspace back on restored its saved windows and minted nothing, so the window the command asked for was not among them and focus landed on whichever the watcher opened last. An explicit open now mints after mounting and restoring, while boot restore keeps its no-mint mode so a workspace whose windows were closed comes back with none. Workspace ordinals allocate above the family maximum, because a workspace holding Windows 1 and 3 would otherwise number the requested window 2 and sort it into the middle; terminal windows keep their lowest-free numbering. On the devserver route, registration became conjunctive: it mounts the workspace and mints one window, a repeat registration reuses the prefix and mints another, the CLI reports the window it opened, and a host with no window registry declines before taking the workspace flock rather than reporting a success it cannot deliver. From `075f37cb`.
- **A workspace on a flapping network mount stays openable.** Merged from `fix/flaky-mount-resilience`: `RootedFs` surfaces `ENOTCONN` instead of collapsing every errno to "does not exist", so the document reconciler stops reporting a live file as deleted; the devserver probes mounted roots on a timer and reports `Unavailable` rather than a green row over a dead mount; capability handles revalidate in place across a remount whose inode is unchanged; and teardown raises the reindex cancel flag first, so a mount dying mid-index cannot strand the handle holding the writer flock. From `0fbf8011`, merged as `9fa5b00a`, with its new e2e harness brought up to this repository's shellcheck configuration in `4ea7a138`.

## Team and process

Five members: a lead and four workers, on one shared worktree with file-disjoint lanes. Two structural decisions did most of the work.

The first was a cold baseline gate before any lane started. `target/debug` had been reclaimed, so the round's first build was cold no matter who paid for it; running it as a full `make pre-push` at the base sha meant one lane paid it, every later scoped gate reused the dependency set, and the container was proven able to run every arm before four lanes depended on it. It took 49m49s and it answered the round's largest environment question at the start rather than at the end.

The second was one isolated gate worktree per lane, each detached at the sha that lane was reporting, with `target` a symlink to the main checkout's. A package-wide check on a shared worktree gates whatever every peer has half-written: `make web-check` compiles all of `workspace-app`, so one lane mid-removal reds another, and a green is equally worthless because it describes a tree nobody will commit. The symlink is what made this cheap, because registry crates fingerprint identically from any worktree while path-dependency crates fingerprint per path, so no cold build and no cross-invalidation.

Two coordination facts cost time before they were understood. A poke to an idle codex worker can queue forever, because delivery waits for output silence and an idle TUI repaints on a timer; the round lost its first four task assignments to a restart and then measured `queue_depth` after every poke rather than assuming. And cargo's build lock is per profile, so a lane that believed a running release build blocked its debug tests was wrong; three lanes nearly idled twenty minutes on that assumption before it was measured with `fuser`.

## Validation

Four full-tree `make pre-push` runs, each against a committed sha in an isolated worktree, with the sha and a porcelain count read before and after, the verdict taken from a status file rather than a pipeline's exit code, and the complete log preserved with its SHA-256:

- `25f884a9`, the cold baseline before any lane started: green, 49m49s. Running it first meant one lane paid the cold build for everyone and the container was proven able to run every arm, including the AppImage bundle and its devserver smoke, before four lanes depended on it.
- `86b7a191`, the round's four items integrated: green, 25m38s.
- `9fa5b00a`, the merged tree: **red in 12 seconds**, in the first arm. `make shell-check` rejected the merged branch's new `scripts/e2e/flaky-mount.sh`. Both findings were correct code shellcheck cannot see the intent of, and both took a site-local directive naming the reason: `cleanup` is reached through `trap cleanup EXIT`, and the process-table search is necessary because rclone is started with `--daemon`, so the surviving pid is not available from `$!`.
- `4ea7a138`, the fixed merged tree: green, 27m47s.

`make windows-cross-check`, mandatory before a GA close, then found the more serious of the two merged-branch defects. `is_transport_error` in `rooted_fs.rs` was compiled unconditionally and matched ten POSIX errnos through `libc`, while `chan-workspace` declares `libc` only under `[target.'cfg(unix)'.dependencies]`, so the Windows target could not compile the crate at all. The Linux gate cannot see this by construction, which is the entire reason that check exists. Fixed at `06e63866` by gating the classifier to unix and returning `false` elsewhere, which preserves the classification Windows had before the merge rather than guessing at a Win32 mapping; the cross-check is green on the fix.

Each lane additionally reported a scoped gate against its own named commit rather than against a working tree. The devserver half of the serve item was exercised end to end against a throwaway devserver with its own `CHAN_HOME`, runtime directory, discovery endpoint, control socket and workspaces: both the in-devserver and plain-shell discovery routes exited 0, printed that they opened a window, mounted distinct workspaces and produced distinct persisted rows, and a repeat registration reused its prefix and created a third. No command touched the owner's live devserver.

Three measurements of failure, rather than of success, are what make the greens above worth reading. The gate lane ran a deliberate red through its exact wrapper and confirmed the status file, the reader's exit, the log and journald all reported 37, then refused to treat a garbage-collected transient unit's default success fields as evidence. The serve lane restored the old ordinal allocation and watched its regression test fail at `[1, 2, 3]` against the expected `[1, 3, 4]` before trusting its green. And a `fbClipboard` hook timeout was classified as load rather than code by three independent readings, including the baseline gate's own run of that file at 494ms.

The three Nix fixed-output hashes were harvested at GA, each from its own build rather than copied between derivations. The two `cargoHash` values are byte-identical, which is this repository's expected shape because both derivations vendor the same workspace lock, and the desktop value was read from its own `chan-desktop-0.98.0-vendor-staging` mismatch rather than taken from the CLI's. Both full package builds then passed with their package and devserver smokes.

## Retrospective

The table item is the round's best work, and the reason is that its investigation preceded its implementation. The accepted item already carried the mechanism confirmed against the live parser, a blast radius wider than the original report, and a fix proposal checked against rows with and without outer pipes and on escaped pipes. Implementation was close to mechanical, and the acceptance check that pins the widget against `renderMarkdown` is what stops this class of defect from recurring: the defect was never one bad line, it was two parsers disagreeing about one source.

The strongest process result was that every instrument was shown to fail before its greens were believed. A green from an instrument never demonstrated to go red is not evidence, and this round has three separate demonstrations on record.

Two lowlights, both the lead's. The branch freeze that protects a gated sha was issued one commit too late, after a documentation commit had already landed past the running gate; the cost was contained only because that delta was provably documentation-only, verified by checking that no gate arm reads `team/`. And a task file quoted a full sha extended by hand from a short log line instead of computed with `git rev-parse`, which is exactly the trap the round's own bootstrap warns about. It failed safe because a bad object fails a checkout loudly, but the habit being enforced on four workers was broken by the person enforcing it.

The third lowlight belongs to the merged branch rather than to the round, and it is the most consequential finding here. `fix/flaky-mount-resilience` reached a merge without having been run through this repository's gates, and it carried two defects: an e2e script that failed the first arm of the first `make pre-push` that saw it, and a transport-error classifier that made the whole `chan-workspace` crate fail to compile for Windows. The second would have shipped. Four green full-tree gates could not see it, because `make pre-push` is host-native and Linux-only, and the mandatory Windows cross-check is what caught it with the tag still unpushed.

The lesson is not that the merged work was poor, because the fix itself is sound and its unix reasoning is careful. It is that a branch merged from outside the round inherits none of the round's evidence, and that the platform checks the release skill marks mandatory exist precisely for the case where a green gate is not a green release.

## Follow-ups

- `PAGE_BREAK_RE` is not the only definition of a page break in the tree. `slides.ts` matches a quote-anchored attribute value case-insensitively, `commands/page_break.ts` uses a stricter regex that refuses any additional attribute, and `pdf_pages.ts` and the document CSS test DOM class-list membership, which is case-sensitive and matches a multi-class element. Four detectors for one concept, counting the authoring macro, which is the same shape as the table defect this release fixes. A multi-class marker cuts a document and not a deck, and an uppercase class cuts a deck while rendering nothing. Raised as [four-detectors-disagree-about-page-breaks](../roadmap/v0.99.0/four-detectors-disagree-about-page-breaks.md).
- Whether a registration should mint a window onto a workspace the health probe classifies `Unavailable` is now documented in the serve item as minting regardless, but nothing pins it. Pinning it needs a test-only way to force `MountState::Unavailable`, whose map is private with no setter, which is a design decision rather than a test to slip in. Raised as [no-test-pins-the-unavailable-mint-contract](../roadmap/v0.99.0/no-test-pins-the-unavailable-mint-contract.md).
- `origin/fix/flaky-mount-resilience` still carries both defects unfixed: the unlinted `flaky-mount.sh` and the unguarded `libc` references that break the Windows build. Fixing them on the round branch does not fix them there, and a later continuation or re-merge of that branch reintroduces both.

## Platform and pipeline

The GA commit `f626d8d5` proved itself before the tag with its own `ci.yml` run `32819543021`, whose `Nix chan-desktop` job is the only place the three harvested fixed-output hashes are verified against a real build, and with a `release.yml` dry run `32819545234` at `publish=false` that exercised the macOS sign and notarize path and both FreeBSD targets. Two `publish-downstream` dry runs covered Docker `32819590912` and Cachix `32819592727`. The tagged Release run is `32823357070` and the downstream run it triggered is `32826799155`.

Five downstream targets published and were verified: the Homebrew tap, all four Docker images with their five manifests on both platforms, both Cachix pins with both fresh-runner substitution smokes, the AUR at `0.98.0-1`, and the PPA. COPR published as well, `chan` at `0.98.0-1` across ten chroots and `chan-desktop` across eight, with no EL9 desktop chroot as intended, but its two workflow jobs are red: the publication probe's 5400 second window is shorter than COPR's build time for this project, which ran past 95 minutes, and the probe reports that state as unconfirmed rather than failed. Publication was confirmed against the COPR API instead. The jobs were deliberately not re-run, because that job triggers before it verifies and a re-run would submit a duplicate build of an already published version. Carried forward as [the-copr-probe-window-is-shorter-than-its-builds](../roadmap/v0.99.0/the-copr-probe-window-is-shorter-than-its-builds.md).

## Known gaps

- **The desktop window checks were not observed.** Acceptance checks 1, 2, 3 and 7 of the serve item, and acceptance 1 of the `cs` card item, need a machine with a display: a window rendering, a window taking OS focus, and a card being absent on a real first open. The release host is a KVM box with no GUI session, so no test on it can close them. A six-step procedure covering all of them was written and handed to the owner, who decided to ship without running it and to report back if an issue appears. That decision is recorded here rather than left implicit: the serve item's focus behavior and the card's absence rest on tests, on reading, and on the ordering pin, and not on anyone having seen them.
- The isolated devserver end-to-end run proves the persisted and API-visible window record for the devserver route, but no browser was attached, so the visible presentation of that window was not observed.
- `origin/fix/flaky-mount-resilience` still carries both defects this release fixed on the round branch: the unlinted e2e script and the unguarded `libc` references. Fixing them here does not fix them there, and a later continuation or re-merge of that branch reintroduces both.
