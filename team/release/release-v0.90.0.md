# Release v0.90.0

GA 2026-08-14. A short era with one theme: executing chan on the platforms it ships to and fixing what only real execution can see. Three roadmap items closed, all Windows, worked on real Windows 11 hardware rather than by cross-compilation: the ConPTY startup deadlock that wedged every server-spawned Windows shell, a workspace-lock defect as old as the lock itself that made every holder-record read return None on Windows, and the standalone `chan.exe` executed by CI for the first time. The era's defining pattern is that writing the CI smoke the roadmap asked for surfaced and fixed two product defects the item had not predicted, both invisible to every arm that had ever run. Four items carried to v0.91.0 unstarted or blocked, and three fixes from live use shipped without items: terminals spawned from the Linux AppImage get a reconstructed host environment, the desktop end of a reverse tunnel survives fd-pressure accept errors, and macOS terminal spawn absorbs a transient openpty refusal.

## What shipped

- **Windows terminals run their command instead of hanging on ConPTY's startup handshake.** A server-spawned Windows terminal could sit forever with a four-byte scrollback, the DSR cursor query `\x1b[6n` and nothing else. The roadmap item modeled this as a pwsh prompt behavior racing the SPA's reattach cursor; the real-hardware reproduction corrected the model before a fix was written. It is ConPTY's own startup handshake: conhost emits the query before it pumps the child's output, so it gates every Windows shell (powershell.exe 5.1 and cmd.exe deadlock identically, on a box with no pwsh installed), and a server-side spawn has nothing attached to answer. The library reader now arms a pending query and the controller answers `\x1b[1;1R` on its existing 25 ms tick, after a grace in which an attached frontend's own report wins. Verified end to end through the same `POST /api/terminals` the team dialog uses: shipped v0.89.0 created the session and never ran the command in 25 s; this branch ran it in 2 s. The no-double-CPR acceptance was verified live with a frontend answering a distinctive `\x1b[7;42R` (ConPTY moved the cursor there and the library wrote nothing) against a frontend-silent control proving the fallback stays live. The three natural-exit tests gated to unix for this reason run on Windows again.
- **A held workspace lock no longer hides its own holder record on Windows.** `LockFileEx` is a mandatory byte-range lock, and the holder record lived in the body of the locked file, so every read of it returned None while a holder existed, on every Windows chan since the lock was written. Five behaviors depended on that read and all five were dead: `chan ps` named no holder, `chan close` reported a served workspace as not served, the steal path could never confirm a dead holder, chan called its own lock foreign in launchers and menus, and a same-process second acquire read as cross-process `WorkspaceLocked` instead of `WorkspaceAlreadyOpen`. The record now also lives in a `writer.json` sidecar written through `atomic_write`, with the lock body keeping a copy fed from the same value for mixed-version boxes. The intake review then found and repaired a hole in the sidecar as first shipped: nothing removed it and reads preferred it, so a crash leftover could shadow a live pre-sidecar holder's record and its dead pid could authorize a steal against a live holder. Reads now prefer the body, the sidecar is removed on release and before a steal's unlink, and a sidecar-sourced record never authorizes a steal, so on Windows a leaked dead holder's lock is identified but still refuses until the pinning handle dies, which is fail-closed and matches every shipped chan. Five existing tests asserted the correct behavior all along and had simply never run on Windows; they pass there now, with four new tests pinning the readable-while-held invariant, the legacy fallback, the sidecar's removal on release, and the no-shadow rule.
- **The standalone Windows CLI is executed on CI.** `chan.exe` ships twice, as the signed standalone zip and bundled in the NSIS installer, and no CI arm had ever run it. `scripts/smoke-windows-cli.sh`, wired into `make ci-windows`, now drives the two Windows-only syscall paths end to end on the Windows arm: the `DETACHED_PROCESS` daemon spawn, and named-pipe discovery plus an `Identify` round trip through `chan ps`. The smoke's headline check was un-writable as specified until the lock-record fix landed, because named-pipe discovery reads the holder record both its callers could never obtain. Verified on Windows 11: it passes against the release binary and fails at the first step against a broken one.
- **The CLI runs on a stack the binary sizes itself.** A debug-profile `chan.exe` died at startup on every invocation, `--version` included: the MSVC linker reserves 1 MB for the main thread and the future `chan::run` produces does not fit unoptimized. Release happened to fit, so the shipped artifact was fine, but the limit is a cliff one future-sized change away from the published binary, and it would arrive as a startup crash. `main` now spawns the CLI on a thread with an explicit 8 MiB stack and joins it, resuming a panic's unwind so the exit status is the panic's own. A `/STACK:` link arg was rejected because cargo replaces `target.*.rustflags` wholesale when `RUSTFLAGS` is set, which the CI test step does, so the flag would vanish from exactly the builds most likely to need it.
- **Terminals spawned from the Linux AppImage get the host environment, not the bundle's.** The AppImage runtime and linuxdeploy's GTK hook redirect loader and toolkit variables into the ephemeral `/tmp/.mount_*` squashfs; the GUI needs them, a spawned shell must not inherit them: system binaries resolved against the bundle's older libraries, `xdg-open` came from the bundle, `GDK_BACKEND` pinned GTK children to XWayland, and a `PYTHONHOME` with no stdlib aborted anything embedding CPython in every login shell on hosts with such profile hooks. The host environment is reconstructed at spawn, matching variables on whether their value hides the mount rather than against a list of names, and filtering prepended search paths entry by entry.
- **The desktop end of a reverse tunnel survives accept errors.** Under fd pressure `accept` fails with EMFILE while every established socket keeps working, and the desktop listener's run loop treated that as fatal, tearing down a healthy tunnel. Accept errors now follow the policy of axum's serve loop, which the devserver end already rides: connection-class errors retry immediately, everything else after a 500 ms pause. Proven by running the e2e suite under `ulimit -n` 88 to 112: the desktop-disconnected contract violation reproduces without the fix and not with it.
- **macOS terminal spawn absorbs a transient openpty refusal.** On macOS `openpty` fails with ENXIO both when the pty pool is exhausted and transiently under concurrent open/close churn where the next attempt succeeds. The spawn path retries a refused openpty on a bounded 10/20/40/80 ms backoff through an injected sleeper, so churn is absorbed while a genuinely exhausted pool still fails with the original error.

## Team and process

No multi-lane team this era. The two fixes on `main` came out of live use and were landed directly behind the gate. The Windows work ran as a single investigation-and-delivery round on one branch against real Windows 11 hardware, which is what the DSR item's own acceptance demanded: it was registered as a candidate blocked on a real-Windows reproduction, and the reproduction both confirmed the deadlock and falsified the item's mechanism before any fix was written.

The round followed the lifecycle's evidence rules in both directions. The two pre-registered items accumulated dated validation sections below their original rationale rather than editing it, one of which records that the item's model was wrong. The lock-record item was registered after the fact, inside the same round that found and fixed it while writing the smoke, so it carries evidence rather than a proposal and says so in its status line.

At intake the branch received a multi-agent adversarial review: four dimension reviewers over the full diff, every finding independently verified by refuting and impact-judging agents, sixteen agents in all. It confirmed one major defect, the sidecar shadowing above, which the branch's own cfg(unix) host tests corroborated on the suite's first Linux run, plus a set of smaller ones repaired at intake: a doc block spliced onto the wrong function, an understated comment on the DSR grace's high-RTT cost, the smoke script's ps retry loop dying under set -e on the first failing attempt, its missing executable bit, and a clippy denial on the stack-floor pin. The branch's commits were also amended to the house commit-message form before merging.

## Validation

- All three Windows items validated on real Windows 11 hardware through the library's and the CLI's own paths, not through mocks: the DSR deadlock reproduced deterministically and its fix measured (a session spawned with `exit 7` recorded nothing for 25 s before, exited in 0.38 s after), the no-double-CPR line verified live against a frontend-silent control, the lock fix pinned by the five previously-failing tests, and the smoke run against both a working release binary and a known-broken debug one to prove it can fail. The intake amendment to the lock repair is validated on Linux by the two host tests that had gone red under the sidecar preference and the two new lock tests; its Windows read path is exercised by the CI smoke's `chan ps` check on the Windows arm.
- The revtunnel fix reproduced and verified under an `ulimit -n` sweep of the e2e suite, with starved runs failing honestly at their named steps.
- The darwin openpty retry is pinned by tests on attempt and backoff counts through an injected sleeper rather than wall-clock time.
- The full Linux `make pre-push` gate ran green at the close commit in the project's gate container before push.
- Not run this era: the `release.yml` publish=false dry run and `make windows-cross-check`, which are release-cycle steps ahead of the GA tag, and the browser smokes, which nothing this era touched (no editor, SPA, or reconciler change).

## Retrospective

Highlights: the real-hardware reproduction protocol paid for itself twice. The DSR item was deliberately held at candidate until a real Windows box could answer its three questions, and the answers changed the fix's justification from a race repair to a handshake answerer that covers every spawn path including headless. And the smoke item, filed as small CI hygiene, surfaced two product defects while being written, one of which had silently disabled four user-facing behaviors on Windows since the workspace lock existed. Neither would have surfaced without executing the binary on the platform.

Lowlights: the lock defect is a reminder of what scoped CI cannot see. Five tests asserting the broken behaviors existed the whole time and had never run on Windows because the arm is scoped to two crates; the deferred full-suite Windows port is still a held draft, and the crate's remaining Windows test failures (unix harness assumptions, not product defects) ride on it. The webgl and frame-rate items carried again with no code, now two releases old.

## Follow-ups

- Four items carried to v0.91.0: the external-edit stale read (deferred on its recorded precondition), the WebGL present stall (reframed by measurement to a desktop-shell question the AppImage environment work did not touch), the frame-rate acceptance guards (instrument built, rule undecided, no code shipped), and AUR publication (re-checked 2026-08-14: the news index carries nothing newer about the incident and the notice still describes restrictions as ongoing, so both restoration conditions stay unmet).
- The full-suite Windows test port stays a held draft; the lock item's remaining Windows harness failures and the 17 vacuous tests removed in v0.89.0 both point at it.
- The DSR grace's standing cost at high RTT is documented rather than closed: a frontend whose round trip exceeds the 150 ms grace, such as a tunnel-published devserver, loses the answer race on every query its programs emit, receiving the library's `1;1` floor first and landing its own report as stray input. Accepted over the alternative, where an unanswered query costs the whole session; a grace that widens when a frontend is attached is the named candidate if it bites in practice.
- The lock item's before/after Windows failure-count sentence does not reconcile arithmetically with its own list of fixed tests; restating it needs the owner's Windows box and is flagged rather than guessed at.
- On Windows a leaked dead holder's lock is identified but not reclaimed, by the fail-closed steal rule the intake amendment records; if leaked ConPTY handles turn out to pin locks in practice, reclaim needs a discriminator that can tie a record to the current tenancy.
