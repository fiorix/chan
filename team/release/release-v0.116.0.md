# Release v0.116.0

Shipped 2026-10-30 as the one GA commit on `0.116.0-ga` over `c073f7491`, the merge of `desktop/terminal-prototypes` at `e8cf0e8a4` into `main` at `a4b5844b9`, the tip of `main` since the v0.115.0 publication record. The branch is the owner's terminal prototypes round, built on macOS from 2026-10-29: twelve commits over `main` by the owner's macOS agent, three readings and a fix from the Linux host on 2026-10-30, the ghostty secret masking from a third agent's branch `v0116/ghostty-mask` rebased onto it, and three more commits from macOS the same day. The version ships four of its six rows with no release candidate, by the owner's words of 2026-10-30: "let's bring in desktop/terminal-prototypes and merge onto main, this will be v0.116.0 and you will cut it from here to tag all the way".

The round began as prototypes on the owner's desktop: a see-through terminal background and a default-terminal launch that opened a second launcher beside a running chan-desktop. Both were built without a roadmap item and recorded as items on 2026-10-30, when the Linux arms were read; the `cs terminal list` row was raised from that reading and fixed the same day; the ghostty masking row was raised by the owner on 2026-10-30 and built the same day. The browser check 95 row came from v0.115.0 unbuilt and leaves unbuilt again; the local `cs tunnel` toast row was raised during the round and not taken.

## What shipped

- `termopa`, A local terminal window cannot show the desktop behind it: `terminal.background_opacity` in `server.toml` (80 to 100, 100 the default), `chan config set` and the Settings slider in steps of one (`1b66ab60f`, `25165529a`, `e63b637f1`); every local standalone terminal window and the default-terminal window is built transparent and carries `transparent=1`, the page paints the terminal background at the live alpha and keeps the workspace backdrop painting the gutters and frames through a masked layer with a hole behind each terminal pane, and the setting applies live to every open terminal window (`fc97aef28`, `077abe298`); the macOS title bar keeps an opaque layer (`fc97aef28`); the browser caret of ghostty's host is hidden (`cff4cb0a1`); workspace, devserver and control windows stay opaque. Known gaps: the light theme in a see-through window is not read by eye; ghostty treats a cell with an explicit black background as clear; Linux needs a compositor.
- `xdgho`, A default-terminal launch beside a running chan-desktop boots a second launcher: a bare `chan-desktop` or one with `--dir` alone is offered to a running same-user desktop over the handoff socket as `OpenTerminal`; the desktop mints a throwaway standalone terminal window whose first terminal starts in the launch's directory (a row never saved, so a relaunch does not restore it), answers `TerminalOpened`, and the launcher exits 0 (`2d5944560`). `-e`, `--hold`, `--app-id` and `--title` keep their own process; no desktop, the `CHAN_NO_DESKTOP_HANDOFF` opt-out, a refusal or no reply in three seconds fall back to the launch as before; the desktop refuses once its shutdown has started.
- `cscwd`, cs terminal list hides the directory of a standalone terminal outside the home: `Session::cwd` reports the shell's live directory when it lies under the registry root or under the directory the session was spawned in, so a standalone terminal outside the home lists its directory in `cs terminal list --json` and in the page's cwd frames; a directory under neither stays unreported (`de817d043`).
- `ghmask`, Secret masking does nothing under the ghostty backend: the detection is backend-neutral and a painter over ghostty's canvas fills the mask rectangles in the frame that draws the content, wrapping the renderer's `render` because the pinned ghostty-web never fires `onRender`; the carve-outs are gone, so a control terminal with masking on spawns on the configured backend and the menu row and toggle work on both (`c3d1f0bd7`). A scrollback line filled to its last column is read as wrapping (the pinned build keeps no wrap flag in scrollback), so a full hard-ended line can mask into the next line's first word.

Beside the rows: every ghostty terminal has its own WASM instance, because the pinned build hands a disposed terminal's pages to the next one (`56184e181`); ghostty wheel input in a full-screen app is paced as xterm.js paces it (`66dff9cf2`); the mouse-driven entry into Hybrid Nav from a pane's tab bar is gone and the mode is keyboard-only (`078d531a6`); the ghostty backend hint says a reload applies the switch (`b1437c050`); chan-desktop and the devserver run one config watch for every tenant they mount, so a settings write in one window reaches every other open window at once (`727ce92a1`).

## Retrospective

Highlights: a branch read on a second platform the day it was handed over found one real defect (the hidden directory) and one design gap (a window built at 100 never following the slider), and both were fixed before the cut. The masking landed as a separate branch and merged as a clean union, so the three agents never edited one file together.

Lowlights: two features shipped with no roadmap item until the day of the release, so their contract and verification lived in commit messages alone until then. The gate's AppImage step cannot be proven on the build host; CI's Ubuntu runner is the only reader of it.

Honest feedback: prototypes that reach a release should get their item when they turn from prototype into scope, not at the cut.
