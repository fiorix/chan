# Release v0.123.0

Shipped 2026-11-03 from `0.123.0-ga`: a no-rc release by the owner's word ("Straight to GA") of the five Hybrid Nav commits built on the owner's local branch `hybrid-nav-tmux` over an old `main` (`762f95240`, inside v0.121.0). One Claude session on the Linux host rebased them onto `main` at the v0.122.0 record, gave them roadmap rows, reran their checks in an sdme guest, gated the result and cut the release on the owner's words.

## What shipped

- `hntmux`, Hybrid Nav fights tmux in a tmux window: in a window that shows a `tmux -CC` window, Hybrid Nav now stages what tmux will be asked for. A split shows a staged New tmux pane and starts no local shell; a divider move, by key or by a mouse drag, previews and sends nothing; Enter sends the resizes and then the splits one at a time, and tmux's next layout shows the result; Escape sends nothing. tmux's layouts, peer saves and terminal renames apply to the live tree at once and never stale the draft, the window-size ask waits for the mode to end, and a tmux pane offers no A/B flip, send-to-side, tile swap or tab staging (`8caa04691`, `26c46dc93`).
- `hnstagedname`, a terminal staged in Hybrid Nav turns the draft stale on a name another window holds: a staged terminal now asks the server for its name, and a settled name for a tab only the draft holds stales nothing (`1bc4ca95a`, with the comment correction `3a74bd1f4`).
- `hnshift`, Hybrid Nav's Shift resize step does not fire on a US layout: the step is one constant and the cheatsheet's Larger nudge row is gone (`ef4cbab28`).

## Rebase and review

The branch's base sat 49 commits behind `main`, below v0.121.0's code fixes and v0.122.0's documents sweep. The five commits were cherry-picked one at a time onto `12b1da9d6` in a new worktree. The fourth and fifth applied clean. The first three conflicted in three files: `App.paneMode.test.ts`, where both sides edited the header comment and an import line and appended a `describe` block at the same place (both kept, the comment merged); the manual's tmux section, where both sides edited the section's tail (upstream's close paragraph and its new pointer kept, the Hybrid Nav paragraph inserted before them); and the workspace app's `design.md`, whose detailed tmux paragraphs the v0.122.0 rewrite had removed. There upstream's text was kept and the branch's additions were condensed into it: a sentence that a tmux window's panes have no sides, and a paragraph on what Hybrid Nav stages in a tmux window, keeping the behaviour and dropping the function names; the owner accepted that wording ("Accept condensed"). The rebase was read against both sides: `git range-diff` shows the fourth and fifth commits identical and the first three changed only at the conflicts; the fourteen paths only the branch changed equal the branch's files byte for byte; in the four shared files that merged by themselves (`App.svelte`, `Pane.svelte`, `tabs.svelte.ts`, `navigation.html`) the added and removed lines equal the branch's; and v0.121.0's changes in those files (the key guard under an open dialog, the tab drag's source on dragend) were read as independent of Hybrid Nav's tmux path. A documents commit (`bb28ecfc6`) gave the work three roadmap rows.

## Validation

- The branch's own checks rerun at the rebased tip in an sdme guest bound to the worktree (`dev/hn-tmux-rig/rig.sh` with its own guest, 6 CPUs): the debug build and the web bundle; svelte-check with no errors or warnings and the workspace app's whole vitest suite, 632 files and 8,455 tests passed; and browser checks 15, 99, 107, 123, 195, 198 and 199 all passed (198 drives Hybrid Nav over a real `tmux -CC` window, 199 the staged terminal's name across two windows). On the old base the first three commits had recorded their new tests and browser checks red before each change, and 13 mutations of the first commit each turning its tests red.
- The full `make pre-push` gate, then `make test-symlink-tmpdir`, at `bb28ecfc6` in the release worktree on the Linux host under `env -i` with private homes: green except the host's AppImage bundle step (linuxdeploy's strip cannot read Arch's libraries), the gate's last step, with 65 `cargo test` result lines of 6,703 passed and none failed, the web suites at 234, 744, 8,455 and 20 tests, the marketing check and the release devserver smoke green, and the symlinked-temp suite at 4,919 passed. `make check-windows-test-target` did not run (no MinGW compiler on this host).
- `make windows-cross-check` did not run: sdme refused the guest's disk cap on this host ("--disk unsupported here: btrfs quotas are already enabled on the filesystem backing /var/lib/sdme by something other than sdme"), as on earlier releases. Windows is covered by `ci.yml`'s Windows arm and the dry run's Windows packages.
- `make gateway-packaging-isolation-test` at the GA commit, and on `0.123.0-ga` its `ci.yml` run, the `release.yml` dry run, the two `publish-downstream` dry runs, Gateway CI and the FreeBSD build: run or dispatched after this commit; their ids are recorded after the tag.

## Retrospective

Highlights: the rebase over a 49-commit gap and a documents rewrite kept every code line of the branch, and the branch's own browser checks and suite reran green in an isolated guest within minutes. Lowlights: the design document the branch edited no longer had the paragraphs it edited, so its additions were rewritten rather than replayed; the Windows cross-check is still refused on this host. Honest feedback: the tmux staging was checked in a browser against a real `tmux -CC`, not in chan-desktop.
