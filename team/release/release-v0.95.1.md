# Release v0.95.1

Status: GA 2026-08-22. No candidates. A one-fix patch release cut the day after v0.95.0, from the owner using that build: over the gateway, the desktop could not turn a workspace off. The arm that failed is the one the v0.95.0 report had named as unproven.

## What shipped

- **Turning a workspace off on a gateway-registered devserver works from the launcher again.** Over the gateway the desktop reaches the devserver's launcher API, where on and off are distinct routes: `/on` takes no body and `/off` carries the `{force}` its live-terminal guard reads. The gateway arm of `set_workspace_on` posted both toggles to `/on` with the direct arm's `{on, force}` body, which that route ignores, so an off re-mounted the workspace as a no-op: the bridge answered Done, the launcher's pending marker spun out its backstop, and the row stayed on with nothing to show for it. The arm now builds its request through a pure `launcher_workspace_toggle_request` (on: `/on`, no body; off: `/off`, `{force}`), the same request the browser launcher sends through the same proxy, so the off lands and an unforced off of a workspace with live terminals still answers the 409 the launcher confirms and forces. `chan workspace close WS --on TARGET` against a gateway-registered devserver rides the same function and is fixed with it. Direct and ssh devservers were not affected, because their management route reads `on` from the body. From `fix/launcher-gateway-off-toggle` (3e85ef27), one commit forked at `main`'s tip (c4bd17b6) and folded in as a fast-forward.

## Team and process

One owner-authored fix branch and one agent session in the owner's main checkout for the cut; no team provisioning and no review lanes. The fix carries its own CHANGELOG entry and two tests, so the cut's work was the release mechanics: the pin bump, the three lockfile regenerations, the Nix hash harvest, the gate, the platform checks, the dry-run dispatches, and the tag. The GA commit was staged on a tag-free branch, `0.95.1-ga`, so that the dispatch ids could be recorded by amending that branch's tip rather than by rewriting `main`; `main` was fast-forwarded once, to the final GA commit, immediately before the tag. Builds and the gate ran in the warm `chan-appfix` sdme container (Ubuntu 26.04, rust 1.95 pinned, node 22 / npm 11) against the main checkout; the Nix harvest and the Windows cross-check ran in disposable `ubuntu` guests driven from the host.

## Validation

## Retrospective

**Highlights.** The defect was found by using the build the day it shipped, and the fix arrived with the two tests that make the arm's request shape a contract rather than a convention: the pure function is asserted on both routes and both bodies, and the stand-in round trip asserts what actually goes over the wire, in order, including the CSRF header the proxy requires on every write. Staging the GA commit on a tag-free branch kept `main` at its published tip until the tag was ready; the re-cut that records the dispatch ids rewrote only that branch.

**Lowlights.** The bug lived in exactly the arm the v0.95.0 report had listed as unproven: the remote-arms e2e could not reach "the gateway arm of the desktop's add-workspace call", the report said so, and the release shipped with the gap open. The gap was real and it cost a patch within a day. A recording stand-in for the proxy origin is the proof available off a real gateway, and it is now in the tree; it would have caught this before v0.95.0 had it existed then.

**Honest feedback.** The stand-in pins the request the desktop sends, not the devserver's handling of it; that the launcher's `/off` reads `{force}` and answers the live-terminal 409 is asserted by the devserver's own tests, and the two halves meet only in the owner's hand-smoke over a real gateway. A gateway-backed desktop e2e remains unbuilt.

## Follow-ups

- A gateway-backed e2e for the desktop's devserver bridge (the add, on/off, close, and forget arms through a real `devserver-proxy`) is the check that would have caught this before v0.95.0; the recording stand-in covers the request shape only.
- v0.95.0's follow-ups stand unchanged: the Windows 11 NSIS passive-reinstall acceptance, the staged on-launch download held in memory, the generator's two go-red smokes, the `chan serve` handoff launch on Windows, the dead `Signature:` parse arm, the browser-smoke Chrome pin, the wine `TMPDIR` note, and the owner-run e2e ladder.

- v0.95.0's known gaps carry forward unchanged: the Windows 11 NSIS passive reinstall, the macOS compile proven only by the dry run, the desktop's Windows unit tests not executing under wine, the remote-arms e2e's unreachable arms (the ssh control-terminal connect, the gateway arm, Windows named pipes), and the four unmeasured GUI e2e suites.
