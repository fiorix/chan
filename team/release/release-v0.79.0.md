# release-v0.79.0

v0.79.0 is a capability release with one large addition and three contained ones. The gateway becomes administrable as a product boundary without direct database access. Off macOS the native menubar collapses to the launcher window alone and its chords move into a per-window key bridge. A second terminal backend ships opt-in behind a default-off setting. Tab rotation stops stopping at the visible Hybrid side. A fifth item removed a class of test that failed on host load rather than on defects.

This cycle is cut directly to GA with no RC pin. The `0.79.0` commit remains untagged until that exact commit passes the local pre-push gate, the relevant workspace-lifecycle scenarios, a `release.yml` dispatch with `publish=false`, the cache-only downstream rehearsal, and artifact inspection. A red rehearsal is a stop condition for the release owner.

## What shipped

**The gateway is administrable without touching its database.** Users carry explicit enabled, suspended, blocked, and restored states, and a durable per-user connected-devserver limit is enforced across the proxy fleet. Control protocol v2 carries tunnel rows and redacted tenant browser-session rows in one proxy snapshot and one contiguous delta generation, so a generation gap retracts both classes of authority and forces a full resync; tenant-session rows use a random admin UUID independent of the opaque cookie id. Session revocation cannot report complete while a connected command is unconfirmed, controller authority is warming, or a retained disconnected proxy authority is unreachable. An idempotent admin API lets an external account service push durable access policy, with operator use on `chan-gateway-admin` and machine use on the same scoped HTTP contracts. The contracts are generic gateway capabilities: no billing provider, product name, price, deployment topology, or consumer schema is encoded. Migration 0016 adds the devserver user and fleet policy tables and the identity session index, and ADR 0003 records the shared control-authority decision.

**Account credentials and database roles are separate surfaces.** Identity configuration, packaging, and the kube manifests no longer share one credential surface, and the packaging test scripts gained database-role reconcile and isolation checks.

**Off macOS, only the launcher window has a menubar.** The app-wide default menu and the per-window-kind bars, meaning the workspace hamburger mirror, the owned terminal and control shapes, and the `wscmd:` and `ws-*` id namespaces, are gone. The launcher bar attaches per window through `Window::set_menu`, and every other window is born menu-less. The chords those bars owned move into `KEY_BRIDGE_JS`, injected per window so routing stays contextual: `Ctrl+Shift+N` opens another window of the invoking window's own connection, `Ctrl+Q` runs the same confirm-then-quit flow as the menu item, and `Ctrl+Shift+T` on a control terminal spawns a standalone terminal instead of toggling a tab it does not have. The launcher never loads the bridge, so its native chords cannot double-fire, and the bridge cases are gated on `!metaKey`, so macOS is untouched.

**ghostty-web is available as an opt-in terminal backend.** A `terminal.ghostty` server setting, default off with a Settings checkbox, makes newly opened terminals parse and render through Ghostty's WASM VT engine instead of xterm.js. The wasm and library lazy-load only when the toggle is on, and a failed load falls back to xterm.js. Four upstream-behavior workarounds are load-bearing: OSC 52 rides a byte-level observer because the WASM parser swallows the sequence with no JS hook; SGR wheel reporting rides a chan-side shim because upstream stops wheel propagation before its input handler sees it; the key-handler wrap maps chan's semantics onto ghostty-web's inverted contract; and the write-origin tracker uses a synchronous writer because upstream defers write callbacks to rAF, which stalls in a backgrounded page and would wedge replay suppression open. The backend ships opt-in and never as the default, and its narrower feature set is the reason for that shape rather than an argument against carrying it: find bar, styled scrollback snapshots, and external link routing stay xterm-only.

**Tab rotation covers the whole pane, not one side of it.** `app.tab.next` and `app.tab.prev` rotate the pane's full ordered tab set, side A in strip order then side B, flipping the visible side when rotation crosses the boundary. Rotation entered from an empty visible side lands on the first tab for next and the last for previous, so the chord is never dead. The close shortcut on a pane whose visible side is empty now flips to the side holding the tabs and keeps the flash that explains why the pane stayed open. A pane with tabs on one side behaves as before.

**Two classes of false-red test are gone.** `SelfWrites` takes a caller-supplied instant through private `_at` internals instead of reading the wall clock inside, so its expiry tests drive synthetic times with no sleeps while the public API, production behavior, and every caller stay unchanged. Browser check 62 replaced a 10 Hz rate ceiling with the coalescer's structural cap, which a slower host can only satisfy more easily, and check 60 now skips on an absent launcher bundle instead of failing downstream. Both rules are recorded in the browser-smoke check contract.

## Team and process

Two agent lanes ran in one shared worktree off a `v079/integration` branch, coordinated by a host session that owned integration, review, and the gate. A third agent delivered the gateway control plane in a separate worktree. Lane briefs pinned the round's standards in a file every lane read: explicit staging pathspecs, hunk review before each commit, no history rewrite, scoped own-gates run after the last edit, and the project's writing rules.

Review caught what lane self-reports did not. A dead chord survived the first rotation implementation, where both selectors no-oped when the visible side was empty and the other side held tabs, reachable by closing the last tab on the visible side. A lane marked its own item accepted, which is the owner's decision. A duplicate browser-check number meant a focused run silently also fired the destructive root-loss check, muddying that lane's own evidence. A peer message sent without `--submit` stranded unsubmitted in another lane's compose box, where it would have concatenated onto that lane's next input.

Two integration hazards showed up in the shared tree and are worth carrying forward. A peer's staged roadmap edit raced into another lane's commit between its staged-file check and the commit itself, so a merge commit carries a file its author did not write; the content was verified intact and the round's no-amend rule left it standing. And the gateway lane finished a full gate but exited without committing, leaving six thousand lines uncommitted in its worktree until the host preserved them.

## Validation

- The full `make pre-push` equivalent ran on the exact tagged commit with both agents frozen, and the SHA and clean tree were verified identical before and after, so the gate covers that commit rather than a moving tree.
- Independent host review of the merged gateway code found no committed secrets, constant-time comparison at every token site with no plain equality anywhere, empty tokens disabling the admin surface rather than guarding it with an empty string, and non-short-circuiting operators chosen so timing cannot leak whether a token was configured.
- The gateway's revocation-completeness claim is tested in the refusal direction, not only the happy path: a warming controller never claims revocation complete, and a zero-row disconnect stays incomplete until grace expiry.
- The desktop test count moved from 314 to 313 and is fully accounted for: four tests were deleted alongside the menubar machinery they covered, and three were added, including one pinning that the key bridge serves the retired chords off macOS.
- Both new browser checks were proven to fail against the pre-change behavior and pass after. Check 99 was run before the fix and recorded next and previous staying on side A and the empty-side close leaving side A visible; the same command passed after.
- The replacement coalescing assertion was proven to still detect the defect by disabling coalescing and rebuilding the bundle, which produced 512 rendered updates against a cap of 130, then restoring and re-running green at 102 against a cap of 112.
- The self-write module ran 50 consecutive times under a parallel web build with zero failures.

## Retrospective

**Highlights.** The gateway control plane arrived with its adversarial direction tested rather than only its happy path, which is the harder half and the one that matters for a revocation contract. The rotation fix landed as a genuine root-cause change: dropping one null guard made both the empty-side and stale-id paths enter the combined order, rather than special-casing the symptom. The coalescing work is the clearest example of measurement beating intuition in this cycle.

**Lowlights.** A shared worktree cost more than it saved. The staging race, the stranded peer message, and the need to freeze both lanes before a trustworthy gate all trace to two writers in one tree. Separate worktrees per lane would have removed the class. The host also interrupted a lane mid-troubleshooting over a constant that the lane's own plan already scheduled for restoration, which cost a turn and taught nothing.

**Honest feedback.** The brief for the coalescing fix specified an assertion that measurement showed could not work: a throttled upload emits progress at the same rate as the coalescing window, so no count-based separation exists, and a fixed ratio against the chunk count inverts under load. The lane measured, said so, and replaced the premise. That is the behavior the round wanted, and it is worth noting that the flawed instruction came from the reviewer rather than the implementer. Reviewer error is not rarer than implementer error, only less often recorded.

## Follow-ups

- Decide whether the ghostty-web pin can move off `0.4.0-next.20` to a stable release, and what the upgrade contract is. The pre-release pin is the remaining open question on that item.
- The gateway crate tests need `TEST_DATABASE_URL` and a live Postgres that `make pre-push` does not provide, so their evidence is single-sourced from the lane that ran them and is not reproduced by the release gate.
- The Wayland data-control clipboard path and the macOS and Windows clipboard branches carried forward from v0.78.0 remain compile-checked rather than exercised on their platforms.
- `window.__chanTransferApplies` ships in the production bundle as a diagnostic the application never reads. Gating it behind a flag set by the smoke harness before the bundle initializes would remove it from production sessions without a second bundle.
- Give each lane its own worktree in the next round.
