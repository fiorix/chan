# Release v0.110.0

Shipped 2026-10-25 as the one GA commit on `0.110.0-ga` over `b2dbbf270`, the tip of `main`: six merge commits over the round's base `4e4ba6987`, which is the v0.109.0 GA commit `53873f50e` with two documents commits above it (`840c4f594`, the v0.109.0 publication record, and `4e4ba6987`, raising four v0.110.0 rows). Each merge brings one lane branch, one commit each, in the order the lanes were accepted: `v0110/nfhome` `4e6fbbe82`, `v0110/lnopen` `0e88dd430`, `v0110/eofpek` `ddc1af71b`, `v0110/xdcard` `50771fbcc`, `v0110/lrnttl` `79034aba0` and `v0110/dsknam` `1c53fd127`. The version closes all six rows of its roadmap, the two the owner raised during v0.109.0's cut and the four raised the day after, with none carried and no release candidate.

The version was built by a four-seat team launched on 2026-10-24 at about 22:48Z: a lead seat (Claude Fable, three sessions) for dispatch, the review of every range, the full gate at every tip, the scratch merge, the merge report and the cut; a workspace-app seat (Codex Sol) for `nfhome` then `xdcard`; a server seat (Codex Astra) for `lnopen` then `dsknam`; and a test-repair seat (Codex Sol) for `eofpek` then `lrnttl`. The owner's words for the round: a small team delivering just these items, each landed on its own branch, without advancing the release, so the team could work as independently as possible. The round first closed with four lanes at 06:06Z on 2026-10-25; on the owner's word at 07:35Z it reopened for the two remaining rows, and the owner's word of 12:2xZ merged the six branches into `main` and cut the release.

## What shipped

- `nfhome`, The launcher's New file in a standalone window creates at the filesystem root: a standalone window's New file starts at the user's home directory instead of `/`, through the file browser, the path prompt and the command palette alike, with the created file selected in the tree. Landed as `4e6fbbe82`.
- `xdcard`, An Excalidraw tab opens an empty Outline, offers a style toolbar and has no Details in a standalone window: editor cards are scoped to the tabs that support them by the owner's two decisions, Details lifted for every editor tab in a standalone window and Outline for document-kind tabs only, so a diagram tab opens with neither an empty Outline nor a style toolbar and shows its Details where a file has them; the manual's editor page says so. Landed as `50771fbcc`.
- `lnopen`, The launcher's Open refuses a path outside the workspace that `cs open` routes: the HTTP route and the control socket share one routing function, so a launcher Open of a path outside the workspace goes to the standalone host as `cs open` does, answering the window it opened in and a transient status in the workspace app; a hostless serve refuses with the guidance `cs open` prints. Landed as `0e88dd430`.
- `eofpek`, The whole-body disconnect test peeks for EOF before the server has read the terminating chunk: the chan-server test proves transport EOF after the stand-in parser has consumed the body's final chunk, through a harness lookahead and two forced orders pinned without a sleep; the macOS arm that was red at the base is green at the tip. A test-only change. Landed as `ddc1af71b`.
- `lrnttl`, Renaming a terminal window in the launcher leaves the desktop window's title unchanged: the window registry's change forwarder arms its first waiter before it starts, so a caption written before the forwarder's first poll still reaches the desktop watcher; a chan-library pin owns the order and a desktop pin covers the caption-only reconcile. The owner's single occurrence is not reproduced by that order; both rename paths read correct at the base. Landed as `79034aba0`.
- `dsknam`, chan-desktop has a setting for its client session name: `client_session_name` in the desktop config, empty by default, presented on every event-socket connection, so a named desktop appears under that name in `cs session list` after connecting and after a server restart; `cs session self --name` and `--reset` keep precedence for the server process's life, and an invalid name is refused with the command's exact sentence as a transient status while the connection stays usable. Landed as `1c53fd127`.

## Team and process

One round, two phases. Each row was a lane on its own branch forked from the base, never from another lane; the lead reviewed every design, reading and range in its own worktree and guest, ran the full gate (`make pre-push`, `make test-symlink-tmpdir`, `make check-windows-test-target`) at every tip in the integration guest, froze and pushed each accepted branch under its own name, and dispatched `ci.yml` once at each tip. A scratch merge of the accepted branches on `v0110/int` was gated again with the whole browser suite, and the merge report named the round's two conflicts with their constructed resolutions: the two web lanes appending a `describe` block at the end of `surfaceCommands.test.ts`, and lnopen's and dsknam's bullets opening the chan-server design's list at the same line. The merges into `main` reproduced those resolutions and the resulting tree is byte-equal to the gated scratch tip `dc14df107`. Every seat ran its builds, tests and browser runs in its own sdme guest from a team-owned btrfs pool, under explicit CPU, memory and disk caps, with every job bounded inside the guest and every count recorded beside the host's cgroup readings.

## Retrospective

Highlights: six rows landed on six independent branches by three worker seats in about fourteen hours, each range read whole by the lead against its rulings and gated at its tip, with a scratch merge proving the branches together before any merge into `main`; the reopen for the two remaining rows cost the same discipline and no shortcut; the two merge conflicts were foreseen by dry runs and resolved by construction rather than around the markers.

Lowlights: the server seat's Codex session compacted twice inside long wrapper outputs during dsknam's verification, each time preserved by a hashed patch and a restart; the host's survey overlay went unanswered three times in nine-minute bounds while the window read alive, so the pushes waited for a moment the owner was at the window; the lead's first marker-based resolution of the web lanes' conflict was caught by the merge gate before the constructed one replaced it.

Honest feedback: the brief kept the merge and the cut out of the round and the owner expected them at the end; a round that ends in a release should say so in its brief, so the lead prepares the cut's inputs while the last lanes build instead of after the owner asks.
