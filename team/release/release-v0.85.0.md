# release-v0.85.0

v0.85.0 is the large-transfer release. The 50 MiB compiled-in write limit is gone, every transfer path runs on a process-wide admission lane that never draws from the threads serving editor saves and terminal spawns, and a client past the queue bound is refused before its body is read. Around that: chan-desktop opens and focuses library windows natively, standalone terminals honour the full terminal preference set, Hybrid Nav splits panes with the mouse, the file browser and inspector share one action source, and ghostty stops erasing the last columns it draws over.

It was delivered by a six-member team on one shared branch and one worktree, across two rounds. The second round was opened by owner acceptance, which passed five surfaces and failed one; that failure turned out not to be a defect at all. 79 commits on the v0.84.1 ancestry.

## What shipped

**Large transfers are bounded by the server rather than by the browser.** Binary workspace writes were refused above a compiled-in 50 MiB `BYTES_WRITE_LIMIT`; that constant is removed rather than left beside its replacement, and the effective ceiling is `[transfer] max_bytes` in the registry, captured once when the library opens and reported to clients as one value so no caller keeps an independent copy. Workspace and terminal downloads, workspace and terminal uploads, directory archives, and the copy batch all run on a process-wide admission lane with two dedicated worker threads. Two transfers run at once and thirty-two more may wait; the request past that bound is refused with HTTP 503 and `Retry-After: 1` before any body is read, which is not a transfer failure because nothing was read or written. A move is deliberately not admitted: a rename plus a link-rewrite walk waiting behind two multi-gigabyte downloads inverts what the lane is for. The browser no longer counts slots, holds a queue, or promotes work; it starts what the user asked for and renders the rank the server assigns.

**Terminal downloads are bounded by that ceiling too, and the exact shape of the bound is the interesting part.** The terminal download arm read to EOF against no bound, while the desktop client documented a server refusal that did not exist on that route and a browser download carried no cap at all. A file whose open handle exceeds the ceiling is now refused with 413 before any header is sent, in a message naming both the size and the bound. The reader also counts bytes as they stream and fails the body if the file grows past the ceiling after the plan measured it, because otherwise appending to a file is enough to serve past the bound. It fails rather than ending cleanly, since a stream that simply stops is indistinguishable from a complete transfer. The response still declares no `Content-Length`: a ceiling is a maximum rather than a count, so a file may still grow freely below it. Growth *above* the ceiling now fails; growth below it is unchanged; a shrink is still not an error, because nothing was promised.

**chan-desktop opens and focuses library windows natively.** Two capability-gated commands mint a native-origin window record and raise an existing one, replacing a flow that depended on `window.open` and therefore did nothing in a desktop window. Both resolve the target library from the invoking window's own label, so a window reaches only its own library, and the workspace id is resolved to a path on the desktop side rather than accepted from the page. Hiding and closing another window depended on the same handle and are fixed with it. Browser tabs keep `window.open` unchanged. This is the repair v0.84.1 investigated, attempted, reverted, and deferred.

**A gateway-served page explains a withheld native command instead of quoting Tauri at the user.** The SPA decided whether to call a native command by asking whether it was inside a Tauri webview, which is not the same question as whether the installed app grants that command. A local window cannot tell the two apart, because chan-desktop embeds the bundle it serves; a gateway-served window is delivered by the remote devserver while the ACL gating its invokes belongs to the locally installed app, so the two are independently versioned. Both native call sites now classify a rejection as the app withholding the command or as the command running and failing, and report them differently. The version cause is named as likely rather than certain, because a release build collapses every rejection shape into one string.

**Standalone terminals honour the full terminal preference set.** A standalone terminal loaded its shell without ever fetching preferences, and a live configuration change was routed through a refresh path that returns early for terminal-only windows, so every preference read fell back to a default. Both boundaries are fixed together, since fixing either alone leaves the other broken. The effect is wider than appearance: the same source drives scrollback, mouse capture, secret masking, the font chain, and the terminal backend, so a standalone terminal now renders whichever backend the setting selects rather than always xterm.js.

**Hybrid Nav splits panes with the mouse.** Dragging a pane divides each target into edge zones plus a centre; an allowed edge previews the half that will receive the grabbed pane's content, and mouseup stages a 50/50 split in the draft. An edge is refused rather than downgraded when either resulting pane would fall below 240 by 160 pixels, and the gate measures the panes that would result, subtracting the chrome a nested split costs. Mouseup revalidates the target bounds, so an edge armed before the pane shrank cannot land.

**The file browser context menu and the inspector share one action source.** A capability-driven classifier decides which non-destructive actions apply to a path from its kind and the caller's capabilities, and both surfaces render what it returns, so a video reached by right-click now has the view and download entries the inspector always had. They cannot drift apart by construction rather than by convention.

**Ghostty stops erasing the last columns it draws over.** The reported symptom was that ghostty left xterm's scrollbar gutter reserved. It was not a reserved gutter and no arrangement of the fitter could have fixed it: ghostty-web's overlay scrollbar clears and background-fills a 14 CSS px strip at the right edge of its own canvas on every frame it draws, ahead of its own opacity and scrollback checks, so the columns beneath it are erased just after they render and stay erased until something marks those rows dirty. The strip is anchored to the canvas rather than the host, and upstream's own gutter reservation does not protect upstream's last columns either. chan now paints the same translucent track and thumb straight onto the content and forces a full row repaint on the frames that paint the overlay, because a translucent thumb composited over its own previous alpha converges on an opaque bar, which is the reported symptom again in a different colour. The hit region that claimed clicks across that strip is gated on the scrollbar actually being visible, since the fix turns dead pixels into content people will click.

**Ghostty viewport handling is stable under streaming output.** Ghostty writes and macOS pixel-wheel input route through one viewport controller: anchored output preserves its relative position, bottom-follow stays at the live edge, and a trim or clear clamps the viewport.

**Selected settings pills no longer switch their outer border to blue.** Checkbox and radio pills keep their shape, spacing, neutral border, and selected background, and are distinguished by that background alone. A radio pill's selected dot and focus ring come from the native input and are unaffected.

**`cs terminal list` shows queue depth.** The markdown table gains a `queue` column reporting the logical messages still waiting in each session's write queue. A session whose server does not report the value renders `-` rather than `0`, so "not reported" stays distinct from "nothing pending".

## What did not ship

**The gateway acceptance failure was not a defect, and nothing was shipped to fix it.** Owner acceptance failed on a gateway-served window refusing `create_library_window`. The desktop lane refuted every candidate boundary in the capability, ACL, and origin-matching layer, could not find a defect, and declined to ship a plausible correction. The cause was version skew: the test ran a previously installed bundle whose ACL predates the command, against a devserver serving the new SPA. The owner's rerun with both ends rebuilt and the fresh bundle launched explicitly confirmed it from the live system. What this release carries from that investigation is two pins, two roadmap registrations, and the withheld-command message above.

**Three ceiling refinements are deferred to v0.86.0**, stated as behaviour rather than as labels: a ranged request is charged by source size rather than transferred length; an archive of a tree larger than the ceiling is bounded by lane admission and concurrency but not by `max_bytes`, and streams to completion; and `doc_sessions/recovery.rs` keeps the older, smaller constant if the ceiling rises without it. The archive gap is the least fail-safe of the three and its wording was not softened.

**Shrink detection on the terminal download is not delivered and is not implied by the ceiling.** The roadmap framed the open question as shrink detection against live growth; the owner ruled a configured ceiling, which is a different axis and buys no shrink detection. It stays open on its own merits.

**The workspace download arm is deliberately not capped on read.** It declares a length from the file's own size and consults no ceiling. Bounding it would refuse a user a file already sitting in their own workspace, which fails toward denying them their data rather than toward safety.

**AUR publication is suspended.** The 2026-06-12 Active AUR malicious packages incident remains the newest AUR item with no resolution announcement, and its restrictions explicitly include pushing package updates, so the plan's AUR Release Checkpoint fired: the three AUR jobs are disabled by condition, templates and local validation untouched, every other downstream target unaffected.

## Process

The round ran on `v0850-base` in a dedicated worktree with six members on one shared branch: a lead plus five lanes (transfer, desktop, terminal, layout, inspect). No worker branches, no cherry-pick trees, one file editable by one member at a time under explicit grants recorded before the edit.

**The round's material starting condition was a loss.** The v0.84.0 round ended with uncommitted admission and runtime work destroyed. The plan required it be reconstructed against the preserved bus record rather than reported as already complete, with every piece of evidence re-earned. It was, including one correction to the contract itself: the record claimed each standalone serve path allocates a lane, and the transfer lane checked the real topology instead of the sentence and found one allocation per process kind.

**The session host died twice.** Both losses took every member's PTY at once. The first cost the round its sessions; the second also left three files of uncommitted lane work on disk, written by sessions that kept running after losing their terminals and so could not report, ask, or be corrected. That WIP was inherited rather than resumed: each lane verified it against its predecessor's recorded design intent before adopting, and stated in its journal whether it adopted, partially adopted, or rebuilt. One lane's implementation survived complete while the evidence its packet required had never been started, which is the shape that would have shipped as done if the code had been taken at face value. The owner's standing rule from that incident, that systemd fdstore testing runs inside a container and never against the host devserver, is now in the e2e docs and the agent playbook.

**Owner acceptance reopened the round.** Five surfaces passed and one failed, and the reopened round ran the plan's failure path: ground the finding, correct it, re-gate in full, push a newly verified SHA. Two owner rulings arrived with it, one overriding a plan line, and both are recorded as decisions rather than absorbed as drift.

**The release was cut by the lead agent under an explicit owner authorization**, no RC cycle, with the host holding the checkpoints and the hard constraint that nothing reaches `main` until the `publish=false` dry runs are green.

## Verification

- The full canonical gate ran green on the first candidate `6e4537e4` in an isolated gate worktree, and again on the second candidate `bea87a2d` after the reopened round. Both were first-attempt greens with zero reds, so the standing three-flake allowance was never used. The second gate: cargo 2886 tests across 33 targets, launcher 315 in 41 files, workspace-app 3572 in 360 files, both devserver smokes PASS including the AppImage bundle.
- Each candidate's push re-ran the whole gate inside the pre-push hook and reproduced its numbers exactly, so both shipped SHAs carried two independent full-gate passes.
- The gate verdict was taken from the log and the exit status independently rather than from either alone. On the second candidate a failure-marker grep returned 44 hits against an exit status of 0; all 44 were test names containing the word "failed" or `0 failed` result lines, and they were checked rather than dismissed on the strength of the exit code.
- 360 of 360 web test files ran on both gates, so the three documented nondeterministic editor tests ran and passed rather than being skipped past.
- The branch was synchronised onto the v0.84.1 GA ancestry twice, each time with a rehearsal on a throwaway branch first and a range-diff showing every commit identical.
- Push verification is update-aware. The first push created the ref, where a failure reads as an empty result. The second could not use that check: the ref existed, so a push that never landed would return a well-formed, plausible SHA at exit 0, making failure and success the same shape. The procedure was amended before it mattered: record the pre-push value, compare the post-push value by string against the new SHA, and treat a return of the pre-push value as a failed push.
- The three fixed-output Nix hashes were re-harvested against the bumped tree in a disposable Ubuntu sdme guest, each replacement taken from its own field's mismatch error rather than carried forward, and the GA commit's own `ci.yml` run is the authority on them.
- `make windows-cross-check` was green on the release tree, and the `publish=false` `release.yml` dispatch exercised the macOS sign and notarize path plus the Tauri updater signing. The platform chains were confirmed to fan out in parallel off `context` rather than serialising macOS behind Linux.
- Both `publish-downstream` dry runs were green without publishing, one building all four Docker images cache-only and one building and smoking `chan-desktop` on both Linux architectures.
- One unexplained test failure stands from the first round: `routes::storage::tests::handler_reset_restores_busy_cell_and_succeeds_after_holder_drops` failed once and did not reproduce across eleven controlled runs on both ancestries. It is recorded as unexplained rather than reclassified as a flake, and it did not recur in either gate.

## Retrospective

The unifying finding of this release is a check that keeps passing after the reason it exists has stopped being true. It appeared in six distinct forms, and no amount of running more checks would have caught any of them.

Two code comments asserted behaviour the system did not have and survived two full green gates, because no test asserts that a comment describes the system. One of them had been rewritten that same morning by the person reviewing that exact file for a writing-rule violation: the archaeology rule and the truth of the claim are different checks, and passing the first says nothing about the second. The same false claim then turned out to have a third copy in the release-facing changelog. An assertion in the download path stayed *true* after the ceiling landed while no longer describing the design, which is worse than false, because it keeps passing while leading a reader to conclude the path is unbounded. A source pin compared two string offsets where a missing needle returns `-1` and `-1` orders ahead of everything, so the pin passed when the thing it ordered against had vanished. Anchoring the needle then proved insufficient in the same file: the needle occurred four times, once as a definition and three times as string literals inside the sibling tests that split on it, so the anchor proved the needle was found and never that it was found in the right place. An anchored needle is not a unique needle; `expect` is a control over presence and nothing at all over identity.

The most expensive instance never reached the tree. The AUR suspension's guard is a constant-false condition on three jobs whose schedules are all `(dispatch clause) || (tag clause)`. Because `&&` binds tighter than `||`, the obvious `false && (A) || (B)` leaves the tag clause live: a job that reads as disabled and publishes on every GA release, during an incident whose restrictions explicitly forbid pushing. actionlint checks syntax and contexts rather than truth, the repository's own contract test asserts only that a substring is present, and `make workflow-check` passes. Nothing in the project would have caught it. It was avoided by extracting each condition, forcing every leaf true, and evaluating, with an unwrapped copy in the same table showing all three jobs schedulable.

The best-shaped work in the release is the investigation that shipped no fix. The desktop lane was handed an acceptance failure, refuted three candidate boundaries by construction and two of them again empirically, made its own control-flow refutation executable rather than leaving it as prose in a journal, and then declined to ship a plausible ACL change on top of a defect it could not find. Had it shipped one, the owner's rerun would have passed anyway, the change would have looked like the cause, and a correction nobody needed would have entered the release with an owner's confirmation attached to it. That failure mode is invisible when it happens, which is why the refusal is worth naming.

Two verification habits earned their keep and are worth carrying. A lane added the probe row for its own fix *before* believing the fix worked, and the row failed; added afterward as confirmation, it would have gone green against a broken fix. The same lane's positive control then caught a bug in its own checker, which had been evaluating a different job than the one it named and producing correct verdicts by luck of layout. What caught it was not care, it was having one case whose expected answer was the opposite of the others. Separately, the terminal lane read the minified `ghostty-web` bundle, built a plausible story from it, and then stopped and drove the real exported renderer against a recording context instead of trusting the reading. That is what turned "the geometry looks like it clears a band" into a measured `clearRect` at an exact offset, and it killed an entire class of proposed fixes including the one the plan implied.

### Honest feedback

The version-skew acceptance failure cost an owner acceptance cycle, an hour of lane time, and a reopened round, and nothing anyone did wrong caused it. The owner fetched and rebuilt both ends and tested. Both the old and the new build report the same version string, and launching from the Dock opens the previously installed bundle. The underlying property is worse than the incident: a delivery-round branch still carries the previous release's version pins, because pins bump at release cut, so **no pre-release build is ever distinguishable by version from the release it descends from**. That is a standing consequence of how this project cuts releases, it applies to every round, and it means the acceptance instruction "build both ends" is not verifiable by the person following it.

The lead's own record is the other honest item. Two of the six false-claim instances were the lead's, both from the same habit of carrying a particular thought's scope into a general sentence, which is false the moment a reader takes it generally, and a changelog reader always does. A pin anchor was fixed on the wrong property and would have been called done. Every one of those was found by a lane rather than by review, and none reached a shipped SHA, which is the system working; but the pattern is that the person integrating is the person least likely to re-read a sentence they have just improved.

## Follow-ups

- Three ceiling refinements are registered in `team/roadmap/v0.86.0/large-transfer-ceiling-refinements.md` in behavioural terms, with the archive gap named as the least fail-safe. Shrink detection on the terminal download stays open there as an owner decision, explicitly not settled by the ceiling ruling.
- `gateway-window-skew-presents-as-a-code-defect` registers runtime build identity and the desktop advertising its command vocabulary to a remotely-served page. The two halves are complements, not stages: an advertisement is itself a command needing its own ACL entry, so an app old enough to lack a command is old enough to lack the query that would report it missing, and for every such build interpreting the refusal is the only mechanism there will ever be.
- `source-pins-bound-on-sibling-string-literals` registers two distinct defects across four sites in `main.rs`: end-assertions that can never fire, and needle non-uniqueness. Its acceptance requires the fix be proven by reordering two definitions, because the obvious deleted-needle mutation passes against a fix that does not hold.
- `aur-publication-is-suspended` carries the restoration condition in checkable terms and names the guard job that must be deleted in the same commit that lifts it. The AUR has now been stale since v0.82.0.
- The editor flake item was corrected during this round: `fold` fails with a numeric range end rather than a null widget, because a time-budgeted parse did not reach its terminator and the range took its doc-end fallback. A deterministic fake for the first mermaid render would fix the other two and not touch it, so the acceptance now names a cause per mechanism. The fold shape is a production concern too: a range that means "I gave up looking" is indistinguishable from one that found the end.
- `make web-lock-check` runs `npm ci --dry-run --ignore-scripts`, which on npm 9.2.0 removes `node_modules` and leaves only `.package-lock.json`. That is registered as `web-lock-check-destroys-node-modules`, and it cost this round four halted lanes and an hour before the cause was found.
- The unexplained storage-test failure keeps its classification. If it recurs it is a finding, not a flake.
- Comments that make load-bearing claims about behaviour should be pinned by the test that covers the behaviour, or should not make the claim. Four instances in one release argue this is a class rather than a run of carelessness.
