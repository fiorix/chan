# Release v0.94.0

Status: GA 2026-08-19. No candidates. An integration round run by a single lead agent: three pre-built branches taken through intake (reviewed, gated, and validated on the merged tree, not reimplemented), three items raised and implemented inside the round, and a machine sweep that replaced the per-branch worktrees and containers with one release worktree and one provisioned container.

## What shipped

- **The CLI speaks noun families with a pinned serve/close elevation.** `chan workspace serve|close|forget` own the workspace lifecycle, top-level `serve` and `close` are the only elevated family verbs (pinned by `flat_workspace_subcommands_are_rejected`), and `chan devserver` holds the server-side verbs beside new client-side verbs (`register`, `ls`, `connect`, `disconnect`, `forget`) riding four additive handoff `Request` variants over the desktop socket. No aliases and no deprecation cycle; unit writers emit `devserver run` while the persisted-unit parsers keep accepting the old form, pinned by deliberately old-form fixtures. From `feat/cli-grammar` (83f4cf27), whose own gate went green in its container before the push; the round waited for that push rather than taking over the lane.

- **Drafts and Rich Prompt in drafts-capable standalone windows.** A per-library `chan_workspace::DraftStore` (`~/.chan/Drafts` on a desktop host, `~/.chan/devserver/Drafts` on a devserver) with a working flat trash, the capability advertised as `<meta name="chan-drafts">`, promotion through `MiniWorkspace::resolve_write_target`, and the companion repair that makes a discarded workspace draft a restorable trash entry. Workspace windows are byte-identical throughout. From `feat/mw-drafts` (d1ee7cf9), built and verified against the v0.93.0 GA base.

- **Gateway operator PAT mint and revoke through the app layer.** Identity gains an operator revoke route at parity with self-revoke (202, immediate tunnel and session cut), operator revokes audit as `revoked_via_admin`, operator mints default to expiring credentials with an explicit `never` opt-out, and the admin CLI accepts the 202 the server answers. From `fix/gateway-admin-mint` (4d4903c5); the prod-host wrapper lives in chan-prod-setup and its deploy steps remain the host's post-GA actions.

- **Extensions have a front door.** `docs/extensions.md` carries the design (declaration, handshake, capability-path proxy, sandbox), the eight-message host bridge table with directions read from the SPA source, an authoring walkthrough anchored on the in-tree echo fixture, and the `chan-ext-*` packaging convention the two published extensions independently converged on. A new README Guides section links it beside the previously orphaned configuration reference. In-round.

- **`/api/files` is removed on the release its deprecation named.** Both tenant route tables, the desktop native-transfer classifier, and the gateway transfer-policy classifier serve `/api/fs` only; the alias tests flipped into live 404 refusal pins and a mount-literal source pin keeps the alias out of the route table. In-round.

- **The tunnel namespace renames from `usr.{domain}` to `proxy.{domain}`.** 71 files and 337 substitutions across documentation, doc comments, test fixtures, and the shipped deployment values (`packaging/gateway/packaging/domain.env`, the kube probe hosts); five literal stems cover every variant, history keeps the names it shipped with, and there is no compatibility alias by ruling (one known deployment, cut over together with this release by the operator's separate chan-prod-setup rollout). In-round.

## Team and process

A solo round under the fabler discipline: one lead agent, with the cli-grammar lane's own agent still live at round start. That lane's gate went red once (`devserver_resilience`), the lane amended and re-gated green and pushed; the round polled the gate's status file read-only and never touched the lane.

The pre-round sweep removed the chan-cli, chan-gw, chan-mw-drafts, and devsrv-toolchain containers and their worktrees after verifying clean trees and pushed branches, keeping chan-hybrid-window and the `ubuntu` rootfs untouched. The planned warm-clone of the mw-drafts container failed: `sdme fs export` of a userns container produces a tree `fs import` rejects, and the staging copy was deleted on a piped false-green before the failure was read, which is the lead's error and exactly the pipeline-verdict trap the gate skill documents. The container was rebuilt from the `chan-ann-ubuntu` base and re-provisioned (postgres for the DB suites, Chrome for browser-smoke, npm 11 over the base's 9.2.0), costing wall-clock and nothing else.

Merges ran in the pre-verified order mw-drafts, gateway-admin-mint, cli-grammar, with conflicts exactly where a merge-tree simulation predicted and prose-only: the roadmap Active section (resolved to the table format, union of rows) and design.md (the drafts paragraph beside the serve-vocabulary paragraph). One real cross-branch skew surfaced and was fixed in-round: the mw-drafts browser check spawned `chan devserver` bare-verb, which the merged grammar hard-errors; it now spawns `devserver run`, and the merged smoke run proves the check green.

Platform and pipeline: `make windows-cross-check` green (rc=0, release-profile windows-gnu crate graph, run against the pinned 0.94.0 tree that becomes the GA commit); both `publish-downstream` dry dispatches green (docker run 32264353036, cachix run 32264355737); the `release.yml` publish=false dry run green (run 32264349987, publish-side jobs skipped by design). ## Retrospective

**Highlights.** The gate caught every class of fallout the round's sweeps could not see: dynamically-built URLs, mixed-case fixtures, formatter width, and a known-bad npm, each fixed as its own commit with the sha re-gated. The refusal direction was tested, not just the success: the alias removal landed with live 404 pins through both assembled routers, and the rename kept every adversarial fixture (the suffix-lookalike host, the case-folding parses) testing the property it existed for. Instruments were re-proven before being trusted: the mini-window-drafts check was known to fail against a binary without the drafts surface, the DB suites were confirmed discriminating by their own item's evidence, and the smoke echo red was reproduced to a one-check pass rather than waved through.

**Lowlights.** The round lost the warm container to a piped verdict and a deletion chained before the read, the exact failure mode this project's own gate skill documents; the cost was re-provisioning time and the lesson is recorded in the operator's memory and here. The round's first alias source pin was self-defeating (it failed on the refusal tests it shipped beside) and survived only one gate iteration, which is what the gate is for, but writing a pin that conflicts with its own companion tests is an unforced error. The gateway-test coverage assumption (that TEST_DATABASE_URL flips the DB suites on inside the gate) was stated as fact in the round plan and was wrong; the gate's green would have silently excluded the suites the round most needed had the NOT RUN line not been read.

**Honest feedback.** The gate-iterate loop was the round's most effective tool and its cheapest: five reds, five one-commit fixes, no red survived two iterations. The expensive mistakes were all verdict-handling, not code: a piped exit status, a deleted artifact, an unread contract line. The discipline that would have prevented all three is the same one sentence: take the verdict from the artifact, and read it before acting on it.

## Follow-ups

- The cli item's deferred remote workspace arms (`chan workspace serve|close|forget WS --devserver TARGET`) need an owner ruling on the flag-name collision with serve's local `--devserver` selector before implementation.
- The gateway item's deploy half is the host's: `make admin-install` the wrapper on the prod host, rotate the two live devserver PATs onto expiring credentials, and optionally point the wrapper's `revoke` at identity's parity route for the immediate cut.
- The `usr.{domain}` to `proxy.{domain}` live cutover is the host's chan-prod-setup rollout (nginx, DNS, certificates), planned together with this release.
- The build-container recipe should carry the e2e toolset (jq, GNU time) and an npm >= 10; the chan-ann-ubuntu base has neither and ships npm 9.2.0.
- The browser-smoke harness builds the echo-extension example only in full-build mode, so SMOKE_SKIP_BUILD runs against a fresh clone red the extension check for a missing binary; either the harness builds the example under skip-build or its docs name the second binary the mode requires.
- The baseline smoke run crashed in teardown on an rm -rf race ("Directory not empty") after all checks ran, losing results.json; the merged run did not reproduce it. Worth a look if it recurs.

- The twelve pre-existing browser-smoke reds carried from the v0.93.0-era baseline remain red and remain unclassified beyond being pre-existing; they are name-listed in the round data.
- The `/api/files` removal's external blast radius (saved links, third-party scripts) is accepted by the one-release alias window the v0.93.0 item granted; nothing beyond the repository was migrated by this round.
