# Release v0.95.0

Status: GA 2026-08-21. No candidates. The round folded two pre-built self-upgrade branches through intake, implemented the remote workspace arms the v0.94.0 grammar item had deferred, and ran the first structured close review since v0.89.0 over every commit since v0.94.0, landing its findings as fixes before the cut.

## What shipped

- **A workspace on a registered remote devserver is managed from the CLI.** `chan workspace serve|close|forget WS --on TARGET` (and the elevated `chan serve` / `chan close` through the same flattened args structs) reach a workspace on a registered, connected devserver through the desktop handoff: three additive request variants, desktop-side resolution of TARGET (URL or launcher label) and of WS (exact path, or a unique label or basename) with refusal over guessing, the devserver's own live-terminal refusal on close and forget, and `--on` distinct from `--devserver=<port|url>` with each flag refusing the other's value shape. In-round (95251732, f4feb42a, d75b76ef).
- **The Linux AppImage self-upgrades.** The updater arms compile for Linux gated on `$APPIMAGE`, the release jobs minisign each AppImage and publish the `.sig`, and the `/dl` collector decorates the AppImage records with `linux-x86_64` / `linux-aarch64` updater entries (optional for archived releases, required for the one being cut). From `feat/appimage-self-upgrade` (87d8c3ed), taken through intake.
- **The Windows install self-upgrades.** The companion `chan.exe` routes `chan upgrade` to the desktop, the desktop downloads and verifies the NSIS installer, drains, and hands it to the updater, which runs it passively and relaunches; the on-launch check stages the download and asks through the launcher dialog; the release job minisigns the installer and `/dl` gains `windows-x86_64`. From `feat/windows-self-upgrade` (2e607db7 + 02c0070d), taken through intake.
- **The chan tree speaks the cs prefix grammar.** Every subcommand-bearing node infers an unambiguous prefix and refuses an ambiguous one; in-round (bfdcaa13), with a behavioural walk pinning every node.
- **The AppImage CLI resolves relative paths in the caller's directory, and standalone transfers signal a clean path.** The shims export `CHAN_CALLER_PWD` and the desktop restores it at boot; the standalone `cs upload`/`cs download` legs normalize lexically (the review replaced the first cut's `canonicalize`, which renamed symlinked downloads). In-round (c77203f0, 3759cd8b, e5364e59).
- **Enter mid-way through a list item splits it, and never inside a fence.** In-round (ca7bfa1a, cbce5a83).
- **Windows paths drop the `\\?\` prefix wherever they are shown or keyed.** Eight sites plus a registry-load normalization; `chan ps` enriches devserver-served workspaces on Windows again. In-round (15eed252).
- **The release workflow's apt steps time out, retry, and fall back.** In-round (4c09cb0e, 94eba61a).

## The close review

Anchor: `v0.94.0` (3d959b43). Every commit since it was reviewed: the eleven that made up the candidate set and the round's own commits as they landed. No blocker was found. Findings accepted and fixed before the cut:

- The two desktop update drivers (the on-launch check and a handoff `chan upgrade`) could replace the same image at once, and a `chan upgrade` that launched the desktop always met that race; they serialize now, and a handoff that finds the on-launch install done relaunches instead of downloading again (f2e51b86).
- A Windows restart from the update dialog that landed while a quit was draining dropped the verified installer bytes silently; `begin_normal_shutdown` refuses visibly and the restart keeps the staged update (f2e51b86).
- The plugin exits the process after launching the NSIS installer, skipping the geometry capture and leaving no trace when Windows refuses to start it: the capture and an info line naming the staged installer's location run before the install (f2e51b86; the design doc names the recovery).
- A self-managed devserver daemon runs from the install's own `chan.exe`, which the installer cannot overwrite; both update drivers refuse until `chan devserver stop` (f2e51b86, 74711f20).
- An NSIS install in a user-chosen directory was classified as not an install and never self-upgraded; the installer-recorded `InstallLocation` joins the roots (e8e1ce05).
- A standalone window's `cs upload` on Windows failed at the desktop's native-upload validator, which refused any backslash; the SPA names the lane and the filesystem lane accepts an absolute path (e8e1ce05).
- The standalone transfer legs canonicalized, renaming a symlinked download after its target; they normalize lexically now, and a trailing `.` names the directory itself (e5364e59).
- The list split fired inside fenced code blocks; it defers to the fence helper (cbce5a83).
- `\\?\` leaked into Windows output at eight sites and `chan ps`'s devserver enrichment missed on Windows (15eed252).
- The apt fallback in `release.yml` rewrote files current runners do not use; it edits the mirror file they do (94eba61a).
- The browser-smoke `cs-paste` deny path depended on headless Chrome's prompt policy; it sets the permission to denied explicitly (ab810423).
- The collector silently dropped an updater platform when a payload shipped without its signature; it warns (0812a1a8).
- `chan upgrade` exited silently when a just-launched desktop was already current; it says so, and the Windows companion guard is pinned (74711f20).
- Pin strength: ambiguity refusals assert the clap kind, every subcommand node is walked for prefix inference, the shim export order and a stale template are pinned, the caller-cwd restore order is pinned, the verifier's `.sig` rule has a go-red smoke, the Windows upgrade handoff has a named-pipe round trip, the launcher update dialog has mounted tests (664db86e, e8e1ce05, e7b5e67b, 0812a1a8, 980aa42b).
- Docs: the CHANGELOG's self-upgrade entries contradicted each other and overstated the CLI's refusal; the chan design doc and the Linux contributing doc described the upgrade and AppImage paths inaccurately (c3c135b5, d75b76ef).

Findings recorded, not fixed in the round (follow-ups): a Windows desktop that stages an on-launch download keeps the bytes in memory for the session; the generator's `signature is required` and `duplicate updater platform` guards have no go-red smoke; the AppImage `.sig` staging line is exempt from the workflow lint (the dry-run artifact diff covers it); the Windows companion `chan.exe` does not launch the desktop for `chan serve` the way it does for `chan upgrade`; the `Signature:` parse arm in the sign steps is dead on tauri-cli 2.x (the `.sig` fallback is the working arm).

## Retrospective

**Highlights.** The remote workspace arms went from an accepted item to a shipped, end-to-end-proven feature inside the round, because almost every piece already existed: the devserver routes, the desktop's close/forget wrappers, the target resolver, and the handoff transport; the work was three additive wire variants, one missing desktop call, two pure resolvers, and the CLI surface. The close review paid for itself: no blocker, but a real race between the two AppImage update drivers (the branch's own e2e had run with the on-launch check disabled, so it never met it), a Windows restart that could drop a verified installer silently, an install-directory classification that excluded a class of Windows users from self-upgrade, a symlink-renaming canonicalize in a fix that shipped two days earlier, and a `\\?\` leak the owner half-remembered and the audit found at eight sites. Running the windows-gnu test binaries under wine64 turned "compiled, not run" into an executed named-pipe round trip.

**Lowlights.** The expensive mistakes were operational, not product: a `cd` dropped from a container command six times in a row (the rustup pin reads the cwd, so the symptom was a misleading "cargo-fmt is not installed"), a gate wrapper whose status file reported the last step rather than the first red, a browser-smoke provisioner defeated by Google's 403 on the current stable build, and wine aborting under `systemd-run` and under `TMPDIR=/var/tmp` for reasons that only mattered because the gate scripts kept both. Each was found by reading the log instead of the exit code, and each cost a relaunch. The fence guard's import edge broke a suite the scoped gates did not run; the full `web-check` caught it, which is the argument for running it before, not only at, the full gate.

**Honest feedback.** The round had one session and no lanes, which made the review cheap to coordinate and the gates slow to serialize; a second container for the release builds would have halved the wall-clock. The Windows self-upgrade ships with its acceptance unproven on real hardware; every check that can run off-Windows ran, and the first real run is the GA installer, which is a risk the owner accepted with open eyes.

## Follow-ups

- Run the NSIS passive reinstall and relaunch on a Windows 11 machine against the published GA installer (default and custom install directory), and record it in the self-upgrade item.
- A Windows desktop that stages an on-launch download keeps the bytes in memory for the session; park the `Update` handle and download on restart, or drop the bytes on dismiss.
- The generator's `signature is required` and `duplicate updater platform` guards have no go-red smoke; add two manifest cases.
- The Windows companion `chan.exe` launches the desktop for `chan upgrade` but not for `chan serve`; decide whether the serve handoff should launch it too (an effective-personality computed once in `run()`).
- The `Signature:` parse arm in the three sign steps is dead on tauri-cli 2.x; drop it or keep it with a comment, the `.sig` fallback is the working arm.
- The browser-smoke provisioner pins `chrome@stable`, which the chrome-for-testing bucket answered with 403 this round (as did 140); `CHROME_VERSION=138` worked. Either pin a known build or teach the provisioner to fall back.
- Wine in the build container aborts under `systemd-run` and under `TMPDIR=/var/tmp`; the gate scripts should run the wine steps directly with TMPDIR unset (recorded here so the next gate does not rediscover it).
- The owner-run e2e ladder beyond the remote-arms suite (`devserver-fdstore.sh`, `gateway-zone.sh`, `storm-check.sh`, `lp-skip-test.sh`) was not run this round; run it by judgment before the next release.

## Known gaps

- The NSIS passive reinstall and `/R` relaunch are unproven on a real Windows 11 machine; the release build and signing are the only proof, and the first real run is the GA installer.
- The macOS compile of the widened updater arms is proven only by the `publish=false` dry run.
- The desktop's Windows unit tests compile for windows-gnu but do not execute under wine here (the Tauri test binary does not start); the Windows CI arm runs them.
- The remote-arms e2e proves the loopback, scriptless, tokened shape; it cannot prove an ssh control-terminal connect, the gateway arm of the desktop's add-workspace call, or Windows named pipes.
- The four GUI e2e suites (WebKitGTK render, terminal pixels, animation fps, WebGL present stall) remain unmeasured on this host.
