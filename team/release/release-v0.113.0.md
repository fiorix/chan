# Release v0.113.0

Shipped 2026-10-27 as the one GA commit on `0.113.0-ga` over the base `e03537239`, the tip of `main` (the v0.112.0 publication record with the documents commits that raised and settled the version's six rows). Above the base stand three merge commits, one per lane branch, each forked from the base: `v0113/b-keys` at `0ac9ef639` (six commits, `329905bbe` through `0ac9ef639`), merged as `c3c345428`; `v0113/c-aptcrl` at `6ec9dc8eb` (two commits, `991e30890` and `6ec9dc8eb`), merged as `499a95748`; and `v0113/a-freebsd` at `9350cfd80` (five commits, `d8e26fef9` through `9350cfd80`), merged as `5cae025e5`. Over them, `403f07b34` keeps `Cargo.lock` on tao 0.37.1 and takes the FreeBSD desktop build out. The version ships five of its six rows and carries the FreeBSD desktop row into v0.114.0, with no release candidate, by the owner's words "we don't need rc, we can go straight to ga and tag fully automated".

The rows were raised on 2026-10-27, the day v0.112.0 shipped, and built the same day on the owner's word "organise 3 independent worktrees for 3 agents to work on ... they will build in parallel": one agent per lane in its own worktree, lane a on the two FreeBSD rows, lane b on the three keyboard and launcher rows, lane c on the release workflow's apt row. The owner tested lane b's native build on macOS against a Linux devserver before its branch was pushed. One session merged the branches and cut the GA, on the owner's words "the others you can start merging", "we also have the a-freebsd branch now, include it", and for FreeBSD, "freebsd is not the most important thing here, the other fixes are".

- `cmdtsr`, The Command launcher opens on five commands of the active tab and hides the rest until a scope is picked: by the owner's choice of the full contextual list, the root view lists every ranked contextual command and search lists every match, with the scope orbs and Computers branches on their existing paths; the design reference and two manual pages follow. Landed as `9ad386472` and `2c76066b7`.
- `lnkeys`, The launcher has no letter keys for its screens and its machine and workspace actions: `g` flips Computers and Gateways from the launcher App's handler, and the carousel presses the selected row's own `data-deck-key` button for `c`, `t`, `w` and `h`, outside text entry, forms, dialogs, command search, repeats and Cmd, Ctrl or Alt combinations. Landed as `ad18083d7`.
- `bsdfds`, A FreeBSD devserver runs out of descriptors watching a large workspace and stops answering: measured on a FreeBSD 15.1 guest (234,972 descriptors filled in ten seconds by notify 6.1.1's kqueue backend re-walking past a dangling symlink and leaking a descriptor per retry), then replaced on FreeBSD by chan's own kqueue backend under a process-wide descriptor budget, registered through the scope-filtered walk Linux uses, with `lstat` polling past the budget, a full release and `ProviderError` on a pass that runs out of room, and retries on every platform spaced from 250 ms to 30 s. Landed as `4c90706b5`.
- `aptcrl`, The release workflow's Linux deps step times out on a crawling apt mirror before its fallback runs: both dependency steps bound the first index update and download-only fetch to five minutes, then drop the Azure mirror, download again and install from the local cache, inside the step's 15-minute deadline. Landed as `991e30890`.

## Merge and review

The three branches touch disjoint files; `git merge-tree` read `v0113/b-keys` against `v0113/c-aptcrl` clean, and `v0113/a-freebsd` against `main` with both merged clean. Each range was read before its merge: lane b's workspace-app, launcher and desktop code, lane c's workflow steps, and lane a's commits and rows, with lane a's watcher rewrite also read by a separate review agent for Linux and macOS behaviour changes and the kqueue backend's descriptor accounting. The merges are `--no-ff`, as v0.112.0's were. The review found no change on Linux or macOS from the watcher rewrite other than the retry spacing, and every desktop `cfg` edit compiles the same code on Linux, macOS and Windows as before. It did find that the `Cargo.lock` move to tao 0.37.2, which FreeBSD needs, applies to every desktop platform: tao 0.37.2 rewrites its macOS view, including the key and IME input path (`keyDown`, `insertText`, `setMarkedText`), and changes four Linux X11 keycodes, so chan-desktop on macOS, Linux and Windows would have taken a tao change the lane read on macOS only through clippy and unit tests. The owner's answer was to keep tao 0.37.1 (see Carried). Its other findings are under Follow-ups.

## Retrospective

Highlights: six rows raised, built, accepted and merged within one day; three lanes in independent worktrees on disjoint files merged without a conflict; lane a measured the FreeBSD failure on a guest before designing the fix and took the owner's decisions by survey; lane b's rows were accepted by the owner on a native build before the merge.

Lowlights: two of the three lanes delivered with their final acceptance still open, lane c's Actions dispatch and full gate and lane a's real-session desktop readings and first workflow run, so the GA's own dispatches are those rows' first CI readings; chan-desktop's FreeBSD `cfg` changes had no Linux reading until the merge; and a lockfile edit described as two lines carried a dependency release that rewrites the macOS input path, found only at the GA's review, which cost the FreeBSD desktop row its release and the cut a second pass.

Honest feedback: a lane that changes shared platform code from a non-Linux host should name the Linux reading it lacks in its hand-back, as lane a did, and the merge should take that reading before anything else. A dependency bump made for one platform is a change on every platform the dependency serves; its hand-back should name what the new version changes there, read from the crate's diff.

## Follow-ups

- Every notify watcher left on FreeBSD (chan-server's `config_watch.rs`, its registry reload watcher and `standalone_watch.rs`, and chan-desktop's own) runs notify's kqueue backend, whose event loop panicked there (`kqueue-1.1.1/src/lib.rs:661`) and whose recursive re-adds can walk a whole tree; recorded in both FreeBSD rows for a follow-up row.
- tao 0.37.2 for every desktop platform, then the FreeBSD desktop build: read the macOS key and IME input path and the Linux X11 keycodes on native desktops, then restore the build steps and the workflow's desktop check; the carried row holds the lane's FreeBSD readings, the real X11 and Wayland session readings and the 900 px page width seen under Xvfb.
- The `tauri-plugin-updater` FreeBSD build gaps are drafted for tauri-apps in the desktop row and not filed.
- The apt row's constructed slow-mirror dispatch on Actions was not run; a crawl on a real release run is its next reading.
- The manual screenshots `command-launcher-terminal.png` and `command-launcher-workspace.png` predate the full opening list; regeneration was not requested.
- On FreeBSD the descriptor budget is shared by every watcher in the process, but only the watcher that needs room can give up its own files' descriptors, so in a devserver whose first workspace fills the budget with files a later workspace's root finds no room and stays Degraded, retrying every 30 s (`watch_kqueue.rs`, read, not reproduced).
- After a provider loss the watcher keeps a retry deadline already backed off to 30 s, and a retry that succeeds after a failed registration reports nothing for the consumer to reconcile, so a tree that recovers can sit unwatched for up to 30 s, against 250 ms before, with the changes in that window unreconciled (`watch.rs`; on Linux this needs a persistent registration failure, read, not reproduced). Resetting the spacing on a provider loss and emitting one provider error on recovery closes both.
- On FreeBSD a file or directory deleted and recreated under the same name between two listing diffs, with its inode number reused, reads as unchanged and keeps a descriptor on the dead vnode (read, not reproduced).
