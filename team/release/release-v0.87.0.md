# Release v0.87.0

GA 2026-08-09. Nine roadmap items delivered and ten deferred, from a round chartered to fix three. The release's defining result is that its smallest item, a single flaky test, turned out to be a production data-loss path that three releases had worked around without naming.

## What shipped

- **The mtime CAS verifies the disk instead of trusting it.** `write_text_if_unchanged` compared only mtimes, so an external editor writing inside a non-advancing timestamp window was read as no conflict and its edit silently overwritten. The CAS now takes the bytes the caller last observed and verifies them; an unreadable disk is a conflict rather than a write. The read half is the same collision seen from the other side, where the scene reconcile settled a hand edit as chan's own flush echo. `DurableBaseline` carries `verbatim` so a canonical rendering never claims to be the file. Four limitations are named rather than papered over, including echo drift, where the window stays open exactly as before.
- **The flaky test that found it.** `flush_cas_conflict_enters_conflicted_after_corroboration` was filed as a test defect. Its mechanism is a filesystem timestamp that does not reliably advance between two writes to the same path, present with no load at all; load is only an amplifier. The lane closed a v0.82.0 follow-up that two releases had left as an unproven mechanism, and produced a deterministic reproducer: 3 of 3 at `main` under a 1-CPU cgroup cap with 32 test threads.
- **A watcher-requested reconcile has a driver.** Writing `.gitignore` in a served workspace parked it in `recovering` permanently, behind a boot overlay that never dismissed, escapable only by an out-of-band rebuild call. `refresh_repository_scope` parked a pending pass and notified nobody while its sibling `set_excluded_dirs` had the coordinator call one file away. Diagnosed live on the owner's devserver, triggered by an ordinary `.gitignore` edit during unrelated housekeeping.
- **Desktop authorization lands on the profile page.** The browser ended on a hardcoded loopback page reading "You can close this tab", off the gateway origin, with no sign the user was signed in. The loopback response for an active flow now redirects to the slot origin's profile page. The neutrality invariant holds: a callback with no active slot keeps today's byte-identical neutral 200, and the no-3xx ruling is amended to say it binds the confirm response specifically.
- **A devserver build is identifiable at runtime.** `chan --version` and the health surface carry a build id, the server-side sibling of the desktop identity shipped in v0.86.0. The trap it exists for fired again during this release's own validation, when a `chan open` silently attached a test workspace to a 19-hour-old devserver running the previous release.
- **`--submit` names the chord instead of only requesting one.** The agent named in `cs terminal write --submit` was discarded and the server's spawn-command sniff substituted, so a session spawned as a shell whose operator then started an agent inside it was unpokeable for life, refused with exit 69 by a server claiming certainty it did not have. The caller is now authoritative and the derivation reports disagreement without overriding it. One case regresses narrowly and deliberately: a submitted broadcast to a mixed-agent group encodes one chord for all of them.
- **The command launcher lists scopes completely and windows as targets.** Choosing a scope stops being a five-row teaser, the focused application's own commands lead its Tab scope, four actions the menu trim had left unreachable are commands again, and one Windows branch replaces the Focus/Hide/Show/Close quartet.
- **Flip card back faces are gated on the turn.** WebKitGTK ignores `backface-visibility` on every element while Chrome honours it, so a hidden face that relied on that property covered the entire window in the shipped app while rendering correctly under every Chrome-driven check. Carried its own WebKitGTK render harness rather than another Chrome check, since the Chrome suite cannot see this class at all.
- **The chan-server timing classification**, partially. All 49 sleep call sites in 18 files are classified with per-site justification, 28 production-legitimate, 10 test-repaired, 11 test-bounded-and-kept, 0 defect-registered, verified by set comparison of the live grep against the committed table rather than by counting rows. Workstream 2, repairing the named tests, is partial and the item says so: one repaired, one classified but untouched, one not reachable by the audit at all because it carries no sleep.

## Process

One round, four file-disjoint lanes plus a lead, spawned into a 3x2 pane grid so the host terminal kept a pane. A fifth lane was added mid-round for the recovery stall after it was diagnosed live, and a sixth workstream, the timing sweep, was sequenced after the delivery lanes landed rather than beside them, because three of the four held files in the same crate. The `--submit` contract change was implemented host-side outside the lane structure and entered as an intake rather than a task.

Scope grew from six items to nineteen during the window. Every growth was registered as an item with evidence before any of it was built, and the owner ruled on each addition; nothing was improvised into the round. The lead escalated the one decision it judged above its authority, a suite-wide sweep versus a fourth round of point fixes, rather than filing it unilaterally.

## Amended after GA: the tag moved, and what verified it

Recorded here rather than left to the git log, because the tag does not point at the commit this report was written in.

The GA commit `479c102e` was tagged and its release run **failed** at `macOS desktop package`. `build-dmg.sh` died on a missing `target/dmg-venv/bin/pip` with exit 127. The venv is cached with `target/`, the dry run had created it fresh and passed, and the tagged run restored a broken one; `python3 -m venv` over an existing `pyvenv.cfg` reuses the directory and skips `ensurepip`, so `bin/pip` was never recreated. Nothing had published: no release, no `/dl` move, no downstream package. `73a33b9c` clears the venv before creating it and turns a missing `ensurepip` into a named error, the tag was deleted and re-pushed there, and the second GA run published. The class this exposed, that a dry run on identical source can take a different path from the tagged run, is registered as [release-dry-run-does-not-predict-the-tagged-run](../roadmap/v0.88.0/release-dry-run-does-not-predict-the-tagged-run.md).

Verified before each tag rather than after:

- On `479c102e`: `release.yml` publish=false green with its artifacts downloaded and inspected (the musl binary reporting `0.87.0 (build git-479c102e2471)`, a real DMG, a 421-byte updater signature), `ci.yml` green including `Nix chan-desktop`, both `publish-downstream` dry dispatches green with docker building four images and cachix building and smoking both Linux arches, `make pre-push` green on the GA tree, and `make windows-cross-check` green.
- On `73a33b9c`: `ci.yml` green including `Nix chan-desktop`, and a fresh `publish=false` dry run green through `Build, sign, and notarize` and `Verify signature and stapled notarization`, the two steps the failed run never reached. Both re-established on the new commit rather than inherited, since the fix sits inside the tree Nix builds from.
- A full local `NIX_PACKAGE=all` run with zero hash mismatches and `chan-desktop`'s `vendor.drv` built, so both derivations sharing one `cargoHash` is observed rather than assumed.

The published release carries 20 assets, and `chan.app/dl/cli/latest.json` moved to `0.87.0`.

## Retrospective

Highlights: a test-flake item became a production data-loss fix, and the same investigation found three engineers had each worked around the identical collision in three files across three releases without registering it. The recovery stall was diagnosed against a live devserver, root-caused to a wired-versus-unwired sibling pair, and recovered in place without restarting the process. The sweep's acceptance was verified by set comparison rather than a count, which catches the two failures a total cannot.

Lowlights: the browser smokes covering the editor convergence path had never run, in a round hardening that exact path, because no container the project builds in carries browser dependencies and the gate does not invoke them. Four releases and eighteen commits touching one timestamp token had gone by. The suite also has a blind spot by construction, since Chrome honours a property WebKitGTK ignores, so running it would not have been sufficient either.

Honest feedback: the acceptance bar this defect class had been certified against does not work. The chartered item asked for 20 consecutive isolated runs; the delivering lane measured 400 consecutive isolated runs green on the unfixed code. A criterion that produces confident green on a known-broken tree is worse than none. Anyone writing acceptance for a load-sensitive defect after this should state why their bar would have caught this one. The same shape recurred twice more in miniature: a mutation probe that reverted the `--submit` decision left both ack-wording tests green, and only the delivered-bytes assertions caught it; and the integrator's own readings went wrong four times by reporting a partial view as a whole one, including a truncated `head -3` that was read as data loss during the owner's live test.
