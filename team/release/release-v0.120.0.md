# Release v0.120.0

Shipped 2026-11-01 from `0.120.0-ga`: the release commit (the pins, lockfiles, hashes, specs and documents) over the round's integration branch `v0120/int`, which carries the v0.119.0 record from `main`, eleven accepted lane ranges (over eight lane branches, seven roadmap rows) merged one by one after the lead's review of each, and the lead's roadmap commits; no release candidate by the owner's word of 2026-11-01 ("Straight to GA"). The round was a four-seat team on one host: a Claude lead that reviewed every range and ran every gate, and three Codex seats on the terminal, the editor, and the launcher and keys, each in its own worktree with its own test server.

The scope was the six rows opened during the v0.119.0 cut (the review's minor ghostty defects, the Computers keys, Hybrid Nav's stage keys with Cmd+` on macOS, the date badge, the nested hash and the URL click), plus the owner's addition of the round: tmux panes resized from chan.

## What shipped

- `v0120review`, Ghostty defects the v0.119.0 review left open: thirteen of the sixteen findings fixed in four stage commits on one lane (`eee284c03`, `0b7086ec0`, `7ef78f7d9`, `57d6fc512`), each finding with a test or a build check red before its fix: the write buffer's allocation order, the long grapheme clusters, the wasm compile-failure cache, ghostty-web's inline wasm stripped from the bundle (the lazy chunk from 648,962 to 83,687 bytes), one focus report per transition, the dropped XTVERSION reply, chan's own kitty answer with the core's dropped, the in-band resize report with real pixel sizes, a non-text key after a dead key, browser-inserted text through the host, and the Windows dead-key and AltGr chords modelled in Chrome. Finding 8 closed as the Option rule, finding 10 closed as a core defect with an upstream report drafted for the owner, finding 13 moved to v0.121.0. Findings 7 and 9 are not verified on Windows; finding 5's macOS sources and finding 12's old WebKit are not measured.
- `datestop`, A date followed by a full stop shows no badge in the editor (`6c570659a`): the trailing boundary admits a sentence-ending dot run; file names and versions stay plain.
- `listhash`, A hash at the start of a list item or a quote styles the line as a heading (`e7f50a09f`): the decoration skips a heading inside a list item or a block quote and an empty `#` run; HTML and slides keep CommonMark.
- `urlclick`, A click on a URL in the editor opens it instead of editing the link (`287286777`): a primary press places the caret at the target's end and opens the picker with one OPEN row and a copy button; a modifier press opens at once.
- `navkeys`, Hybrid Nav's stage keys miss their mnemonics, and Cmd+` does not switch chan windows on macOS (`4dfcdb2c3`): `f` and `e` stage a File Browser and an Excalidraw diagram. The Cmd+` half waits for the owner's macOS reading (the round's check `mac/check-1-navkeys.md`), not received by the cut; it is carried into v0.121.0 as `cmdbq`.
- `onoffkeys`, The Computers keys turn no workspace on or off and open no terminal in a workspace (`c050c3b02`): `o` is the launcher's on and off key on the Computers and Gateways screens (a devserver's connect and disconnect, a tmux connection's detach, a workspace's power button with its live-terminals confirmation, a gateway's connect, disconnect and cancel) and `c` acts nowhere; `t` on a ready workspace row opens one window of it with one terminal tab, on this machine and on a connected devserver, through an optional terminal-start intent carried by the window mint and record, forwarded over the desktop bridge, translated to a launch parameter by both URL builders and consumed once by the workspace app's bootstrap when no layout is saved.
- `machname`, ghostty finding 3, one by-name machine lookup in the command launcher: a plain window, a tmux window and a workspace target of one library are named by the same row: the local card claims its own library first, then the first devserver by name claims each other library (`devserverForLibrary` in the launcher's machine tree, used by the three lookups alike), so a devserver registered directly and again through a gateway roster names its windows once, and a devserver row that resolves to this machine's library leaves a local tmux run on This machine (`805eab91f`).
- `tmuxresize`, A tmux window's panes cannot be resized from chan: the divider between two panes of a tmux window now resizes tmux's panes: a drag previews the ratio locally and sends one `resize-pane` for the pane on the border's first side at release, Hybrid Nav's committed resizes send the same request per changed split, and chan then shows the layout tmux returns; the request rides the existing tmux request family (`Command::ResizePane` in chan-tmux, `TmuxRequest::ResizePane` and `request_resize_pane` in chan-library, no new route). A divider whose border no first-side pane reaches (a same-axis split nested under a perpendicular one) refuses the drag and is the v0.121.0 `tmuxnest` item (`acbd534c9`).

## Merge and review

Every range was reviewed by the lead in its own worktree before acceptance: the diff whole, the new tests replayed red on the code before the change and green at the tip, the seat's mutations read, `make web-check` (and the Rust trio where a lane touched a crate) run at the committed sha, and the browser checks the row's behaviour lives in run alone at the tip and at the base (94 for the terminal stages, 123 for Hybrid Nav, the seats' own drivers for the editor rows replayed by the lead). No range returned for a code finding; three were amended before acceptance for stale tests or fixtures a change exposed. Each accepted lane was frozen, pushed under its own name, and merged into `v0120/int` with `--no-ff` in the order of acceptance; every merge was clean but the last, where machname's new paragraph in the launcher's design document sat beside onoffkeys' rewording of the paragraph after it, resolved by the lead by keeping both (the ledger's merge record 9). ## Retrospective

Highlights: eleven ranges reviewed and merged in under four hours with no code finding returned; every hand-back carried a red-first test run, mutations and a real-surface reading the lead replayed in its own worktree; the gates chained their push and `ci.yml` dispatch, so no pushed tip waited on the lead. Lowlights: two parallel `gh run watch` pollers drew GitHub's pace limit at 02:51Z and every run read and dispatch failed for thirteen minutes (the rule since: one read per run per minute, never `gh run watch`); the sdme contract step failed its first attempt inside two full gates with the stub's `unsupported fs call` and passed on retry (drafted for the owner); the lead's first real-tmux reading failed before any reading because the seat's driver expects a tmux session the seat had created by hand, which its hand-back did not say. Honest feedback: the Codex seats' sandbox refused every git write and `systemd-run` at its first submission and passed each unchanged on the second, a turn lost per write that a round rule should name up front; the macOS and Windows readings asked for at the start had not arrived by the cut, so findings 7 and 9 ship on Chrome-probe readings alone and the Cmd+` half of navkeys is carried.
