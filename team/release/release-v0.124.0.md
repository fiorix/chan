# Release v0.124.0

Shipped 2026-11-05 from `0.124.0-ga`: a no-rc release by the owner's decision of 2026-11-05, the release commit (the pins, lockfiles, both Nix hashes, the Fedora specs and these documents) on the round's integration branch `v0124/int` at `e11926729`. That branch holds seventeen `--no-ff` merges of verified tips from fourteen branches over `main` at `720b543c0`, a fifteenth branch, the pane centre drop, arriving through the menus branch, and nine commits made on the branch itself. Fifteen roadmap rows shipped, written at the cut; none was withdrawn or carried. The owner builds and tests the release commit on a Mac before its proofs run.

The round opened on 2026-11-04 as a first candidate for five branches the owner had built that day in other sessions: the in-process WireGuard client with the macOS floor it needs, the auto-hiding pane strip, the command launcher's focus return, the ghostty repaint after an off-screen window and the gateway admin help's token leak, over `main`, which already held the Computers launcher's keyboard fix `720b543c0`. It grew as the branch was integrated and tested: a reading of the WireGuard branch found its desktop resolving each endpoint once inside a blocking start, which the owner had rebuilt before it shipped; the Windows guest found the CLI needing the Visual C++ runtime; an order-dependent browser check exposed group broadcast that could not be turned off; a stale-check repair found Escape not closing a terminal's menu; and the owner added the pane centre drop, the Commands rows in the pane and terminal menus, and the gateway identity's empty OAuth pairs seen on devsrv.io.

## What shipped

- `wgclient`, chan reaches a gateway behind WireGuard only through a VPN client on the host: chan-wireguard runs one WireGuard peer and a smoltcp stack in the process, the protocol core boringtun 0.7.1's `noise` module owned under BSD-3-Clause; `chan devserver run --tunnel-wireguard FILE` dials the tunnel through it, so the tunnel ingress may be an `http://` address inside the tunnel; chan-desktop names a wg-quick file per gateway and sends that gateway's HTTP clients, window feed and webviews through one loopback proxy that routes by AllowedIPs; the gateway builds without the crate. Endpoint lookups never hold up start-up: a name is looked up on each handshake initiation with the host resolver, a known endpoint's initiation leaves at once, an answer moves the endpoint only when none is known or the handshake is older than 135 s, and a fresh session's changed answer gets one probe initiation while the data stays on the peer's authenticated source. Proven against kernel WireGuard from Linux, FreeBSD and Windows and through WebKitGTK and WebView2 (`e0e88872c` to `1f897bed0`; `f6098a49c` to `957e5ba97`, merged as `c7e0f963f`; `6dd0ecb09`, `805339f2f`, `58f090a66`, `e11926729`; the documents `770ac34aa`, `0a0259a5f`, `2d8df9c89`, `ddc250c43`).
- `macfloor`, chan-desktop needs macOS 14 for its webview proxy and its updater checks no floor: the floor is 14.0, the release metadata carries each release's floor, and the desktop refuses an update its macOS cannot open, naming both versions; the install page, the manual and the desktop README state the minimum. A v0.123.0 desktop on macOS 11 to 13 has no guard and updates itself into this release; shipped as is by the owner's decision, with the warning in the CHANGELOG (`d5ce4fbd1`, `08b233b87`).
- `vcrt`, the Windows `chan.exe` does not start without the Visual C++ runtime: a shipped bug; `crates/chan/build.rs` links the VC runtime statically with `static_vcruntime`, the Universal C runtime staying dynamic, and both release workflows refuse a `chan.exe` that imports a VCRUNTIME or MSVCP library (`edebd4d10`, the Nix re-pin `a949adbe1`).
- `stripauto`, a pane's tab strip shows over a lone tab with nothing to switch to: `pane_strip_auto_hide`, off by default, draws a side's strip only while it holds two or more tabs, per side, with Hybrid Nav's staged rows keeping it (`8682ef861`, `d6134752c`, `ceef3ebd1`, `be917f444`; check cleanup `5d045a0a8`, `bc44c56cd`).
- `centredrop`, a pane under a hidden strip has nowhere to drop a tab or a file: every pane's body has edge bands that split for a tab of the same window and a centre that takes a drop as the strip does, the whole body for another window's tab, a Files row or an empty pane; a Files row over an editor still types its path; a Files row allows copy as well as move, which Chrome refused before (`bf913da01`, `3fe245f16`, `dbcc97520`, `3b6a066d9`, `061258772`, `399bf0c6d`, `84a21c38d`).
- `ctxcmds`, the pane and terminal menus offer no way to the command launcher: the strip's empty stretch and an empty side's body open chan's pane menu with Commands, Reload and, on the desktop, Open Inspector and their chords; a terminal's menu ends with Commands (`e5752c5ef`, `9291d0a3f`, `db60cca05`, `3e3761186`, `93a6f1cdd`).
- `lnchreload`, a shown Computers launcher goes deaf when its host page reloads or opens a terminal: nothing in the host page takes the keyboard under a shown launcher, and the launcher reclaims it on window focus and on a host page load (`720b543c0`, already on `main`).
- `runfocus`, a command launcher run that opens nothing leaves the terminal deaf: a run that took no focus hands it back once it settles, a dialog a command opens returns focus to the launcher's origin, both refused under a survey or the Computers launcher (`672533478`, `18197e02c`, `ffd1a1463`, `0180b4cd8`; the desktop test `d1e98d764` and the check's own group `e6a7ea258`).
- `ghblank`, a ghostty terminal comes back blank after its window sits off-screen: every host-resume path forces a full render pass of the ghostty renderer (`3018f76cb`, check renumbered to 204 by `a4b4b0427`).
- `bcastoff`, group broadcast cannot be turned off while a member sits in a window no page holds: the roster says whether a page holds each window (`window_live`), is pushed again when such a window connects or disconnects, and the SPA leaves those members out of the toggle, the label and the count (`55210c511`, `9040f8ab5`, `1427fe50c`, `15b2d75fd`, `99de0e322`).
- `menuesc`, Escape does not close a terminal's right-click menu: a terminal's and an editor's menus take Escape in the window's capture phase, so the shell reads no ESC and the editor keeps its selection (`81c2b438c`, `f315ce65a`, `e3211cdc3`).
- `oauthpair`, the gateway identity counts an empty OAuth pair as a configured provider: a provider registers only when both halves are non-empty after trimming, a half pair refuses to start naming the empty variable, and the packaged `identity.env` stops setting the six variables (`c6d34dca0`, `8bfca252d`, `d439c50d0`, `2a4c1c912`, `10d200309`, `3633e28d1`).
- `admhelp`, the gateway admin help prints the admin tokens it read from the environment: `hide_env_values` on the three token arguments, pinned by a test over the built binary (`4987e655a`).
- `stalechecks`, browser checks 60, 125 and 134 test what the product no longer does: 60 dropped with its feature, 125 presses the Rich Prompt chord its menu labels and runs its devserver through the suite's helper, 134 expects the URL's end; the editor design's lost caret sentence restored (`f25081f52`, `a714bd980`, `07ca1f8cb`, `8e5bb6124`).
- `smokeguard`, the browser suite starts its devservers beside the user's own: the runner exits 2 before it starts anything when `XDG_RUNTIME_DIR` is unset or the user's own (`fcd946cef`, `96d71d989`).

## Retrospective

Highlights: the WireGuard client went from its first commit to interoperating with kernel WireGuard from three operating systems, and through WebKitGTK and WebView2, in two days, and its endpoint handling was rebuilt before it shipped; testing the integration branch in guests found three shipped bugs (the VC runtime, the stuck broadcast, Escape over a terminal's menu) and each shipped fixed with tests red before the change and a check in a guest; every merge kept its branch's evidence on an ancestor sha, so a later fix merged in again without a rebase; the endpoint resolution's review was settled by probes and a mutation runner rather than by argument. Lowlights: CI went red on a desktop test that reads a web source file, which a branch whose gate ran only the web checks never ran, and the fail-fast jobs then skipped every test binary after it; a check cleanup that swallowed its own error made check 203 depend on order and cost a diagnosis, though that diagnosis found the broadcast bug; check 206 broke on a helper signature another branch had changed, which only the whole suite saw; the first endpoint resolution change let a failing resolver kill a live tunnel, which only an independent review caught, and the change took three reviews and nineteen commits; two whole browser suites and a Codex seat's checks ran on the host beside the owner's devserver before his rule; the host's `/tmp` sat near full and swapped under parallel builds, which pushed one check over its memory limit. Honest feedback: the roadmap table tracked nothing this round; its fifteen rows were written at the cut from the lead's notes, and the Active table's next cells never moved. Nothing was read on macOS before this commit although the release moves the macOS floor and changes focus behaviour WKWebView may not share; the owner's reading of the release commit is the first. The floor's guard ships with the floor, so a v0.123.0 Mac below 14 updates into an app that will not open, mitigated only by the release notes, by the owner's decision. No run reached a real chan gateway behind WireGuard. The whole browser suite last ran before the last six merges, which were read in packs.
