# release-v0.83.3

v0.83.3 is a patch release with two themes: the retired command-launcher overlay leaves the tree end to end, and the wall-clock timing tests stop failing under host load. v0.83.2 was skipped: its shortcut work was superseded by the overlay removal before it shipped.

## What shipped

**The command-launcher overlay is deleted end to end.** v0.83.0 shipped without the desktop-owned overlay window, but the tree kept its Tauri host, eight Tauri commands, the `command-launcher` capability, five permission blocks, the `?command=1` overlay mode and source-submission protocol in both SPAs, and the native key bridge's chord claims, so the bridge kept routing Cmd+K / Cmd+Shift+K to the dead window on desktop while every other trigger opened the inline deck. The whole path is gone: the host and its commands, the capability and permission sets, the overlay mode and protocol, and the chord claims. The SPA keymap now owns the launcher chords identically on every surface, which is also what the parked v0.83.2 shortcut fix wanted; that line is closed rather than merged. The transparent window was the only `macOSPrivateApi` consumer, so the flag and the Cargo feature leave with it, and the Mac App Store blocker the original ADR recorded no longer applies to the launcher.

ADR 0001 is amended to the model this leaves standing: one shared command deck rendered inline inside the invoking page on every surface, two authority hosts, and no native launcher window. The desktop's aggregate Computers authority moves to a stateless broker IPC (catalog snapshot plus named, revalidated actions; no bearer, token, or per-window state crossing into any page), which is the next launcher item; the browser keeps the shipped scoped-capability model. The design docs (`desktop/design.md`, the launcher and workspace-app design notes) describe the inline-only reality.

**Wall-clock timing tests are load-proof.** `tenant::tests::one_deadline_aborts_and_joins_every_stuck_task` measured `elapsed < grace * 3` against a 100 ms grace and went red at 390 ms on a host at load 20 while passing 12 of 12 in isolation; it now runs on `#[tokio::test(start_paused = true)]` and measures with `tokio::time::Instant`, so the deadline fires at precisely 100 ms of virtual time on any host and a grace-multiplication regression still trips the bound at exactly 400 ms virtual. `indexer::tests::trigger_during_active_rebuild_forces_one_follow_up_generation` required a follow-up rebuild to start within 750 ms of release and failed the pre-push gate twice in a row on a busy machine; that test drives real rebuild work on blocking threads, so instead of a paused clock all five waits on the coordinator's rebuild pipeline across both recovery tests ride one named 30 s `CONVERGENCE_BUDGET` sized for rebuild work on a contended host. The cooldown floor stays (tokio timers do not fire early, so it cannot flake), and a genuinely swallowed generation still fails with `mid-rebuild generation was swallowed`. The audit called for by the item found `devserver_resilience.rs` (12 s exit budget) and `index/facade.rs` (30 s smoke) already asserting properties with slack, so both were left alone.

## Process

Two branches, `v083/drop-launcher-overlay` and `v083/timing-test-virtual-clock`, each fully gated and pushed, then merged to `main` as `4b8c78fd`. The pre-push gate rouletted twice on the indexer flake before the fix existed, and passed first try with it in place. The merged `main` push went with `--no-verify` at the owner's call (both branches individually gated green, disjoint diffs) so CI would start immediately. The release commit regenerates the three lockfiles, keeps every version pin in lockstep, and re-pins the Nix fixed-output hashes in an sdme `nixos/nix` container on the release host (Nix is not installed locally).

## Retrospective

The gate roulette was the trigger for taking the timing fix the same day instead of deferring it to the v0.84.0 virtual-clock item: a gate that reds without a defect teaches everyone to bypass it, which is how real regressions get through. The first widening (750 ms to 5 s) was not the whole fix, and only the logged 40-run under load showed it; one more unlogged green batch would have shipped a smaller flake. A docs edit botched by an inverted old/new string was caught by re-reading the file after the edit, which is what the separate verification pass is for.
