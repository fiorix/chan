# Release v0.119.0

Shipped 2026-10-31 from `0.119.0-ga`: the release commit (the pins, lockfiles, hashes, specs and documents) over the round's two merged branches, its roadmap commit and seven fixes, one from the lead's merge read and six from its review, with no release candidate by the owner's word of 2026-10-31 ("no rc, straight to ga because ive already tested all of it"). The branch was opened on 2026-10-31 over `main` at the v0.118.0 publication record.

The round took the two branches the owner's agents had left unmerged at the v0.118.0 publication ("these remote branches unmerged are the ones"): `v0119/ghostty-keys`, which carries `v0119/ghostty-vt-wasm`, with the ghostty core switch, the idle-keys repair and the key parity, all built and checked on macOS by the owner the same day; and `v0119/tmux-card-devserver-title`, the launcher's devserver tmux card title. At the owner's word ("do an adversarial review") three reviewers then read the ghostty binding, the key path and the terminal tab with the launcher change. They found nothing that fails on a US-layout Mac, which is what had been tested, and two regressions it could not show: on Linux and Windows an AltGr or dead-key character was lost or swallowed the next key, and on a non-US Mac layout Option no longer typed `@`, `[` or `|`. Those, three smaller binding defects and the Library card's unguarded session read were fixed on the branch, each with a test red before it, and the minor findings went to a v0.120.0 item.

## What shipped

- `ghvt`, A ghostty terminal runs a patched Ghostty snapshot and keeps one page of scrollback: a ghostty terminal runs Ghostty's own signed release build of libghostty-vt (`tip` at `ae0dc1b71`, pinned by hash with its minisign signature and MIT license under `web/packages/workspace-app/vendor/ghostty-vt/`) behind ghostty-web's renderer, input and selection, through `ghosttyVt.ts`, a binding of the upstream C API to the object ghostty-web's `Terminal` takes; scrollback holds the line count the setting maps to instead of one page (`bab8b0eba`). From the review: the binding answers no OSC 4, 10, 11 or 12 color query, as ghostty-web's build never did and chan's xterm.js path does not (`0660097e8`); a grapheme cluster longer than the scratch area is read into its own buffer, and a change to the default colors or the palette redraws every row (`34abc34f2`); the OSC 21 query of kitty's color protocol is dropped too (`e53a4aeb8`).
- `ghidle`, A ghostty terminal stops taking keys after idle: on a window focus, page show, visibility change or wake, a ghostty terminal whose host holds the focus blurs it before refocusing, so the webview reattaches keyboard input (`0d632058d`). Confirmed on macOS by the owner for an app switch and a sleep and wake; the original intermittent failure over the gateway was never reproduced.
- `ghkeys`, A ghostty terminal sends different key bytes than an xterm.js terminal: a capture-phase listener sends what chan's xterm.js terminal sends for every keydown, through a port of xterm.js 6.0.0's key evaluator, and a stream parser follows the program's kitty keyboard and modifyOtherKeys requests (`fb2506378`). From the review: a key ghostty-web would type is its to type whatever a pending dead key or AltGr says, which ends the lost AltGr and dead-key characters on Linux and the swallowed next key on Windows (`a701b9bd3`); by the owner's decision ("ASCII types itself"), on macOS an Option character that is printable ASCII other than the space types itself, so a German or French layout types `@`, `[` and `|` again while a US layout keeps Option as Meta (`9b7b106fb`), and such a character ends a pending dead key (`f99ac6291`).
- `tmuxhost`, A devserver's tmux card says it runs on this machine: a `tmux -CC` run in a devserver's terminal is titled `tmux -CC on <devserver>`, and the lists of every machine's windows add the tmux session (`5b4334acc`); the card renders when its record arrives before tmux names the session (`52a75e155`).
- The manual credits Superlogical's Program Status Protocol specification for chan's OSC 7501 support (`7eb6e9596`) and drops an unmeasured speed word from its overview (`eb3cdb89d`).

## Retrospective

Highlights: a version whose code was already built and checked by its owner went through a review that asked for evidence, and the review found what the owner's machine could not show: a US-layout Mac is the one keyboard on which the key parity had no regression. Every fix came with a test that was red first, and the Chrome probe turned a modelled event sequence into bytes on a page.

Lowlights: the key parity row was built as "send what xterm.js sends", and xterm.js's keypress path, which delivers AltGr and dead-key text, has no counterpart in ghostty-web while its host holds the focus; the item's evidence covered every key in a US list and no other layout. The lead's first scoped gate on the merged tip ran the browser suite's Node tests without their dependency sync and read red until rerun through its Makefile target.

Honest feedback: a key path change needs a non-US layout and an AltGr sequence in its evidence, on every platform it ships to, before it is called built. A parity port is a contract with the original's whole input path, not only its encoder.
