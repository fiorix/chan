# Release v0.127.0

Shipped 2026-11-10 from `0.127.0-ga`: the release commit (the pins moved from `0.126.0` to 0.127.0 in the ten manifests, the three lockfiles regenerated, both Nix hashes harvested, the Fedora specs, the rows moved to `done/`, the CHANGELOG section, the release index line and this record) on the round's integration branch `v0127/int` over its final tip `65fe07378`: the gated tip `e10d622a4`, a documents commit, the Metrics slide's centering and its row. No release candidate was cut: the owner released from the integration branch, as v0.126.0 did, on his word of 2026-11-09 ("if these all work (including the Window menu fixes), and no items pending any decision, we should mark this as ga v127"), confirmed on 2026-11-10 after his Mac checks ("we're good to ga from my tests") with the cut and the tag left to the lead ("if all green you can ga then tag").

The release opened on 2026-11-08 with the five items the owner moved out of v0.126.0, a sixth found while reading the documents drift, and the wake-visibility row carried at the v0.126.0 cut. On 2026-11-09 he added live process metrics, built directly with an agent, and the ghostty terminals' move to libghostty-vt 1.0.0 with find, and moved the two largest rows, the per-node WireGuard ingress and the system CA store, to v0.128.0. On 2026-11-10 he pulled the tmux title bar in from v0.128.0, added the pane tree's window name, which he had built with an agent, raised the macOS Window menu's stale sections from his Mac, fixed the same day, and ruled the single-instance desktop into the release when a `tmux -CC` window that opened twice turned out to be two desktop processes. His Mac checks that day raised three more (the tmux pane names, the Computers label on a tmux window, the upload row), and before the GA he asked for a second reading of everything merged. He then closed the release to new work ("no more new features at this point, just close off the current in-flight items and the rest moves to v128"), closed the wake-visibility row without its reading, and after his last Mac checks pulled one more fix in before the cut, the Metrics slide's place in a wide window ("do include dashboard fix"). Sixteen rows: fifteen shipped and one closed without a change.

The round had one seat, the integration lead, and no standing team: the lead (Claude Opus, then Claude Fable after a recycle the owner asked for on 2026-11-10, handed over through a written handoff) ran each build, review and fix through an agent in a worktree of its own, read each result against the code, merged, gated and pushed. The owner built two rows himself with an agent (the metrics and the pane tree's window name), tested on his Mac, and ruled on every open question the same day it was put to him.

## Retrospective

Highlights: a second reading asked for on the day of the cut found twelve small defects and none that blocked the release, and every one was fixed with a test shown red and merged the same day, with the exact roles suite proven on both PostgreSQL majors before anything else moved; a check that could not fail (the roles suite, which CI had been running as a guard since its merge) was found by a reader and shown by a run at the base before it was fixed; the owner's two screenshots turned one reported bug into three fixes, one of them a macOS title race that no test on this host could have shown; the live tmux test run on a second tmux version caught a test that had been passing without testing its last step's subject.

Lowlights: the single-instance row's acceptance steps described a launch that never sends the request they were meant to check, written from the contract and not from the code path, and stood in the item until a reader followed the launch from `main`; int gate 1's symlink arm went red on a load-sensitive test and was attributed by reruns, not fixed; the session's usage limit stopped the documents agent mid-run, with its commits made and its gate and report still to come, which cost a resume; the lead's own slips (an apostrophe inside a parameter expansion in a cut script, a wait started as a shell job where a user unit belonged, a draft's "first" where the suite drifts its grants later), each caught by the next check.

Honest feedback: readers and fix agents on this host cannot run the desktop, so every macOS and Windows statement in this release rests on reading, on target-compiled lints and on the owner's hands; the brief's instruction to say what was run and what was only read is what kept those apart. A fix agent's "found nearby, not fixed" list was the most useful part of several reports: the Dock door, the desktop upload's local paths and the stale unit port all came from there.
