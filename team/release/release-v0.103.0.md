## What shipped

### Library, server and devserver

- A workspace removal claims the registry row it selected and only its unowned path aliases before closing, checks the selected mount's identity before changing it, and unregisters the captured row instead of looking one up by path again. Registration cannot pass a removal's claim in the same library, and an open rechecks its row under the writer lock before returning it. Claims belong to one library instance; other processes' registry edits remain outside them.
- A relinked mounted workspace is handed off through its registered row: a devserver handoff or row-on without a mounted record reuses the host runtime selected by its stored root and registry identity, and a captured runtime that closes while the call waits is refused. Recorded limit: an open by an alias of a relinked root answers `WorkspaceLocked` with a reason that misleads, outside the accepted contract.
- A restore attempt that ends without a mount removes its prepared overlay rows for a workspace removed while it was pending; stopping a devserver's restore closes no other caller's mount; a stopping devserver answers 503 to the window list and new feed requests instead of publishing a window set its shutdown shortened; devserver forget keeps a record when removal changed nothing.
- An overtaken `chan serve` handoff stops with a retry message and starts no standalone server, including when the selected devserver belongs to another library. Mixed versions keep their previous fallback.
- Launcher add and on save their on row while the mount's use stands, so a later removal clears that row instead of leaving an on row for a removed workspace.

### Workspace app and launcher

- A document's first live attach asks before replacing another writer's text: a clean tab takes the live text, a tab with conflicting local edits keeps them for Reload or Overwrite through the same session, and a classic save in flight finishes before a new session is acquired.
- A page returning to the foreground probes its event socket and replaces one that does not answer without waiting for the old close event, so a healthy return keeps its survey subscription.
- The File Browser reconciles its root after reconnect and broadcast lag, retries transient root-listing failures within five attempts, and on a confirmed missing root clears stale tree rows and marks open files missing while keeping their dirty text.
- A browser's Show no longer opens a second page for a desktop's window: by the owner's choice of 2026-10-06 (explicit browser Open, no remote native Focus), every scoped window row carries its origin, a browser deck's Show of a hidden desktop-held record posts visibility only, and both browser decks offer an explicit Open in this browser for such a row and Focus only for windows a browser opened. One Linux WebKitGTK run of the observed deck Show on a desktop built from the candidate was native-only, against the baseline's browser page and two holders.

### Desktop

- Repeated desktop handoffs to an unresponsive path share one registration permit: the blocking registration retains the permit after its caller times out, so later `chan serve` requests to the same path wait within their existing bound without starting another registration thread.

## Retrospective

- **Every observation is Linux WebKitGTK.** The round's native observations, the engine comparison, the restart arms and the hide seeds, ran on one engine on one box; macOS WKWebView and Windows WebView2 were not observed, and the round's code first ran on macOS in the candidate's CI run and its dry run, minutes apart.
- **A reader found what the gate did not, again.** Review refused the roadmap's disposition text twice for a count one short and a wording wider than its file, and read every wrapper before it ran; the lead's own mistakes of the day, a 63-character hash carried from a handoff, a heredoc whose backticks ran a path as a command, and timestamps written ahead of the clock, were each caught by a measurement or a reread and recorded.
- **One-attempt paths refuse first.** Seven instruments refused at their first execution, each on something a dry read had passed: a helper name collision, a never-formatted overlay, an unheld bound, `${10}` through `sdme exec`, an option-name clash, a stale worktree stamp in a shared target, a saturated trace buffer. Each repair was small; each cost a lock cycle and a review.
- **The hazard that was built for was not reached.** The restart-windows arms were built to catch a restart whose window feed omits the window; both restarts restored within a second and omitted nothing, so they prove the fixture and not the hazard. The delayed arms that would hold the restore open were designed and not run.
- **A GA commit was cut and held.** The first GA commit was complete, gated and accepted when its own CI run failed macOS twice; reading the failure as the runner's bad second would have carried a coin toss into the tagged run's validation job, and a measurement on Linux showed a plateau the suite had carried since before the round. The cost was one more candidate and its cycle; the lesson is that a burst of refused thread spawns is a shape of the suite to measure, not a runner to retry.
- **Partial dispositions were written as partial.** The browser-stalls and real-stop items end the round with what was measured and what was not, and no repair; the owner has the choice of the next instrument and of a client contract rather than a claim.
