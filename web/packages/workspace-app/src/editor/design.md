# chan editor (CM6) design

Load-bearing reference for the chan editor. Mirrors the workspace design doc's role for the editor surface.

## Model

The document text IS the markdown source. `view.state.doc.toString()` is the file on disk; there is no separate rendered tree and no serialization layer. The editor decorates the source in place (hide markers, render widgets) so it reads like rendered markdown while every character stays editable. This is the Live Preview model, the same architecture as Obsidian's.

Because the source is the single source of truth, the editor sidesteps a class of structural bugs a rendered-tree model is prone to: editing 1-char marks like `*a*`, flickering pending-mark heuristics, and markdown round-trip escape gymnastics. See "Why 1-char marks work" below.

## The contract (10 invariants)

1. **Doc invariant.** `view.state.doc.toString()` is the markdown source. Always. No transform layer. Autosave writes it directly.

2. **Token detection.** `syntaxTree(state).iterate({from, to, enter})` from `@codemirror/lang-markdown` + GFM, extended with three custom lezer extensions: `[[wikilink]]` (inline), YAML frontmatter (block-start, so headings inside `---...---` are not promoted), and a ref-aware link interceptor so `[label with [inner]](path)` still forms the outer link. Fenced code bodies parse with lazy-loaded per-language packs. Tokens that are not lezer nodes - `#tag`, `@@mention`, dates - are matched by regex in their own ViewPlugins, skipping code ranges.

3. **Decoration taxonomy.**
   - **Hide markers**: `Decoration.replace({})` over `*`, `**`, `~~`, `` ` ``, an external link's `[`, `](`, `)` and URL, an autolink's `<` and `>`, `# ` heading prefixes, ```` ``` ```` fences with the language text beside the opener, the whitespace around a list marker and after a task's `[ ]`, and a task item's bullet. Every other list marker is replaced by a marker widget rather than hidden (a `Decoration.replace({widget})` that is not atomic). Blockquote `>` and `---` rules are never hidden or replaced: `>` is the visual cue that a line is quoted (Obsidian convention), and replacing `---` with a rendered rule makes the markdown harder to edit.
   - **Inline marks**: `Decoration.mark({class})` over the *content* between markers - emphasis, strong, strike, inline-code, link-label.
   - **Line decorations**: heading levels (`cm-md-h1..6`), list lines, blockquote lines, fence opener/content/closer rows - CSS paints size, indent, borders, slab background.
   - **Atomic widgets**: `Decoration.replace({widget})` over the *whole* range - wikilink/internal-link pill, image, date pill, GFM table grid, mermaid diagram, page break. `EditorView.atomicRanges` registered for each so caret motion skips them in one keystroke. The task checkbox is a replace widget over just the `[ ]` / `[x]` marker (not atomic; the click toggles the source).

4. **Visibility rule (per token kind).**
   - **Marks** (bold/italic/strike/code/link markers): hide unless the active selection intersects the OUTER token range `[from, to]`. Equality at the boundary counts as intersection, and the outer-range rule (not per-marker) means a caret near `*a*` reveals both `*` together instead of `*a` then `a*`.
   - **Heading prefixes** (`# `): hide unless the caret line intersects the heading's line. Selection-intersect alone causes flicker as the caret crosses the prefix mid-line.
   - **Atom widgets**: each widget runs its own test. The wikilink pill, the date pill, the table grid and a diagram show unless a selection range touches the range they replace, its two ends included; on a touch the widget is suppressed and the source shows, so the user can edit it literally. An image tests the strict interior instead: a caret at either end of its source selects the image and keeps the widget, and only a caret inside the source, or a non-empty range overlapping it, enters edit mode, where the source shows beside a block preview. A page break shows its source while a selection range's lines overlap its line.
   - **Fences**: the ```` ``` ```` markers and the language text beside the opener are hidden unless a selection range's lines overlap the block's lines; an unclosed fence has no closing marker, so its block runs to the end of the parsed node. While revealed, the language text carries a mark, and the badge on the opener row shows the language either way.
   - **List markers**: no selection test, so they render the same with the caret on the item. A marker is replaced by a widget: `-` and an ordered number show their literal text, `*` and `+` show a glyph picked by nesting depth. The indentation before the marker and the whitespace after it are hidden. A task item's `[ ]` / `[x]` is replaced by the checkbox; its bullet is hidden, while an ordered task keeps its number in front of the checkbox.
   - **Always-visible markers** (`>`, `---`): never hidden. A quoted line gets a line decoration; `---` has no handler, so it shows as typed.

5. **Atom strategy (split by token type).** A widget dispatches a document change only into a view the user can edit, and `widgets/writable.ts` is the one predicate that answers it: read-only is spelled two ways, `EditorState.readOnly` for the prompt composer and the `EditorView.editable` facet for the document surfaces, and CodeMirror enforces neither against a programmatic dispatch. Selection and effect dispatches are not writes and do not consult it.
   - **Wikilinks (`[[note|alias#anchor]]` and `[label](path)` where `path` is internal)**: atomic pill widget. Pill kind (file / contact / image / broken) resolves via `GET /api/resolve-link`, cached per target. The cache is dropped whole, and every pill on screen asks again, when this window creates, moves, copies or deletes a path, when it hears a watch frame of a created, moved or deleted path, and when its watch socket opens again after a drop. A burst of frames shares its drops: one at the first frame, and one at the end of each 250 ms window a frame came inside. A target whose resolve failed with no answer waits its 5 s whatever drops come. A note that another window, or `cs open`, creates, moves or deletes through the server reaches this window as a watch frame that names its writer, and its drop is the one any such frame makes; the server keeps out of every socket's frames the echo of a write that named no window, which is a save of a file that exists, an attachment upload and a contacts import, so a pill that names a contact an import created elsewhere keeps its kind until one of those drops or a reload. Editing means caret-adjacent reveals raw text, OR click pill -> wiki bubble.
   - **External markdown links `[label](https://...)`**: `link` mark on the label. Unless a selection range touches the link's outer range, the markers (`[`, `](`, `)`) and the URL are hidden; a link with an empty label keeps its URL visible, marked as the link text. A range touching the link reveals the whole source, the URL dimmed, for editing in place.
   - **Naked URLs**: mark only, no hide.
   - **Tables**: read-only grid widget; click drops the caret at the source start, which reveals the pipe form for editing.
   - **Diagrams (mermaid, mermaid-to-excalidraw)**: a closed ```` ```mermaid ```` or ```` ```mermaid-to-excalidraw ```` fence renders as a diagram atom while the caret is outside; caret inside reveals source. A hover "View" button opens a fullscreen pan/zoom overlay, always on a light panel with a light render so a dark-theme diagram never vanishes on the dark backdrop. Both fences share one widget (`widgets/diagram.ts`, one decoration field per fence language with its own caches) over per-renderer render modules (`mermaid_render.ts`, `excalidraw_render.ts`); each library is dynamic-imported on first render.
   - **Tag `#word` / mention `@@{name}` pills**: mark-based (no replace), with click handling delegated through one content-DOM listener.

6. **Selection rule for ranges.** A non-empty selection has no reveal rule of its own. Each visibility test in invariant 4 runs over every range of the selection, so a token kind answers a range as it answers a caret: marks and external links reveal when a range touches the token's outer range, heading prefixes and fences when a range's lines overlap theirs, and an atom by its own widget's test. List markers, task checkboxes, `>` and `---` take no selection test and render the same under any selection.

7. **Bubbles** (`[[`, `![`, `@@`, `@`, `#`) open/close from `computeBubbleSpec`, which inspects the doc text around `state.selection.main.head` on every document or selection change via `bubbleListener`; the editor host mounts/reuses the bubble UI. Triggers also fire in "raw" mode when the caret sits inside an existing Link/Image URL slot or `[[...]]` body, so commit replaces the right range. Triggers never fire inside code ranges, and the reserved macro words (`@today`, `@date`, `@pagebreak`, `@break`) suppress the contact bubble. The bubble keymap intercepts before CM6's defaults via a high-precedence `keymap.of`. Bubbles must NOT call `view.focus()` mid-flow - the caret stays in the document and the popover runs alongside it.

8. **Find** uses one shared `scanMatches` pipeline. The `findField` and `FindAdapter` shape are shared by both Source and WYSIWYG modes.

9. **Fold** is a custom heading gutter over `@codemirror/language`'s fold state (`codeFolding`), folding the range a heading-aware computer returns. Heading detection has one source of truth: the lezer syntax tree. A line is a heading iff the tree resolves it to a non-empty `ATXHeading1..6` node, so a `#` inside a fenced block, a tilde fence, an indented fence, an inline code span, or frontmatter is never a heading; the gutter marker and the gutter click read `headingLevelAt`, and the click folds the range `headingFoldRange` returns. A heading folds end-of-line -> start of the next `ATXHeading{<=n}` line (or doc end); the forward scan runs to doc end so it forces the parse past the lazy viewport (`ensureSyntaxTree`). Three recorded decisions: indented ATX headings (up to three leading spaces, CommonMark) fold, matching the tree; an empty heading (a bare `#` with no text, which lezer still parses as `ATXHeading1`) does not fold, since it has no section under it; and Setext headings (`===` / `---` underlines) are out of the fold gutter. The chevron gutter is custom (headings only): `foldGutter()` would chevron every foldable block because lang-markdown marks paragraphs, quotes, and fences foldable too. The same tree-based code-node guard stops the block-formatting chords (`setBlockKind`, `toggleLinePrefix` in `commands/format.ts`) from rewriting a fenced `#` comment.

10. **Autosave** writes `view.state.doc.toString()` on `update.docChanged` to the bindable `value` prop. The echo guard prevents prop write-back from clobbering the caret, and the debounced autosave pipeline owns the server write. No serialize step. While a tab is attached to its doc session (`/api/doc/ws`), edits ride `@codemirror/collab` update logs (remote peers paint as cursors) and saves are flush confirmations; the debounced autosave + CAS `PUT` below is the fallback when the channel is unavailable. The write contract on `PUT /api/fs/<path>` is server-authority per path: a read of the path returns `authority_version` + `disk_conflicted`, and a changed-content write echoes the `authority_version` it last saw (alongside `expected_mtime_ns`). The server answers `428 PRECONDITION_REQUIRED` when that authority precondition is required but missing, and `409` on a version mismatch, carrying `current_authority_version` + `current_mtime_ns`. Both are the refusal envelope with the code `write_conflict`: the save path opens the conflict dialog on that code, and a 409 or 428 without it is a failed save. A watcher event for a non-self write flags a "changed on disk" banner instead of auto-reloading; once a session goes dirty/conflicted, the divergence is resolved explicitly via `POST /api/session-conflicts/resolve` with `{action: reload | overwrite}`. A debounced localStorage mirror keyed by path is kept for hang-recovery.

## Decoration pipeline

The decorations come from several providers, each with its own DecorationSet and its own recompute test, and CM6 merges the sets when it paints. The walker re-walks the viewport syntax tree on a document, viewport, selection or geometry change, or when the parser hands it a new tree; its registry yields the hide markers, the inline marks, the line decorations, and the list marker and checkbox widgets. The atomic widgets are not the walker's: the wikilink pill, the inline image and the date pill each come from a ViewPlugin, and the table, the diagram, the page break and the image's edit preview each from a StateField. The tag and mention plugins scan the viewport text and add marks.

## Why 1-char marks work

`*a*` is three real characters in the doc: `*`, `a`, `*`. The emphasis token's outer range is `[0, 3]`, with its `*` markers at `[0, 1]` and `[2, 3]`, and both markers get hide-decorations whenever no selection range touches `[0, 3]`, its two ends included. A caret at offset 1 (between `*` and `a`) is inside `[0, 3]`, so both markers reveal together, as they do at offsets 0, 2 and 3. No special case. Backspace deletes a real `*` character the user can see, and round-trip is the identity function. A rendered-tree model that represents `*a*` as a single marked node has no integer caret position satisfying `from < caret < to` when `to - from == 1`, which is the structural reason that model needs a per-pattern boundary patch and this one does not.

## Modes

The file editor host owns a per-tab mode: `wysiwyg` | `source` | `pretty` | `table` | `canvas`. Markdown (.md) pairs WYSIWYG with source; Excalidraw scenes open as the interactive canvas board; JSON opens as a collapsible tree and CSV/TSV as an editable grid, each with source as the toggle. Any other text-kind file (.txt included) is source-only - source IS the sensible surface for a .py / .toml / Makefile. Source mode highlights by extension via the same lazy language packs.

A drawing's canvas (`ExcalidrawCanvas.svelte`) writes the tab's buffer only from a seeded board. Seeded means the drawing library, past its own init, holds the whole buffer of a finished load as its init would restore it (the elements, the files, and the part of the appState its serializer keeps: the grid and the background; a file whose id the board already holds keeps its bytes), and the canvas holds the library's serialization of it as the baseline. An element after the first of a repeated id is restored under an id derived from the buffer (the id, a dash and its place among the repeats, counted past any id the scene holds), at the init and at every seed, so two seeds of one buffer and two windows on one file hold it under the same id; the library alone gives it a random id at each restore. The canvas seeds when the library first reports that its loading state has cleared, which is its init's own change, and after that whenever the tab's load finishes or its buffer changes without the board, as a reload, a conflict's resolution or a sibling pane's mirror does. Every seed puts the buffer on the board through the library's restore, whatever the board was built from, and takes the baseline in the same synchronous run, so no stroke lands between them; a stroke begun before the seed is replaced by it. The library shows an update's appState only at its next render, which for a seed made outside the library's own change comes in a later task, so the canvas keeps the appState a seed handed until the library shows it and lays it over what the library reports in every serialization, the baseline's and every flush's alike: a flush between the seed and that render publishes nothing. A handed key is dropped when the library shows another value for it than it showed when the key was handed, so a change the library reports first, as a click's or a key's own render does, leaves it handed. Until the library hands its API over, which its App's constructor does in the same synchronous commit in which the App mounts and reads its initial data, every render of the board carries the buffer as its initial data, so the App is built from the buffer whichever render it mounts with; that decides what the first frame shows, and nothing rests on it. The canvas publishes a serialization only while it is seeded and its tab is not loading, and only one that differs from the baseline or from the last it published, so a board nobody drew on writes nothing and never dirties its tab: neither the empty scene of a load in flight nor the library's rewrite of a file it did not write. The library marks an image whose file fails to decode after the load, a deleted image of that file too, in a copy one version on; a scene that differs from the baseline by such marks alone joins the baseline and is not published, and the mark reaches the buffer with the user's next edit. A live session is offered no image that differs from the authority's copy by that mark alone, at that flush or after any snapshot or update adopted since: an adopt carries the authority's older copy, which loses to the board's in the library's reconcile, and the canvas tests the board's copy against what the authority holds. The authority takes the mark with the user's next change to that image, and takes the image whole while it does not hold the copy the mark was set on. A load in flight unseeds the board, which keeps the drawing on screen in view mode until the load ends and seeds it again, and a tab reopened after a close during its load reads its file again. The library's order of events this rests on (the imperative API handed over before the init, the App built with the props of the render in effect when it mounts, the init replacing every element set before it, no change reported before it, an update's appState shown at the next render) is read from `@excalidraw/excalidraw` 0.18.1's source and was not run in a browser; `src/__tests__/excalidrawLibrary.ts` models it, and a test fails when the installed version is another. If the drawing library fails during a render, a React boundary clears the canvas API and seed, cancels the pending serialization and shows a loss and recovery alert; the failed canvas renders no new library board, and a Source-to-canvas switch or a tab reopen mounts one from the buffer. Its scene binding remains bound after failure, so a live frame arriving then is dropped at the canvas until a new mount binds and replays it.

A board writes the library's changes into its tab's buffer once 200 ms pass with no new one: the wait starts again at every change the library reports, so what waits is everything drawn since the last such pause. The flush the host registers for the tab in the tabs' store commits a change still waiting, and every way a drawing's tab or its window goes that runs page code runs it first, a forced close aside. A tab's own close, the close of a pane or of its tabs, a move to another window and a layout reconcile commit it before they read the buffer, so it counts as any unsaved edit does. The control client's `cs pane close-tab`, `cs pane close` and `cs pane close-all` commit it before they ask each tab whether it has unsaved changes, so a stroke inside the wait blocks the close with unsaved changes and the command closes nothing; the same command closes the tab once an autosave, or on a live board the push's ack, has come. With `--force` they commit nothing and close at once, and each releases a live board's scene session before its tab goes, so what the board commits as it is torn down reaches no authority: all three drop a stroke still inside the wait. A forced pane close releases a text tab's document session the same way, as the forced tab close does, so an edit of that tab still queued behind a push is dropped with it. Without `--force`, `cs pane close` and `cs pane close-all` leave each session to its host's lingering release once their check has passed, so a stroke a board takes after that check still reaches the authority; `cs pane close-tab` releases its tab's session at once, as every close of a tab does. A pane's close from the app, which commits and saves first, leaves the session to its host's lingering release. A move to another pane, by its tab strip or a drop on its edge, commits it before the tab is copied there. A reorder within a pane and a move to the pane's other side keep the board, whose tab becomes the copy, and commit it before the copy as well: where the copy's buffer is not the board's own last serialization, as before the first change after the drawing opened, the board reseeds from that buffer, which then holds the change. Hybrid Nav commits each file tab's waiting input before copying the live layout into its displayed draft and before copying that draft back into the live layout, so both replacements carry the board's first stroke. Every way the page asks the desktop to hide or close its window (the red dot's prompt with its Hide and its Close, the red dot at once while the window reconnects or holds no tab, the hide-window and close-window commands from a chord, the host or the command deck, and a chord a user assigned to either) and an unload run no tab's close: they commit every board's waiting change, run the effects that queue each tab's recovery write, and write every queued recovery write, a text tab's included. So a window's close does not save first: it runs no save and asks about no unsaved tab, each tab's waiting input goes to its recovery buffer, and the next page load's open of the file offers it. A way a window goes that runs no page code commits nothing: `cs window hide`, the launcher's hide, and a desktop window the desktop destroys on its own, as at its quit or a devserver's disconnect, unless the webview fires an unload event then, which is not known. The recovery buffer is not a save, and it is the browser's storage for the page's origin: a local desktop window is served from its saved loopback port when available, so its recovery entries survive launches at that origin; a fallback run uses another origin and strands its entries for that run. The next page load's open of the file offers an entry whenever its content differs from the file's, however late the file was written: a live board's authority writes the file as soon as its last window detaches, so the file can be newer than an entry and still lack the entry's last push. An entry is retired once the file holds its content byte for byte. A file the authority wrote holds a scene in the authority's serialization, so an entry stamped between a stroke and its ack is offered even when the push arrived. Such an entry holds nothing the file lacks: on a live board Restore takes nothing of it and it stays, and on any other tab Restore puts back the scene the file holds. Restore on the seeded board of a session that can still reach its authority, which is one whose snapshot the board has adopted and that has not stopped for good, does not put the entry in the board's place: the board holds its authority's scene, which a peer may have changed since the entry's stamp, so the canvas lays the entry over that scene as a local change (`restoreOverScene`). It takes the entry's elements whose id the board lacks or holds at a lower version, the board's tombstones counted, and the files the board lacks, and flushes at once, which offers those elements to the session and writes the result into the buffer. When the board took something of the entry, an element or a file, the host stores the buffer in the entry's place, under the current page load, before Restore returns: the buffer holds the board's serialization and never the entry's bytes, so no save could retire the entry by holding its content, and the tab's open would offer it again as soon as its saved text moved. The store is written then and not after the recovery write's debounce because a session between sockets or degraded takes no push: the restored elements are in the page alone, and a page killed inside that wait would leave neither them nor the entry. So from the moment Restore returns the store holds the entry or the buffer that took it. When the board took nothing, nothing is deleted: the entry stays stored and the banner stays, with the reason in the place of its offer and Restore and Discard beside it. The reason is that the unsaved changes cannot be read as a drawing, for an entry that does not parse as a scene, or that they hold no element newer than the board's and that Restore on a live drawing leaves its grid, background and deleted elements as they are. It stays while that entry is offered, through a peer's edit that moves the tab's saved text. An element the board holds at the same or a higher version stays the board's, a peer's delete and a peer's newer copy among them, so where the push arrived the board does not change. An element the entry lacks stays too: an entry carries no tombstone, so an element its user deleted before the reload cannot be told from one a peer added after it, and such a delete is not restored on a live board. The entry's appState is not taken on a live board, in any case: an entry does not record which of its appState keys its window had changed, and a key has no version, so the entry's value for one cannot be told from one older than the authority's. The board keeps the authority's grid and background, a grid or background the entry's window had picked and no authority had confirmed is not restored, and an entry that differs from the board by those alone is one Restore takes nothing of. On any other tab, Restore writes the entry into the tab's buffer, and a board reseeds from it, with the entry's deletions and its grid and background: a text file, a drawing with no session, a board that is not seeded, a drawing whose board has adopted no snapshot of its session, which has had no frame, or only frames that are no snapshot (the hello a server opens the socket with, an error it sends before it closes the socket), or has not sent the snapshot of the socket the board bound on, so that the board holds the buffer's scene and nothing a peer made, and a drawing whose session has stopped for good, as one does when the server lacks scene sync, closes the session or answers a permanent error, after which the session's object stays the tab's with no authority whose scene a merge would keep. A degraded session that keeps redialing still has an authority, and its board gets the merge. A session whose board had adopted no snapshot can still send one after Restore, and it is reconciled over the restored board as over any board: an element the authority holds and the entry lacks is on the board again, one the entry's user had deleted among them, the entry's elements the authority lacks are offered to it, and the authority's grid and background take the place of the entry's, since what a seed puts on the board is never offered. A grid or background the user picked on that board before Restore is no claim after it: Restore replaced the board the pick was made on, as a reload does, so the host tells the session, which ends the claim as it does when the tab takes the disk's scene, and the snapshot's value takes the board with nothing of the pick pushed. A file replace's refresh and the watcher's missing-file check commit a waiting stroke before they check whether the tab is clean, so the check reloads nothing over it, and Reload from disk commits one before it asks whether to discard it. The tab menu's Reload, changed-on-disk banner's Reload and conflict dialog's Reload commit nothing first; a load's end reseeds the board and can lose that stroke.

With a live scene session, the board takes the authority's appState from a snapshot or an update as the library keeps it: the canvas restores and serializes that appState as the seed does a buffer's, so only the grid and the background reach the board, each at the library's default where the file lacks it (and the grid's size and step also where they are not finite numbers, then rounded and clamped to 1..100), and a view key in a file's appState never does. That value becomes, at once, the baseline the board's next offer is compared with and the appState laid over the board's in every serialization until the library shows it, so a flush or a push made before the library renders the adopt sends nothing older over it. One kind of key is kept over it. A key the user changed inside the 200 ms before the board's next flush is on the board and in no offer yet, so the session laid no claim for it over the handed appState, which carries the authority's value. Where the session would keep that key's offer as a claim (`keepsAppStateClaim`: a writable tab, an authority still to reach, whether or not the board has adopted the scene), the canvas lays such keys over the handed appState, so they stay on the board, and leaves them out of the baseline, so the next flush offers them. On a read-only tab the handed appState replaces them, as an offer made there is not kept. The canvas offers its session the appState keys whose values on the board, as the serializer keeps them, differ from its baseline's, each compared as JSON with sorted keys. The baseline is what the board took at its last seed or adopt, or held at its last offer, so what a board seeded with is never offered, and the authority is not handed, and does not write, an appState nobody changed on the board, whether the file's is `{}`, carries keys the serializer drops, or lists its keys in another order; a change of the grid or the background is offered as that key. The session keeps the keys the canvas offers as this window's claim from the offer on, whether the push went on the wire, was queued behind one or was refused, as it is while the socket is down, between a socket's opening and its snapshot, the first socket's included, and while the session is degraded. The canvas takes the offer as its new baseline on either answer, so the board keeps no second copy to offer and its next change is compared with what it offered. The claim holds only the keys this window changed, each with the value picked, and the session keeps the authority's appState beside it, as it last knew it: a snapshot's, an update's, and the one a push of this window's sent once that push is acked. The scene's appState is the authority's with the claim's keys laid over it. It is what the session hands a canvas at a snapshot, at an update and at a bind's replay, and what a push sends, whole, since the authority replaces its appState with a push's. An appState key has no version, so the claim is the only thing that can offer one again: it stands across a drop and a redial, and this window's value stands for each key it picked, over a peer's change of that key made meanwhile, while a peer's value stands for every other key, on the board and in the push. While an appState of this window's is on the wire, a snapshot's and an update's appState stay off the board and out of the scene, since the authority applies that push after them and then holds what it sent. A push still queued is not on the wire: a snapshot's or an update's appState that lands while only a queued push holds one is the authority's, so the board is handed it with the claim's keys laid over it, and the queued push's appState is built when the push goes on the wire, at the ack of the one before it, over the authority's as it is then, so a peer's change to another key made while the push waited is in what it sends. What is laid over it are the keys the queued push carries: an offer that joins a queued push adds its keys to them and drops none, so a key the session's claim lost while the push waited, as when the tab turned read only and back, is still sent, and the session's claim is that push's again, ended by its ack. Once a snapshot has been applied and the canvas has pushed what stayed local, the session pushes the claim itself: a push it takes carries the claim when no push on the wire or queued does, so the claim rides the canvas's push when there is one and goes alone when there is none, and a save that waits pushes it too. A claim ends in one of six ways. It ends at the push-ok of the push that carried it, unless a key joined it since, and then it stands whole until the push that carries the later one is acked. It ends when the session stops retrying, since no authority is left to confirm it. It ends when the tab loads its file again: the host releases the session for the length of a load, and a session released while its tab loads drops the claim, so a Reload that ends inside the release's linger, which acquires the same session again, replays the authority's appState and not the pick the user reloaded away. It ends when the tab takes the disk's scene through the server's resolve route, which runs no load and keeps the session, in whatever state it is: the tab tells the session, which drops the claim and takes the appState out of a push still queued, so the next snapshot is not handed the pick and no later push sends it. It ends when Restore replaces a board that adopted no live scene: the host tells the session to drop the claim made on the board it replaced, and a later snapshot takes the authority's appState without that pick. It ends when the tab turns read only, by read mode or by a file that lost its write bit: the host tells the session, which drops the claim and hands the board the scene's appState without it, since a read-only tab pushes nothing and no ack could end the claim. A key that a push on the wire or queued carries is still in that appState and stays on the board: its push goes out whatever the tab's mode, and the authority then holds the key. A claim does not end with its session while its tab lives on: a session torn down with a claim hands it on for as long as a release lingers, and the session the tab acquires next starts with it, so a rename, which releases the session of the old path at once, carries the claim to the session of the new path, where it is laid over the first snapshot and pushed, and the tab reads unsaved meanwhile. A tab that closes takes its claim with it. Two sessions keep no claim that a canvas offers them: one whose tab is read only and one that has stopped retrying. A canvas bound before the current socket's snapshot, as a tab shown for the first time or mounted again while its session is between two sockets is, shows the buffer it seeded from; a key picked there is this window's claim like any other, laid over that socket's snapshot when it lands and pushed after it, while every key the user did not pick takes the snapshot's value. A peer's edit reaches the tab's buffer only through the canvas's flush, and no push-ok follows it, so after each flush that writes the buffer the canvas asks the session to mark the buffer saved, which the session does only while attached and with nothing of this window on the wire, queued, claimed or not yet handed over; a local change keeps waiting for its own push-ok, so a tab whose appState claim stands reads unsaved until the authority acks it.

A live board binds to its scene session once it has taken its first seed, and not before: the library hands its API over before its init, whose apply replaces every element put on the board before it, and the seed at the init's first change then hands the buffer's appState. Until the bind, every snapshot and update waits in the session's scene, which holds those frames and this window's own pushes, each with its elements, its appState and its files, taken when the session takes the push. The bind replays that scene onto the seeded board as an adopt, so the board shows what the session holds beyond the file, an older copy the file carries loses to the session's, and a board nobody touched pushes nothing, except when the file holds an image the authority does not hold. A first seed at the library's change runs in the library's task and the bind in the microtask after it; a first seed made when a tab's load ends after the library's init is followed by the bind in a later pass of the same flush. No frame lands between them in either. The bind depends on the session and that first seed alone: it binds again when the session is replaced or its prop goes through null and back, and not when the roster or the tab changes, though the replay reads both. A board that has not taken its first seed pushes nothing. A later reseed keeps the binding: a conflict's resolution or a sibling's mirror reseeds from the buffer and replays nothing, so no replay brings back an element that buffer deleted, and a reload releases the session while the tab loads and binds it again when the load ends. That leaves a reseed from a buffer older than the authority, which a conflict's resolution answered before a peer's push can hand a bound board, on the board with the scene's marks: its older elements are offered, the authority discards them and the canvas marks them as sent, so the board shows them until their next update, and its older appState stays on the board, unpushed, until the session next hands the board one: a seed's appState is the baseline and never a change. The scene's appState holds this window's claim from its offer on, laid over the authority's, so a later bind replays the claim's keys with the authority's others. A snapshot belongs to the socket it came on: until the current socket's has landed, the session takes no push and replays nothing, so no push that leaves on a socket is handed back by that socket's first snapshot, which hands back as unaccepted only what an earlier socket carried, and the elements and files of a push discarded with a bound canvas are handed back to that canvas, while those of a push discarded without one are held outside the shadow until a fresh snapshot and a later bind can replay and offer the ones the authority lacks, in a push that carries the claim. The appState of either stays the session's claim, so a canvas bound at the drop and one that is not end the same way. The server also fans a snapshot to every attachment, on the socket each has, when a conflict's resolution leaves the scene unchanged or overwrites the disk. Such a later snapshot ends none of this window's pushes, since the authority applies those it reads after it and acks them on that socket: they stay claimed, their parts stay in the scene over the snapshot's but for an element the snapshot holds that the authority keeps against the push's, a newer one or one of the same version with the lower nonce, and while an appState of this window's is on the wire the snapshot's appState stays off the board, as an update's does. Such a push's elements and files end as any on the wire end: at its push-ok, at the socket's close, or at the next socket's first snapshot.

An appState this window picks on a board before its session's snapshot, the first socket's or a later one's, or while the socket is down, is kept as the claim and pushed after the snapshot, and elements and files that stayed local are reconciled with the snapshot and pushed. That has two costs. A save that waits on such a push waits for the snapshot for at most `SCENE_FLUSH_TIMEOUT_MS` (4 s), after which the session degrades and the save falls back to the classic PUT, or until the socket closes and the reconnect's grace (two attempts or 3 s) runs out, which degrades the session with its socket down: the save then writes nothing, as a save does during any outage that is still retrying, and the tab reads unsaved until the reattach pushes the elements, the files and the appState claim that stayed local and the authority acks them. And a tab can hold a session with no seeded board: a board whose library never reports its init's change never seeds, and a restored drawing tab that was never brought to the front has a session and no board, since the host loads the canvas at the tab's first showing and acquires the session whether or not it is shown. Neither binds, pushes or publishes, so the buffer stays the load's text while the session stamps the tokens of its last frame on the tab. The server would apply a classic PUT of that buffer to the live scene when those tokens pass its check, and its replace makes a deletion of every element the text lacks, a peer's edit made after the load among them; that path is read and not run. So a save of such a tab that the authority does not answer writes nothing, in whatever state its session is. While the session owns saves, a flush that fails, by the timeout or a flush error, leaves it attached and the next save asks the authority again; once the session is degraded or off, the save is refused with no wait. The save line says that the file was not saved and why: the flush's own error, or that the server has not confirmed writing the file and the tab has no board open to save it from. That second reason goes when a flush lands, when a new snapshot says the file holds the scene, when a board binds and when the session is released. A session released while a save waits on it answers for nothing: it writes no reason and mirrors no status, the save writes nothing, and whatever released the session owns the tab's next save.

## Bubbles

A document or selection change recomputes the bubble spec; the host mounts or reuses one popover and commits a range replace through a high-precedence keymap, never stealing focus from the document. A bubble that closes itself (Escape, a click away, a pick) is not opened again while the caret stays in the trigger that opened it, since the next keystroke there only changes the query; a caret that leaves that trigger, or a new trigger, clears that memory. The closes the host makes for its own reasons (another trigger, no trigger, a read-only flip) are not remembered.

    Triggers-->>Listener: BubbleSpec or null

## Server contract

The editor relies on three server contracts: file reads/writes with optimistic CAS, picker/classification lookups for links, contacts, tags, headings, and images, and a watch stream whose self-write filtering keeps autosave from reloading the buffer it just wrote.

## Autosave and conflicts

### First document attach

Before installing collaboration, a document session compares its first snapshot with the tab's saved base and current text. A clean tab adopts the authority without pushing its older text; local edits against an unchanged authority proceed through live updates. When the buffer and authority both differ from the base and from each other, the session holds the buffer for Reload or Overwrite. A failed editor commit also requires a choice, as does an unanswered former push whose outcome cannot be matched to the new authority while the buffer differs from that authority. This judgment runs between editor mounts too, including when a peer update arrives before the editor binds.

The same session keeps save authority while the choice waits: it receives the authority's updates but publishes no held buffer, and classic autosave writes nothing beside it. The tab shows its own banner; its question does not replace another tab's open modal. A classic save refusal in another tab can replace the held tab's modal; the held tab keeps its banner and save line, and a choice applies only to the tab it names. Cancel dismisses the modal and leaves the hold in place. Further edits and peer updates do not reopen the dismissed modal while the hold remains; an explicit Save can reopen it. A first snapshot waiting for its editor also keeps dirty text out of classic saves.

Reload takes the latest received authority text and replaces the editor without committing the input it discards. Overwrite, while the channel is open, submits the difference from the session's latest authority text to the current local buffer through collaboration against that authority version. A peer edit arriving after the click is rebased beside the local edit. A disconnected Overwrite leaves the choice held with a reconnect reason. Choosing does not itself confirm a disk write: the existing push acknowledgement, flush and error rules still determine whether the file is saved. After collaboration is installed, its existing reconciliation handles later changes.

If a classic save started before a document or drawing session was acquired, it finishes under its original preconditions before a new session is acquired. Existing sessions are retained; acquisition eligibility is not rechecked on each edit. The drawing guard changes acquisition around an in-flight classic save, leaving scene reconciliation unchanged.

### Live saves and classic fallback

This is the detached/fallback path; an attached doc session replaces the PUT with collab pushes and flush confirmations. A keystroke flows through the echo guard and debounced autosave to `PUT /api/fs/<path>`, carrying `expected_mtime_ns` + the last-read `authority_version`; a missing authority precondition returns 428 and a version mismatch returns 409, each with the code `write_conflict`, and either opens the conflict dialog; a non-self `/ws` event only raises the changed-on-disk banner. A dirty/conflicted session is resolved explicitly through `POST /api/session-conflicts/resolve` (`reload` | `overwrite`).

An attached document or scene session writes through its authority. A scene session reads from a push's ack whether the push changed the authority's scene: a save that waited on a push that did answers saved at the authority's next flush frame, when the file holds the push, and until then the force-reload prompt counts the tab as holding what the file lacks; after a push that changed nothing the authority writes nothing, so the save answers at the ack. A flush the server cannot make (a full disk, a permission) keeps the editor: the session writes the error as the tab's save error, which the toolbar shows as not saved while the tab is dirty or the session holds what the file lacks (a live tab's confirmed text counts as saved, so the tab stays clean), and a flush that lands clears its own error. A failed live save degrades the session and waits at most `DOC_FALLBACK_SETTLE_MS` or `SCENE_FALLBACK_SETTLE_MS` for pending pushes, unless the session refuses the fallback: a scene session with no board bound and no push of this window's unresolved is not degraded by the save, which writes nothing (see Modes). A positive answer for every relevant push permits the classic PUT with the latest authority token; timeout, socket closure and a later snapshot on the same socket leave the PUT withheld, the buffer marked unsaved and the close warning active. A fresh socket snapshot reopens live synchronization with retained local edits; a confirmed live flush or a guarded classic PUT clears the unsaved mark. A document socket that hears the server's `hello` starts a 30 s snapshot bound when its dial has no version or its session is not attached; every scene socket starts the same bound at `hello`. At the bound the session degrades with the socket open, so the tab can save the classic way. A late snapshot attaches unless a classic save lands first and redials for a fresh snapshot. A resumed document socket with its editor attached at open waits for no snapshot and has no snapshot bound.

A classic save request that fails also keeps the text editor or drawing board and shows "Not saved" with the failure reason on the toolbar. A later request that writes the buffer or meets a conflict clears that reason; a load failure still replaces the editor because there is no complete buffer to show. Closing a dirty file after a failed save asks whether to keep editing or close without saving. A draft's close or promotion and a move to another window instead leave the tab open and give one notice; failures of draft inspection, discard, promotion or the path prompt give their own notice without claiming a save failed. A thrown write does not set the refusal hold that keeps a drawing off its live session.

A drawing's save checks its text first. Text that does not parse is not written: the tab keeps its editor with the text as typed and says on its toolbar that the file was not saved and why, and in board mode the placeholder says the drawing has not been saved and points to Show source code. The toolbar gives the parse reason for invalid text; when the text parses, that reason clears on the next autosave check, but the board placeholder can still hold valid text awaiting a write or conflict resolution. A successful write or an edit back to the saved text clears the hold; a load or rename out of the check clears it too. While that hold remains, the tab takes no live document or scene session, so the write carries the tokens of its load and meets the conflict check; the cost is that the tab shows no peer's cursors and merges no live edits until then. A close of such a tab asks whether to keep editing or close without saving, and a close that also ends a running terminal asks "Close tabs?". A draft has its own close flow: with unsaved text that does not parse its close runs no save and opens the draft's dialog, which then names no destination, gives the parse reason and offers Discard Draft and Cancel alone, with focus on Cancel. Discard removes the draft with nothing written first, and Cancel keeps the tab with the text as typed. A reopen of a draft discarded that way mints a new draft and puts the text back as its unsaved buffer, written nowhere, with the parse reason on its toolbar, so the new draft's close opens the same dialog. A draft whose text on disk does not parse and has no unsaved edit keeps the dialog that saves it. A move to another window stays open instead and says that the file was not saved, and so does a draft's Save to Workspace.

## PDF export

`exportMarkdownToPdf` (`pdf_export.ts`) renders markdown to PDF in the page itself: a deck gives one A4 landscape page per slide, a document paginated A4 portrait. Each page is composed as DOM (`pdf_pages.ts`), made self-contained and rasterized (`pdf_snapshot.ts`), and embedded as one PNG through pdf-lib.

- **A page is drawn from an SVG document, with HTML images painted separately when their place is exact.** The page DOM is serialized into an `<svg><foreignObject>`, loaded as an image and drawn on a canvas. That SVG document loads no external resource, so shown image resources are fetched when external and decoded in the app document, CSS URLs and fonts are inlined, and an audit refuses references left external. Before measuring, `content-visibility:auto` is revealed on each image's ancestors in the export page. One pass then records whether each image is shown and, for each HTML image with a box, its composed content box, ancestor clipping, scale, computed `object-fit`, and computed width and height. A lifted HTML image becomes an empty stand-in and keeps its decoded bitmap outside the page. Its width hint is the greater of decoded natural width and measured computed width when it has a natural size, but no width attribute is added when the author supplied a width or height attribute; its aspect ratio follows natural dimensions unless the author supplied an inline aspect ratio. The lift compares final computed width and height with the recorded lengths and constrains them where they differ. A marker raster locates each stand-in, and the bitmap is drawn there with computed `object-fit`, centered `object-position`, and containing-block clipping. The separate bitmap is overlaid on the page, so partial opacity, filters, border radius and content overlapping the image are not preserved. An SVG `<image>` stays in the page document after its bytes are decoded. Document images are prepared once before pagination reads the export layout and pages are cloned; an image cut by a page continues on the next when the lift can place each shown part.
- **An image the lift cannot place stays in the page document.** A shown image with a transform other than a positive scale, a computed `rotate` other than `none`, a computed `scale` with any nonpositive component, an `offset-path` other than `none`, `clip-path`, or mask on itself or an ancestor keeps its prepared `data:` source. A deck's own centered fit transform is allowed because its marker records the scale and translation. The same fallback applies when its measured size or final box cannot support a stand-in, its marker is missing, narrower than the recorded shape, or shorter away from the page edge that cuts its shown part, or the last page window ends before the image does. The last document window ends at the lowest top-level block, preserving that page cut; extending it to the content scroll bottom would change pagination and show overflow past the block. A first part whose marker reaches both the page's top and bottom is treated as a cut from below, so an image that began above the window and extends beyond its bottom can show the wrong rows. The page's own SVG document paints a fallback image with its crop or transform, although that raster may still finish before a nested image loads.
- **An export refuses an image resource it cannot prepare.** A failed fetch, non-image response, or failed decode fails by the address selected for preparation, without its query token. Page raster and time bounds also refuse work they cannot complete. A hidden HTML image is replaced with an empty stand-in; a hidden SVG `<image>` has an external href replaced but keeps a data href. Neither is fetched or decoded while hidden. Hidden cases include closed `<details>`, `display:none`, hidden visibility, zero opacity, `content-visibility:hidden`, and loaded HTML images with no composed box or a fully clipped box. An unsettled or broken image's empty box alone does not hide it. Where `checkVisibility` is unavailable, style, document structure and the loaded image's measured box decide; an SVG `<image>` follows its outermost `<svg>`. A shown HTML image without `srcset` is prepared and named from its `src` attribute; an empty or fragment-only `src` is left as the page has it. A shown HTML `<img srcset>` is prepared from `currentSrc` when available and loses its `srcset` before the audit; a shown `<picture><source>` remains refused, as do disallowed embedded content and unresolved CSS URLs.
- **Image preparation is bounded and ordered.** Images are fetched and decoded in batches of eight. If one fails, later work in its batch is aborted and no result from that batch is written; later batches do not start. The first fetch, type or decode failure in document order is named; a later lift fallback is not a preparation failure. Decodes already in progress may finish, but their results are discarded. A document resource pass is allowed 30 seconds plus 30 more for each image batch, up to five minutes; `cs export` gives up on its reply at 90 seconds.
- **A deck page is laid out as the deck plays, at one reference screen.** A slide's text and its `#w=` images are sized in px and its box in viewport units, so where a line breaks depends on the screen. The export lays each slide out in the box play gives it on a screen 1920 by 1080 (1920 by 1080 for 16:9, 1440 by 1080 for 4:3, with 54 px of padding) and rasterizes at the scale that maps that box onto the page, so one deck gives one PDF from any window and from `cs export`. Its lines are play's at that screen, not at every screen: on a wider one, play holds more on a line than the PDF does. The preview's box is narrower, 86 percent of the viewport, and the PDF does not follow it. On platforms with classic scrollbars, a vertically overflowing slide gains one in play, so lines near its right edge can wrap about one scrollbar width earlier there than in the PDF's scrollbar-free box.
- **A slide larger than its box comes out whole and smaller.** On screen such a slide scrolls. In the export a code block grows to its longest line instead of scrolling, the page is attached off screen and its content measured, and content taller or wider than the slide is scaled by a transform, which keeps every line break; its top is kept and it is centered across the slide. One long line therefore makes its whole slide small.
- **No raster carries a scrollbar.** The SVG document of every page, a deck's or a document's, hides the scrollbar of every element.
- **A `cs export` job reports each page and heeds a stop.** The job's window renders in the page and answers the command through the reply route. After each page it finishes, a slide or a document page, it posts the count of pages finished, and the next page starts once that post has returned; the server ends a job that says nothing for its quiet bound and a count that advances starts the bound again, so a long deck whose slides each finish inside it completes, within the job's cap. The reply follows the last count. A job whose frame carries `guarded_upload` writes under the server's guard: each of its uploads carries the job's id in `X-Chan-Export-Job` and targets the job's output path alone, a create or, when the create is refused because the target exists, a replace. The server refuses them once the job has ended, and any refusal other than the create's 409 ends the job with `ok: false` and the server's sentence; the window renames nothing on a collision and removes nothing. A frame without `guarded_upload` takes the page's fallback write, replacing `out` first and uploading into its directory if the replace is refused; every server that embeds this page sends the flag, so no matched build takes that fallback. An output path ending in a slash makes the create target a file named `export` in that directory, which differs from the job's output path; the server refuses the commit and the job answers `ok: false` with `io error: export job retired, expired, or upload path differs`. The server's `export-stop` frame for the job, or a count the server answers 404, ends it: no further page starts, no new upload or reply begins, and a request of the write already in progress may finish, with no further request after it. A count that fails any other way is logged and the export goes on. A job whose engine fails to load is answered `ok: false` with the error. The window's own Export to PDF posts nothing.

## Implementation notes

- List continuation and indent/outdent match the current line with a regex, not the syntax tree, so the edit stays cheap and local.
- Heavy or optional modules load lazily on first use: mermaid and mermaid-to-excalidraw + excalidraw (diagram render; excalidraw carries React, so both are dynamic-imported and code-split out of the eager editor bundle), turndown (HTML-paste -> markdown), HEIC -> WebP conversion before image upload, and the per-language code packs (one vite chunk each).

## Out of scope

- In-cell table editing: the grid atom is read-only; edits happen in the revealed pipe/dash source.
- YAML highlighting inside frontmatter: the block is isolated and dimmed, the body is unstyled.
