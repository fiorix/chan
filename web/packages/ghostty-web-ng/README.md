# @chan/ghostty-web-ng

chan's terminal widget is derived from [ghostty-web](https://github.com/coder/ghostty-web) (MIT, by Coder) and runs on the signed libghostty-vt core and chan's binding. The workspace app imports the widget and binding from source through `@chan/ghostty-web-ng` and `@chan/ghostty-web-ng/vt`. The package is private and has no standalone build or publication.

## Sources and consumers

`lib/` contains the widget, renderer, input handler, selection manager, buffer facade and both link providers. `Terminal` takes a required `GhosttyVt` instance as its `ghostty` option. The renderer, buffer and selection manager read the binding's `VtCells` views; each cell carries the core's styles, colours and complete grapheme cluster. Frame reads use `beginFrame`, `endFrame`, `isRowDirty`, `readRow` and `readHistoryRow`.

`vt/` contains the libghostty-vt binding, the copy filter and their tests. `vt/index.ts` is the separate `./vt` export. The workspace app, its terminal tests, the binding tests and the terminal pixel harness under `scripts/e2e/terminal-pixels/` all use the vendored core, exported as `./vendor/ghostty-vt/ghostty-vt.wasm`.

The widget exposes the subset chan uses rather than an xterm.js compatibility API. OSC 8 and plain URL links use the built-in providers; see Links below. The widget owns viewport positioning and output following; the app supplies wheel calibration, copy policy, find, secret masking and theme updates. `Terminal.open()` does not take focus; the caller chooses when the terminal receives the keyboard. `focus()` synchronously focuses the connected host with `preventScroll: true`, takes no focus before open or after disposal, and schedules no retry. `blur()` releases only a focused terminal element or descendant, including the hidden input textarea.

## Themes

`term.setTheme(theme: ITheme)` replaces `options.theme` with a copy and updates the core defaults and painter together. It synchronously repaints all rows, cursor, selection, highlights, scrollbar and registered paint layers, with the mask last. It preserves focus, content, core identity, viewport, selection and grid dimensions and emits no resize or input. Before open it only stores the copied theme for construction; after disposal it does nothing. A call from a paint callback requests a complete next frame. Direct mutation of fields inside `options.theme` is not an update API.

An omitted or `undefined` color clears its previous override. Core defaults are foreground `#cccccc`, background `#000000`, no explicit cursor color and libghostty-vt's built-in 256-color palette. The painter's omitted background is `#1e1e1e`, cursor `#ffffff`, cursor accent `#1e1e1e` and selection background `#d4d4d4`; omitted selection foreground preserves the cell's own ink. The painter uses core-resolved foregrounds and palette entries for cells. Theme color inputs support hex (`#RGB`, `#RGBA`, `#RRGGBB`, `#RRGGBBAA`), numeric `rgb`/`rgba` and `transparent`; the core takes their RGB channels while the painter retains background alpha. Zero RGB is explicit black, including palette entries; omitted binding palette slots use `undefined`. Program OSC color overrides remain over the new core defaults.

`ITheme.minimumContrastRatio` defaults to 1. Non-finite values and values below 1 behave as 1. At 1, cell ink is unchanged. Above 1, inherited cell foregrounds below the requested WCAG sRGB luminance ratio move along an RGB line toward whichever of black or white has greater contrast with their painted background. The widget takes the least interpolated, rounded 8-bit color meeting the ratio; if no color can meet it, it uses that maximum-contrast endpoint. The adjustment affects paint only, including truecolor, ANSI colors, inverse video, wide clusters and custom box/block glyphs; core color values and all backgrounds remain unchanged.

Default backgrounds use the row's theme fill, explicit backgrounds use their own RGB (so black stays black), and inverse video uses the original foreground as its background. A transparent or translucent final backdrop has no known external color, so its ink is left unchanged; explicit opaque cells on that backdrop still receive the floor. Selection and highlights composite their background over the row fill, and inherited ink is measured against that composite when it is opaque. An explicit selection or highlight foreground, cursor/accent, explicit SGR underline color and link-hover underline keep their own colors. Other decorations follow the adjusted ink. Faint, shade glyph opacity and font antialiasing still apply afterward, so their resulting edge/translucent pixels can be below the requested ratio. Custom paint layers, including the final mask, receive no contrast adjustment.

## Scrollback budget

Construction option `scrollbackBytes` sets a budget in bytes of retained history in the core, not process memory or WebAssembly memory capacity. A positive finite integer replaces the `scrollback` line ceiling, even when both options are supplied. Values above `4,294,967,294` saturate there because wasm32 reserves the next value for unlimited history. Zero, negative, fractional and non-finite values behave as an omitted byte budget: `scrollback` retains its line-count behavior, defaulting to 10,000 with zero meaning unlimited. Neither option updates the core after open.

The binding forwards the budget as `VtTerminalConfig.scrollbackMaxBytes`. An omitted binding byte limit uses the line limit; explicit zero disables history. The core prunes whole pages and retains the live grid, so a small budget rounds up to its page minimum and retained allocation can exceed it by page granularity. Page size depends on content: wide/combining clusters can consume more bytes per row and retain fewer rows than ASCII at the same budget. For a setting in MiB, pass `scrollbackBytes: mib * 1_048_576`; do not also convert it into a line count.

## Core access and lifetime

`term.core` is a frozen runtime forwarding facade, not the raw `VtTerminal`: core is available when `term.core` is defined, never by instanceof. It is `undefined` before open and after disposal, and the same facade and core remain throughout an open terminal's lifetime. Writes, resize reflow and a program's VT reset do not replace either. There is no `Terminal.reset()` method or core-replacement event.

`TerminalCore` exposes exactly `beforeResize`, `createSearch`, `trackCell`, `cols`, `getScrollbackLength`, `getDimensions`, `plainText`, `readRow`, `readHistoryRow`, `isRowWrapped`, `isScrollbackRowWrapped` and `encodePaste`. It has no write, resize, free, theme setter, response drain or frame-consumption operations. `cols` and dimensions follow the live grid. `beforeResize(listener)` observes the old grid before reflow, receives a dimension snapshot and returns an idempotent unsubscribe function. `plainText(range?)` uses inclusive absolute buffer rows, oldest history first; `readRow` and `isRowWrapped` use live-screen rows, while the history variants use oldest-first history rows. A wrap flag says that the row continues the row above it. `encodePaste` sanitizes text and frames it according to the live bracketed-paste mode; it sends nothing.

Row reads fill a caller-owned `VtCells` view with copies of cell values, without exposing the raw core as the view's cache owner or consuming render dirtiness. A view holds one row at a time and reuses its cell objects on its next read; use separate views or explicit copies to retain multiple rows. Mutating those values does not change terminal content or widget bookkeeping.

`createSearch()` returns a frozen `TerminalCoreSearch` handle with `setNeedle`, `restart`, `step`, `feed`, `selectNext`, `selectPrev`, `caughtUp`, `state`, `matchesBetween`, `indexOfMatchAt`, `free` and a read-only `completingUnitMs` observation. Its mutations affect only its search state; selecting a match changes neither widget selection nor viewport. `trackCell(row, col)` returns a frozen `TerminalCoreTrackedCell` handle or null for an invalid cell; `point`, `moveTo` and `free` affect only that handle's tracked reference. Neither handle exposes binding internals. Both remain caller-disposable, and the widget releases every outstanding handle and resize subscription before freeing its core.

After terminal disposal or failed open, every member of a captured core facade, including the `cols` getter, throws the exported `TerminalCoreDisposedError`. Previously returned unsubscribe functions and handle `free()` methods remain idempotent. Released search handles are empty and complete, have null timing and match/index values, return false from selection and ignore updates. Released tracked handles return null from `point()` and false from `moveTo()`. Calls through `term.core` therefore require an availability check; retained facades must not be used after their terminal is disposed.

## Viewport and content changes

`term.getCursor()` synchronously returns a fresh `Readonly<{ x: number; y: number }>` snapshot of the cursor's zero-based column and row on the active live screen, including the alternate screen. It reflects parsed writes and cursor moves immediately, independent of viewport scrolling or retained history. Its `x` is always below `cols`, including deferred wrap, and its `y` is the screen row regardless of origin mode. It returns `undefined` before `open()` and after `dispose()`.

`term.viewport.offset` is the fractional number of rows back from the bottom. `scrollTo(offset)` sets that distance, `scrollBy(rows)` adds to it (positive moves toward older output), and `scrollToBottom()` returns to live output. Explicit positioning cancels a pending smooth scroll and clamps to retained history. `reveal(row, align)` takes an absolute row, with row zero at the oldest retained history row; it leaves a visible row in place and positions an off-screen row at `"start"`, `"center"` (the default) or `"end"`, subject to the same clamp.

The viewport's `followOutput` policy is `"at-bottom"`. Writes keep a view anchored to its retained row, including when the core prunes older history. The visible row and an active smooth-scroll target are tracked independently; if either row is discarded, that position falls back to the oldest retained row. Their fractional distances are preserved within the retained-history bounds. An offset below one row follows the live screen while retaining its fractional distance, so successive pixel-wheel events can move into history while output streams. User input that emits bytes returns the view to the bottom before those bytes are emitted.

`term.onChange(({ kind }) => ...)` reports `"write"` after each non-empty synchronous core write and `"resize"` after a grid size change. The core and viewport are updated, terminal replies are sent and cached links are invalidated before the write event; the event precedes painting, including the immediate input-echo frame. An empty write queues its callback without emitting a change or consuming a pending input echo. Its subscription has `dispose()`, and disposing the terminal releases all change subscriptions. Emission uses a snapshot of subscribers, so a listener disposing itself does not skip the next listener. The dimension-bearing `onResize` event serves consumers that publish terminal size; an unchanged size emits neither resize event.

## Selection and copy

`SelectionAnchor` is `{ col, absoluteRow }`, both zero-based, with row zero at the oldest retained row of the active screen and live screen rows following history. The alternate screen has no history. `SelectionRange` is `{ start, end }`, inclusive of both cells and accepted in either direction. `setSelection(range)` selects without copying; `setSelection(null)` and `clearSelection()` clear. `getSelectionRange()` returns a snapshot, so mutating an input or returned range cannot change the selection. Non-finite or fractional coordinates throw `RangeError` without changing it. Integer coordinates clamp to retained rows and columns; a range wholly before or after retained rows clears. Endpoints on either half of a wide glyph expand to the whole glyph.

`selectAll()` covers the retained history and active screen regardless of viewport. `getSelection()` joins core soft wraps, preserves whole grapheme clusters and wide glyphs, and applies the binding's `copiedText` filter to remove undrawn controls. `hasSelection()` reports whether a selection exists; a blank selection can have no copyable text. `copySelection()` returns true when nonempty text is handed to the copy writer, not when asynchronous system clipboard delivery succeeds. `getScrollbackText()` reads the retained history and active screen with the same formatting and filtering, without changing selection or writing the clipboard. `getRangeText(range)` reads the text a selection of that `SelectionRange` would, in either direction: the same clamp, whole-glyph widening, wrap joining and filtering, with `RangeError` for non-finite or fractional coordinates and empty text for a range wholly outside the retained rows. It neither selects nor copies, so an embedder can copy a highlight's range, such as a find match, while the user's selection stays theirs.

The constructor's `copy?: (text: string) => void` receives automatic copies on drag release, eligible capture loss, double click and triple click, and explicit `copySelection()` calls. With no callback the widget uses its browser clipboard writer. The optional `joinDrawnWraps?: () => boolean` callback is queried for each selection/scrollback read and word/line click; its default is false. When true, a row filled through its last cell joins a following nonblank row even without a core soft-wrap marker. A full-width row of box-drawing characters and spaces is never joined by that rule, to either neighbor. Double clicks keep the widget's path/URL word alphabet and triple clicks select a whole logical line; both cross core soft wraps and, when enabled, drawn wraps. Program identity and clipboard/PRIMARY routing belong to the embedder.

`cellAt(clientX, clientY)` takes DOM client coordinates in CSS pixels and returns `{ col, row, absoluteRow }`; `row` is a viewport row, and mapping uses the floored viewport offset. Positions outside the live grid clamp to its edge. It returns null for a detached canvas, unavailable geometry or non-finite input. Selection readers return empty text, false or null before open and after disposal, and selection mutators do nothing then; an unopened selection request is not queued.

Both selection endpoints track their cells through scrolling writes, history pruning and resize reflow. If the earlier endpoint is pruned, it clamps to the oldest retained cell; the selection survives with its later endpoint unchanged. If the later endpoint is pruned, or a switch between normal and alternate screens is observed between writes, the selection clears. These rules use text order, including for backward selections. Entering and leaving the alternate screen within one write preserves the normal-screen selection: its tracked cells remain valid and hold the same text. Clear, replacement, disposal and failed open release the owned references. Returned ranges remain coordinate snapshots, not persistent identities. Internally, the app's find adapter can still assign `selectionStart` and `selectionEnd` directly: each assignment replaces that endpoint's tracked reference, and reads return its current coordinates.

## Named highlights

`term.highlights` is a stable facade with `set(name, ranges, style?)`, `get(name)` and `clear(name)`. `HighlightRange` uses the selection's inclusive `{ start, end }` absolute-row coordinates. `set` replaces only the named layer, orders each range in text order, and copies its endpoints, array and style. `get` returns a fresh `{ ranges, style }` snapshot or `undefined`; caller mutations cannot affect painting. `clear` returns whether the layer existed. An empty range array retains an empty named layer. Highlights do not change selection, copy text, take focus or emit content-change events.

Coordinates must be nonnegative safe integers; invalid coordinates throw `RangeError` without replacing any part of the layer. Coordinates beyond the current grid are retained and clipped only for painting, so the owner can publish ranges before they become visible. A multi-line range covers the remainder of its first row, whole interior rows and the beginning of its last row. Either half of a wide glyph highlights the complete glyph. Before open and after disposal, `set` does nothing (including for invalid coordinates), `get` returns `undefined` and `clear` returns false. Unopened requests are not queued.

Layers persist at their supplied coordinates across writes, pruning and resizes; their owner republishes coordinates when content moves. An observed switch between normal and alternate screens clears all layers before `onChange` observers run. A round trip inside one write retains them, matching the selection's observed-switch rule. The owner's clear and terminal disposal also remove layers. Changes repaint old and new coverage; dirty-row bookkeeping expands intervals only within the visible grid.

`HighlightStyle` has optional CSS `background` and `foreground` colors. Omitted background uses the current theme's selection tint; omitted foreground keeps the glyph's own color. User selection paints above every highlight, using the theme's selection foreground if present and the glyph color otherwise. The widget reserves `search-all` as its lowest highlight layer and `search-active` as its highest. Other names paint in registration order, later names above earlier ones; replacing a name keeps its place, while clearing and setting it registers it anew. There is no caller-supplied priority. Highlights preserve explicit black backgrounds, transparent defaults, complete clusters and link underlines.

## Search

`term.search` is a stable frozen facade for one query per terminal. `find(query)` starts or replaces the query and activates the newest match as soon as one is found; repeating the same query keeps its position. `step(query, "older" | "newer")` moves up or down the buffer, wrapping at either end. With a different query it starts from no active match, so older lands on the newest and newer waits for the oldest. An empty query closes the search. Matching follows the core: ASCII case-insensitive literal bytes, with no Unicode case folding or regular expressions. The widget does not trim the query.

`search.state` is a frozen `{ index, total, partial }` snapshot. The one-based index counts from the newest match, is null when the active match's position is unknown, and is zero when total is zero. Partial totals count only distinct matches found so far, except after a write or resize on the same screen: the refreshed list starts empty, and the snapshot keeps the last total as a partial one until the refreshed results pass it or the rescan completes, so a reader between the change and the next search frame never sees a zero the buffer does not have. Identical complete cell ranges are deduplicated in newest-first order; genuinely overlapping ranges remain separate. `search.onChange(listener)` reports changed snapshots and returns a disposable subscription; it does not replay the current snapshot. Before open and after disposal every operation is inert, state is zero/complete, and subscriptions retain nothing.

Scanning runs in the widget's own animation frame, ahead of its paint, with a 4 ms core scan budget, up to 4 ms for result placement and publication, and a 12 ms scheduling target including highlight paint. Pending results drain before further scanning, and elapsed feed/scan time reduces the placement allowance. A step that would wrap during a partial scan waits for more results or completion; after one second it may wrap among those found so far. Presses queue in order with separate deadlines. A user selection made while a step waits suppresses its delayed viewport reveal; the search still updates its active highlight and count. Output feeds coalesce per frame, and a feed predicted to exceed the budget restarts the scan when cheaper. Tracked endpoints keep the active match through output and reflow. Reflow moves its highlight before paint and reveals it only if it was visible beforehand. Resize/restart restoration waits at most one second; ordinary output retains its tracked active match while placement catches up. Pruning, a cropped match or a completed rescan without the range loses the active match. Navigation is owned by the deduplicated list, so restoring an index needs no core selection walk. Replacement and close discard queued presses.

The owner publishes every known match to `search-all` (background `#806d36`) and its active match to `search-active` (background `#ffb454`, foreground `#000000`). These names are reserved for search. Painting clips to visible rows; selection paints above both layers and find never replaces, clears or copies it. Writes invalidate the old all-match coordinates and refresh them in the next frame before it paints, and before the echo paint inside a write that answers input, so a paint after a write shows the matches placed within one frame's budget, the newest first, also while output streams; the active highlight follows its tracked cells before paint. The synchronous paint of a resize still precedes its refresh. An observed active-screen switch drops the prior screen's active match and rescans. `close()` frees the search and all tracked references, cancels pending work, removes only these two layers and publishes zero/complete. Terminal disposal also releases subscriptions and pending work.

The internal owner reads result batches directly from the binding, retains a canonical index and publishes only newly placed highlight ranges. Neither navigation through settled results nor paint rereads the core match list. Highlight blocks reject offscreen history before visiting individual ranges; all matches remain logically highlightable, without a count cutoff. A write or resize invalidates numeric placement and rebuilds it incrementally. The binding still copies the core's whole selection buffer when its raw count changes, since the core does not export slices. Core feed and completion units are also uninterruptible and can exceed 12 ms on dense maximum-size history, so the scheduling target is not a hard frame-time guarantee. The public core/search facades keep their existing member lists.

Run the opt-in wall-clock harness from `web/` with `GHOSTTY_SEARCH_PERF=/absolute/path/search.json npm run test -w @chan/ghostty-web-ng -- lib/search.perf.test.ts`. It populates and prunes a 52,428,800-byte history, measures owner stages and highlight painting near both history ends during streaming and reflow, and records raw frame samples, distributions and core completion/feed limits. It asserts the full 12 ms target, including the known core limits, so a failure is retained as a measurement failure rather than silently exempted. Ordinary test runs report this file skipped: allocating maximum history and measuring wall time is intentionally opt-in, and that skip provides no performance acceptance. Its jsdom software rectangle canvas has fixed glyph metrics and no glyph rasterization; real browser frames require a separate measurement.

## Paint layers and metrics

`term.addPaintLayer({ order, paint })` registers a callback after cells, highlights, selection, cursor and scrollbar. Numeric orders must be finite; lower numbers paint first and equal orders retain registration order. The reserved `"mask"` order paints last, including after ordinary layers registered later. Only one mask can be registered at a time; a second registration throws. Each registration copies its order and callback. Its returned function removes only that registration and is idempotent. Adding or removing a layer invalidates the full viewport for the next frame. Registering before open or after disposal returns a no-op disposer and retains nothing, without validating the order.

`PaintFrame` carries `ctx`, a CSS-pixel `metrics` snapshot, `pixelRatio`, the fractional bottom-relative `viewportOffset`, absolute `topRow`, `rows`, `cols`, `full` and sorted `changedRows` in viewport row coordinates. `topRow` is retained history length minus the floored viewport offset. `changedRows` describes actual cell-row repaints, including cursor visibility and movement, hover, selection, highlights, adjacent rows for glyph overflow and scrollbar repaint or removal. `full` means all viewport rows were repainted. The frame, metrics and row array are frozen. The widget owns render-state frame reads; consumers must not call the core's `beginFrame` or `endFrame`.

Callbacks run only when rows were repainted. Each callback receives a saved canvas context clipped to those fresh rows, with the absolute DPR transform applied before drawing; its drawing state is restored afterward. Callbacks must balance their own canvas save/restore calls. Registrations are snapshotted at frame start: additions and removals during painting affect the next frame. If a callback throws, remaining callbacks, including the mask, still run; context and core-frame bookkeeping are restored, the next frame is invalidated, and the first error is rethrown. The animation loop retains its next repaint after an error. A mask callback owns its own error handling and policy.

`term.refresh()` synchronously repaints the full viewport at the widget's current scrollbar opacity, without changing PTY size or emitting content-change events. Calling it from a paint callback requests a full next frame; it never recursively paints. Calls before open or after disposal do nothing. Rendering a visible scrollbar refreshes the underlying rows, and its first hidden frame restores the old strip. Idle frames with no repainted rows do not composite paint layers again. Clearing the renderer invalidates the next full frame.

`term.getMetrics()` returns a new `{ width, height, baseline }` snapshot in CSS pixels, or `undefined` before open and after disposal. The grid measures `W` with offscreen font-box metrics when available, otherwise a hidden span of 32 `W` characters. Width is floored in device pixels; font-box height is ceiled, multiplied by `lineHeight`, then floored before conversion to CSS pixels. The natural padded `M` ink measurement supplies a baseline, centered in the measured cell and clamped into its height. An unavailable or invalid grid measurement uses natural width and multiplied natural height. Changing `options.fontSize` or `options.fontFamily` remeasures and repaints. Browser DPR changes are detected on metric reads and frames, remeasuring and repainting without resizing the PTY. Canvas backing dimensions round to whole device pixels, while metrics and CSS dimensions retain their fractions.

Construction options `lineHeight` (default `1`), `boxGlyphs` (default `false`) and `scrollbar: "overlay"` configure the grid and painting. A non-finite line height or one below `1` uses `1`. `boxGlyphs: true` draws supported light box-drawing characters, rounded corners and U+2580..U+259F block elements as cell paths. Block edges snap to device pixels, shades reduce alpha, and inverse, faint, invisible, selection/highlight foregrounds and text decorations retain their normal semantics. Complex grapheme clusters and unsupported glyphs use the font. The overlay scrollbar composites translucent ink onto content; omitting the option retains a background strip. Both styles repaint underneath each visible frame and on the first frame after hiding. These three options take effect at construction; use `{ lineHeight: 1.2, boxGlyphs: true, scrollbar: "overlay" }` for a taller grid with cell-drawn glyphs and translucent scrollbar.

For test instruments only, `testHooks: { scrollbarOpacity: number }` fixes paint opacity to the supplied value clamped to `[0, 1]` and suppresses automatic fades while supplied; omit it in production. An instrument may update that object and call `refresh()`, and observe full repaints with an ordinary paint layer. This hook controls painting rather than terminal content, event order or sizing.

## Links

The link detector underlines what its two providers find: OSC 8 hyperlinks first, then URLs in the text (`http`, `https`, `mailto`, `ftp`, `ssh`, `git`, `tel`, `magnet`, `gemini`, `gopher`, `news`). A click on a link opens nothing by itself. `term.onLinkActivate(({ target, kind, range, event }) => ...)` reports it: `target` is the OSC 8 URI exactly as the program wrote it, or the matched URL, and can name another place than the text on the screen; `kind` is `"osc8"` or `"url"`; `range` holds the link's first and last cells, absolute rows with row zero at the oldest retained history row; `event` is the click, modifiers included. With no listener a click on a link does nothing; the widget calls `window.open` nowhere.

Only a link click is reported: a primary-button click whose press neither moved as far as the selection manager's drag threshold (`DRAG_THRESHOLD_CELLS`, half a cell) nor was the second click of a double click, and whose press was not reported to a program tracking the mouse. Cancellation, unexpected capture loss, an outside release or any drag reaching the threshold discards the pending link click. An ordinary in-grid release keeps it until click, including the normal capture loss between release and click. chan's workspace app opens its link menu on the event.

Selection and mouse reporting share a captured primary mouse or pen gesture on the canvas. A pointerdown the embedder has already default-prevented belongs to the embedder for every button: the widget takes no capture, sends no mouse report and records no link press for it. Each press determines whether its button reports or bypasses the program: Shift bypasses reporting and permits selection or a link click even when Shift is released before the pointer. Shift motion and a Shift wheel are not reported. Captured releases outside the grid are clamped to the live dimensions and complete the gesture once. Cancellation and disposal stop scrolling without copying; connected unexpected capture loss completes an eligible selection once. Cancellation and unexpected or silent capture loss on a connected canvas release reported buttons at their last known position while the core still tracks the mouse. A captured move releases each reported button absent from its buttons mask at that move's position, once, while tracking remains active. A captured buttonless move ends the gesture and releases capture unless a local selection gesture is in progress. The press records that disposition independently of the selected range. User input clears selection; mouse reports clear it only outside a local selection gesture. Consecutive motion reports with the same button/modifier code, column and row are suppressed, with the record reset at press, release and gesture end. Alt and Meta both encode modifier bit 8. A release, cancellation or capture loss that arrives while the core is not tracking clears held state silently. Disposal and disconnected canvases also send no releases. Selection survives clicks outside the widget. The visible scrollbar strip claims only primary mouse or pen presses, prevents selection and lets the press bubble to page menu closers. Its thumb uses pointer capture and restores the canvas selection styles on release, a buttonless move, cancel, loss or dispose. A buttonless thumb move ends without scrolling. Hidden strips and terminals without history keep those pixels as content. Thumb movement uses the current viewport, preserving fractional offsets and output anchoring; reaching either end discards overshoot so reversing responds immediately. No widget pointer listener is attached to document or window.

## Type checking and tests

TypeScript, Vite and Vitest read the sources through the package's export map. `vt/tsconfig.json` checks the binding, widget entry and widget test suites under the workspace app's strict settings. `vitest.config.ts` selects the binding, input-handler, focus, core, scrollback, theme, selection, highlights, search, paint-layer, rendering-option, drawn-wrap, link, pointer and viewport suites. `make web-check` runs these checks together with the workspace app's terminal suites and production build.

The package's `tsconfig.json` is a build input for `lib/`: its ES2020 target preserves constructor-assigned class fields. Vite uses the nearest configuration that includes each file. The binding's separate configuration targets ES2022; it does not change how Vite compiles the widget. The workspace app's `src/terminal/ghosttyWidget.test.ts` pins the widget's class-field behavior.

The input-handler suite keeps the upstream cases, pinned to the exact bytes the handler sends, and adds one case per composition-guard arm, the SHIFT and ALT mask bits, the AltGr fallthrough, each beforeinput kind and the SGR and X10 mouse release, each on a fresh vendored-core instance. Its container and input events are stand-ins, so it checks responses to supplied sequences rather than native IME, clipboard delivery or platform event ordering. `vt/oldCellFormat.test.ts` and the workspace app's `src/ghostty_old_format.test.ts` reject references to the unsupported upstream binding and cell format. The binding's differential tests compare against the recorded oracle.
