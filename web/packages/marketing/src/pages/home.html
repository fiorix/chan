  1. 01 / LIBRARY

    The window is a view.

    Its shell runs in the library: the one server on the local machine that holds every workspace, standalone terminal and window. Reload or hide a window and its shells keep running.

    How the layers fit →

  2. 02 / COMPUTERS

    One library per machine.

    The Computers screen lists the local machine and each devserver. A devserver is the same library, running headless somewhere else. Disconnect, and everything stays running there.

    The Computers screen →

  3. 03 / WORKSPACE

    Any directory becomes a workspace.

    chan open . registers the directory and opens a window of it. Your files stay ordinary files; what chan derives from them lives under ~/.chan.

    Workspaces →

  4. 03.1 / FILE BROWSER

    Files, beside the shell.

    cs pane new right splits the window from the shell, and cs open src opens the directory in the new pane's file browser.

    Files →

  5. 03.2 / EDITOR

    Markdown that renders as you type.

    cs open README.md opens a text file in the editor, with its source one switch away.

    The editor →

  6. 03.3 / GRAPH

    The project, drawn.

    cs graph opens the directory tree with each file's links, tags and mentions drawn over it.

    The graph →

04 / TMUX -CC

Your tmux, in Chan.

Run tmux -CC locally or over ssh. Each tmux window opens as a Chan window, with its terminal and panes and layout. Use Chan's shortcuts and hybrid nav to split and resize panes, create new windows. Manage tmux sessions from the Computers screen.

tmux setup and controls →

LOCAL

$tmux -CC new -A -s dev{{copyButton}}

OVER ssh

$ssh -t user@host tmux -CC new -A -s dev{{copyButton}}

Enable tmux control mode in Terminal settings. Requires tmux 3.2+.

05 / CHAN DEVSERVER

Your tools, on any machine.

Install Chan on a remote machine and use Add devserver in Computers to configure access. Connect over ssh or Eternal Terminal, as in the examples above. Your terminals, files, and workspaces live on that machine, ready when you reconnect.
