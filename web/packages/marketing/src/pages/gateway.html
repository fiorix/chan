Access is an operational control.

ADMISSION CONTROL

Decide what connects.

Set per-user devserver limits, suspend access, and pause fleet admissions. Every tunnel passes signed admission checks.

ACCESS POLICY

Manage enrolment, devserver grants, and PATs. Durable policy and audit records live in Postgres.

LIVE SWITCHES

Act on running connections.

Inspect proxies and tunnels, revoke sessions, or pause the fleet with fleet pause --drain. A drain disconnects active sessions and tunnels; resume reopens admission.

chan-gateway-admin fleet status
chan-gateway-admin proxy ps
chan-gateway-admin tunnel ps

Work runs on the devservers independently of client connections. Proxy nodes scale the data path; a singleton controller coordinates admission and policy. On loss of control connectivity, admission stops and existing tunnels close after a bounded grace period. See the scaling and recovery design and operator commands.

03 / SETUP

Bring your domain.

Start with one proxy node, p1. These example names show the DNS and TLS boundaries.

gw.example.com
Sign-in, accounts, and desktop discovery.
proxy.example.com
Outbound tunnel ingress and proxy health.
*.p1.proxy.example.com
A separate origin for each devserver.
  1. 01

    Deploy the services and database.

    Run identity, profile, devserver-control, devserver-proxy, and Postgres. Configure distinct service credentials and signing keys. Apply the database schema jobs before starting runtime services. Use the deployment guide and manifests.

  2. 02

    Connect DNS, TLS, and OAuth.

    Point the names above to your TLS edge and configure a sign-in provider. Route account requests to identity, tenant HTTP/WebSockets to the proxy, and /v1/tunnel to its HTTP/2 ingress. Keep internal listeners on loopback or an authenticated, encrypted private network.

  3. 03

    Provision tools and publish the devserver.

    Enrol users and grant the sign-in and devserver feature flags, which default to off. Install Chan and your team's tools on each managed host. Create a PAT with the tunnel scope in your gateway and supply it as CHAN_TUNNEL_TOKEN on the devserver. Then run:

    chan devserver run \
  --tunnel-url https://proxy.example.com/v1/tunnel \
  --tunnel-devserver-name build-host
    {{copyButton}}

    Each devserver uses its own token. The token identifies that devserver's registration.

  4. 04

    Add your gateway to Chan.

    In Computers, press g to open Gateways. Choose Add gateway, enter https://gw.example.com, connect, and sign in. Return to Computers to open owned and shared devservers.

The gateway design explains the architecture. The service documentation covers configuration, and the enrolment guide covers first sign-in.

04 / WIREGUARD

Reach a private gateway.

The devserver and Chan Desktop can each run a userspace WireGuard peer inside their process, with no OS interface, host routes, root privileges, or separate VPN client. The gateway side uses an ordinary WireGuard peer. On the devserver, add --tunnel-wireguard /absolute/path/to/devserver.conf to the command above, or set CHAN_TUNNEL_WIREGUARD; the tunnel URL and PAT are still required.

In the desktop launcher's Add or Edit gateway form, set WireGuard file to the desktop's wg-quick file, using an absolute path or ~/. The file takes effect as soon as you save: changing the path starts the new tunnel, and clearing it ends the old one. Its HTTP requests, window feed and webviews reach destinations in the configured AllowedIPs through WireGuard; other destinations connect directly. Browser sign-in uses your system browser, which needs its own network access to the gateway's identity URL.

The file has one [Interface] with PrivateKey, Address and optional MTU, and one [Peer] with PublicKey, Endpoint, AllowedIPs and optional PresharedKey and PersistentKeepalive. OS settings (DNS, Table, FwMark, ListenPort), hooks (PreUp, PostUp, PreDown, PostDown), SaveConfig, unknown keys and additional peers are refused. On Unix, remove all group and other permission bits with chmod 600 FILE; Windows ACLs are left to the user.

The devserver manual has the command example. The chan-wireguard design describes the peer, TCP stack and desktop proxy.
