01 / CONNECT

Install there. Connect here.

  1. 01

    Install Chan on the remote machine.

    Use the CLI installer. The examples below use a Unix host and ~/.local/bin/chan.

  2. 02

    Add it in Computers.

    Choose Add devserver, set a name, then copy the Address and Connect script from either example below. Replace user@host with your ssh destination.

  3. 03

    Connect and open a terminal.

    The script runs in a control terminal. join starts or attaches to the devserver; keep the script running to hold the tunnel. Enable Auto-hide control terminal on success to tuck it away.

A direct connection.

Connect script
ssh -L localhost:9901:127.0.0.1:8787 user@host \

ETERNAL TERMINAL

Reconnect across interruptions.

Address (URL)
http://localhost:9901
{{copyButton}}
Connect script
et --tunnel 9901:8787 \
  --command '~/.local/bin/chan devserver join --port 8787' \
  user@host
{{copyButton}}
LOCAL TUNNELlocalhost:9901
REMOTE DEVSERVER127.0.0.1:8787

Install ET on both ends. It uses ssh to establish access and its own TCP connection, normally port 2022, to reconnect after interruptions. See the ET setup guide and command reference.

These are alternative configurations for the same address. The URL's port 9901 matches the local end of the tunnel; its remote end 8787 matches --port 8787. For another simultaneous connection, choose a free local port and update both the URL and the tunnel mapping. Remote in the manual →

cs tunnel

Forward a remote service to your desktop. In one remote Chan terminal, keep this running:

cs tunnel 8080
{{copyButton}}

In another remote pane, serve the current directory with Python 3:

python -m http.server 8080 \
  --bind 127.0.0.1 --directory .
{{copyButton}}

Open http://127.0.0.1:8080 in your desktop browser. Chan forwards desktop port 8080 to port 8080 on the remote host. Keep both commands running; Ctrl+C in the tunnel pane closes the forward.

Requires Chan Desktop. Through a gateway, use the devserver owner's desktop connection.

03 / SHARED SESSIONS

One host. Multiple participants.

Chan's workspace protocol coordinates presence, document and drawing updates, and leadership across connected windows. Each client reaches the same devserver through its authorized connection.

cs session list

List this server's clients across terminal and workspace windows.

cs session self --name "laptop"

Name this client and its workspace participant.

cs session info CLIENT_ID

Inspect a client's windows, terminals, and connections.

cs session detach CLIENT_ID

Disconnect that client while keeping terminals and saved layouts. It can explicitly reconnect.

cs session handover

Request session leadership. The current leader answers with cs session handover --accept or --reject.

cs session takeover

Take leadership when the leader is gone. --force also permits taking over from a live leader.

Client IDs come from cs session list; session leadership belongs to windows. If a shell has multiple viewers, self asks you to identify your client. See Collaboration in the manual. For account-based access and devserver sharing, set up a gateway.
