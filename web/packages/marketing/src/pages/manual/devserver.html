A devserver

A devserver is chan running headless on another machine, in a VM, or beside your desktop. It holds terminals, windows and workspaces, and keeps them running while no one is connected.

Your computerRun the devserver
macOSIn a Lima VM, or on a remote machine over ssh.
WindowsNatively with the x64 CLI, in WSL, or on a remote machine over ssh.
LinuxOn the same machine with its own chan home, in a Docker container, or on a remote machine over ssh.

What you can do

  • Install chan on a headless machine with one command.
  • Run the devserver as a service that comes back at login or boot, or in the foreground.
  • Print its URL and token, and rotate the token if it leaks.
  • Read what the running devserver costs: CPU, memory, traffic and disk.

Install chan on the machine

On macOS or Linux:

$curl -fsSL https://chan.app/install.sh | sh{{copyButton}}

On FreeBSD:

$fetch -o - https://chan.app/install.sh | sh{{copyButton}}

On Windows x64, from PowerShell:

PS>irm https://chan.app/install.ps1 | iex{{copyButton}}
  • The Unix installer writes ~/.local/bin/chan and links cs to it.
  • The Windows installer adds %LOCALAPPDATA%\chan-cli\bin to your PATH.
  • Packages for Nix, Homebrew, Ubuntu, Fedora and Arch, and a Docker image, are on the install page. Install chan, not chan-desktop, on a headless machine.

Start and stop it

$~/.local/bin/chan devserver start{{copyButton}}

This installs the devserver as a background service on 127.0.0.1:8787 and returns. On Windows, open a new terminal and run chan devserver start.

chan devserverWhat it does
runRuns in this terminal until Ctrl+C.
startInstalls the service, enables it at login or boot, and starts it. Safe to run again.
stopStops the service and disables it, so it does not come back at the next login or boot. Its terminals end.
restartRestarts the service on the current chan binary, at the same address.
statusPrints the service's state and, in a terminal, its URL with the token.
join, rotate-tokenSee The token.
SystemThe service runs under
Linuxsystemd, as a user service. It survives logout once lingering is on: chan turns it on, or asks you to run sudo loginctl enable-linger. systemd integration covers restarts and upgrades that keep every terminal running.
macOSlaunchd, as a user agent that runs while you are logged in.
Windows, FreeBSDchan's own background daemon.

To choose another, put --service=chan, systemd, launchd or none after the action. --bind and --port change the address.

Listening on the network

--bind 0.0.0.0 listens on every interface. A devserver speaks plain HTTP behind its token, with no TLS, so bind it only on a network you trust and reach it over ssh everywhere else.

The token

Every request to a devserver carries its bearer token, kept in ~/.chan/devserver/config.json and the same across restarts. run, start and join print it with the URL:

chan devserver: listening on http://127.0.0.1:8787/?t=Zr8mT2xQwN6vLb3HcY5dKp7sJf9aGe4u
CHAN_DEVSERVER_TOKEN=Zr8mT2xQwN6vLb3HcY5dKp7sJf9aGe4u
CommandUse it to
chan devserver statusPrint the URL with the token, to open the devserver in a browser. Add --url to print it through a pipe.
chan devserver joinStart the service if it is down, print the token, and stay attached until Ctrl+C, which leaves the service running. Connect scripts use it: Chan Desktop reads the token line, so you never copy it.
chan devserver rotate-tokenMint a new token when you suspect a leak, and print it with the new URL. A running devserver drops the old token at once.

A token also rotates by itself at the first start after it turns 30 days old. After a rotation, reopen browser tabs at the new URL; a connect script picks the new token up at the next connect.

See what it costs

chan metrics, on the devserver's machine, prints the running devserver's own readings, the ones on the Dashboard's Metrics slide: version and uptime, CPU, memory and I/O, chan's traffic, transfers and tunnels, and the size of the chan home. It never starts a devserver.

chan metricsPrints
(no flag)The readings, once.
--jsonOne JSON document. --history adds the samples the devserver keeps.
--watchThe readings again about once a second, until Ctrl+C.
--url URLThe readings of another chan server, by a URL it printed, such as the one from chan serve.

chan metrics --help has examples, and docs/metrics.md is the reference.

Details and limits
  • restart and join without --bind or --port keep the running service's address.
  • --service=none works only with run; systemd and launchd need one of the other actions.
  • On a Linux machine with no systemd, the default choice fails and points at --service=chan.
  • For a second, isolated devserver on one machine, give it its own CHAN_HOME, a --port and a private XDG_RUNTIME_DIR. CHAN_HOME takes the place of ~/.chan, token and workspace list included.
  • A foreground devserver with the default environment shares ~/.chan with Chan Desktop, and a workspace the desktop serves shows as Locked.
  • status builds the URL from the token on disk; a devserver still running with another token refuses it.
  • With no devserver running, rotate-token rewrites the token on disk, and a devserver running elsewhere keeps the old one until it restarts.
  • A URL with a LAN address leaves its token readable in the terminal that printed it.
  • A reading the platform cannot give prints as n/a, never as zero.
  • The Windows installer writes chan.exe, cs.cmd and a Git Bash cs into that folder.
  • The CLI's calls to its own devserver skip HTTP proxies and need no NO_PROXY entry; on Linux, a call that carries the token first checks that the listener is yours.
