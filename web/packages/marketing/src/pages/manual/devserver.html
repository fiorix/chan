Chan Devserver

The devserver runs chan on another machine for remote development. It can also run locally with a separate CHAN_HOME to isolate its state. Chan Desktop connects to the devserver as the client shell; sessions, window layouts, and terminals all live on the devserver.

Pick where to run it:

  • On macOS: a lima-vm, or a remote machine via ssh.
  • On Windows: the native x64 standalone CLI, a WSL sandbox, or a remote machine via ssh.
  • On Linux: an isolated devserver on the same machine (all platforms support CHAN_HOME=/path), a docker container, or a remote machine via ssh.

Install on the host

On macOS, Linux, or FreeBSD, install chan:

$curl -fsSL https://chan.app/install.sh | sh {{copyButton}}

On native Windows x64, run this from PowerShell:

PS>irm https://chan.app/install.ps1 | iex {{copyButton}}

The Unix installer writes ~/.local/bin/chan and the symlink cs -> chan. The Windows installer writes chan.exe, cs.cmd, and a Git Bash cs shim under %LOCALAPPDATA%\chan-cli\bin and adds it to your user PATH.

Start the devserver

$~/.local/bin/chan devserver start {{copyButton}}

In a new native Windows terminal, use chan devserver start.

This installs the devserver as a background service listening on localhost:8787, using the default service manager for your platform:

  • On Linux it uses systemd: a user-scoped service that survives logout once linger is on (chan enables it, or asks you to run sudo loginctl enable-linger).
  • On macOS it uses launchd: the service runs while you are logged in.
  • On Windows it uses chan's own daemon mode, which works on all platforms.
  • You can override the choice with --service=[auto,none,chan,systemd,launchd]. The actions are start, stop, status, restart, and join; --service goes after the action.
  • chan devserver run runs in the foreground.
  • chan devserver ls, connect, disconnect, and forget manage the desktop's connections to remote devservers. A connected devserver's workspaces are managed from a terminal on your desktop too: chan workspace serve /path --on NAME, chan close /path --on NAME, and chan workspace forget /path --on NAME, where NAME is the devserver's label or URL as chan devserver ls shows it and the path is on that machine.

Connect from the main window

Now add the devserver to Chan Desktop:

  1. Open the Computers screen (Cmd+P on macOS, Ctrl+Shift+P on Windows and Linux), turn to the last card, and click Add devserver.
  2. Fill in Name, Address, and Connect script. Examples:
    • lima-vm from macOS:
      • Address: localhost:8787
      • Script: limactl shell default ~/.local/bin/chan devserver join
    • WSL from Windows:
      • Address: localhost:8787
      • Script: wsl ~/.local/bin/chan devserver join
    • Remote machine via ssh:
      • Address: localhost:9901
      • Script: ssh user@host -L 9901:localhost:8787 ~/.local/bin/chan devserver join
  3. Optionally tick Auto-hide control terminal on success so the terminal running the connect script hides itself once connected.
  4. Click Add devserver. The new devserver's card comes to the front; click Connect on its header, or press c.

Connect through a gateway

A gateway reaches your devservers, and devservers shared with you, through its tunnel instead of a connect script. Press g on the Computers screen, or click its title, to flip to the Gateways screen, then:

  1. Turn to the Add gateway card and enter the gateway's URL (https://...) and an optional name.
  2. Click Connect on the gateway's card, or press c, and sign in in your browser. One sign-in covers the whole account.
  3. Flip back to Computers with g: the gateway's devservers are listed there, each marked "via" the gateway.

Open remote terminals and workspaces

A connected devserver's card offers New terminal (t). Its registered workspaces appear on the card; open a workspace window from its row with New window (w). The command launcher's Computers scope does the same from any window on that devserver.

Once connected, remote terminals and workspaces behave like local ones: run chan open {path} in a devserver terminal to create a workspace on that machine, or chan workspace serve {path} --on NAME from a terminal on your desktop. Disconnecting keeps the remote sessions alive and running; reconnect and pick up where you left off.

The clipboard and file transfer work across the connection too: see Copy and paste freely and Download and upload freely on the Terminal page.

On Linux devservers managed by systemd with fdstore support, you can restart the devserver process without losing your shells: the PTY file descriptors are parked in the systemd fdstore while the devserver restarts, then loaded back up, so your agents continue working and your terminals are always alive.
