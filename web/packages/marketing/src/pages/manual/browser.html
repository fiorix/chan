What you can do

  • Serve one workspace to any browser with chan serve --standalone, without Chan Desktop.
  • Use chan on a server or a VM through an ssh port forward.
  • Open a devserver's Computers screen in a browser, and its windows in tabs.
  • Hide a window, close its tab, and find its terminals still running later.

Chan without the desktop

The chan binary carries the whole UI. Install the CLI on the machine, then pick a way in:

Way inYou getIt lasts
chan serve --standaloneOne workspace window.While the command runs in the foreground.
A devserverThe Computers screen: terminal windows and as many workspaces as you add.As a background service, whether or not anyone is connected.

Serve a workspace

$cd ~ && chan serve --standalone ./notes{{copyButton}}
chan is ready:
http://127.0.0.1:8787/?t=Zr8mT2xQwN6vLb3HcY5dKp7sJf9aGe4u

It creates notes if needed, serves it on 127.0.0.1:8787, opens your browser on the URL, and runs until Ctrl+C. Without --standalone, chan serve hands the workspace to a running Chan Desktop or devserver: see Workspaces.

The URL is the key

The ?t= part is the workspace's token: anyone with the URL who can reach the port can use the workspace, terminals included. It stays the same across restarts, so a bookmark keeps working.

FlagWhat it does
--port 9000Serves on another port. The default is 8787.
--no-browserPrints the URL without opening a browser, for a machine without a desktop.
--hereServes a subdirectory of a Git, Mercurial, or Subversion repository. Without it, chan serve refuses one and asks for the repository root, because links, the graph, and search follow the project.
--host 0.0.0.0Listens on every interface. See the warning under Serve from another machine.
--timeout 1hShuts the server down after this long idle. Takes 30s, 5m, 1h.
--no-settingsRefuses settings changes, for a shared or demo machine.
--no-tokenDrops the token. Never use it on a shared machine.

Work in the browser

The URL opens a workspace window, with panes and tabs as on the desktop. Open a terminal from the pane menu and try:

$echo '# Hello' > hello.md && cs open hello.md{{copyButton}}
  • The shells live in the server, not in the tab. Reload or reopen the URL and your terminals are still running, with their scrollback.
  • A second browser on the same URL joins one shared session.

Serve from another machine

The server listens on loopback only. Forward its port over ssh, run chan serve --standalone --no-browser ./notes in that session, and open the printed URL on your computer:

$ssh -L 8787:127.0.0.1:8787 user@host{{copyButton}}

The workspace stays up while ssh and the command run; a devserver keeps it up for good.

Listening on the network

--host 0.0.0.0 listens on every interface, and chan serve warns when it does. chan has no TLS, so the token and everything you type travel in plaintext. Prefer an ssh forward.

A devserver in the browser

A devserver is the same server as a background service, holding terminal windows and many workspaces. Start one, then print its URL, which carries its token:

$chan devserver status{{copyButton}}

On a remote machine, forward a port as in Serve from another machine.

  • Search, the graph, and agent teams need a workspace window.

Add a workspace

In a devserver terminal, chan open registers the directory with the devserver:

$chan open ~/notes{{copyButton}}
chan: opened a window for /home/user/notes with local devserver on port 8787 (library /home/user/.chan, chan {{version}})

It appears under Workspaces. New workspace on the card does the same from the browser.

On a workspace rowWhat it does
New windowOpens another window of the workspace.
New terminal windowOpens a window of the workspace that starts with a terminal.
Turn off, Turn on (the power button)Off unmounts the workspace: its index and windows are kept, and its terminals end. chan asks first when any are running.

Hide and show windows

Windows outlive their browser tabs. Start a build or an agent, hide its window, and check on it later from any computer.

You doThe window and its terminals
Hide windowKeep running. The tab shows a cover saying the window is hidden; close the tab.
Show windowCome back, in the old tab or a new one.
Close the tab of a shown windowThe window closes and its terminals end. Hide it first to keep them.

When several pages show the same Computers screen, only the session leader's page shows, hides, and opens a workspace's windows.

Details and limits
  • To upgrade a devserver, run chan upgrade, then chan devserver restart. On Linux under systemd, terminals survive the restart; elsewhere they end, and workspaces, windows, and layouts come back.
  • If Open window opens nothing, the browser blocked the pop-up: allow pop-ups for the page.
  • If port 8787 is taken on your side of an ssh forward, forward another, such as -L 9901:127.0.0.1:8787, and change the port in the URL to match.
  • A terminal window's Dashboard shows the metrics and About only.
  • In a browser the Computers screen has no All windows or Add devserver card, and no keyboard letters.
  • chan devserver rotate-token replaces a devserver's token at once; reopen any tab that used the old URL. The token also rotates on its own at the first cold start after it turns 30 days old.
  • A standalone server's token is kept under ~/.chan.
  • On Windows, a Chan Desktop that is still starting cannot take a workspace; chan serve says so and serves it itself.
  • A chan installed apart from Chan Desktop may not find a Chan Desktop of another release, and then serves the workspace itself. The chan that Chan Desktop installs is always of its release.
  • When Chan Desktop serves a workspace, chan close or chan workspace forget may answer workspace is still releasing; retry. The workspace is off and its cleanup continues; run the command again once it finishes.
  • On the first run on a workspace, chan serve says the search index builds in the background; the editor and terminal work at once.
  • --prefix /team/alice mounts the server under a URL path, so one host behind a reverse proxy can carry several.
  • The Linux build is statically linked, so the same binary runs on any distribution. Check it with chan --version.
