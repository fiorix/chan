Read the dashboard

Run New dashboard from the command launcher or the pane menu, or cs dashboard from a terminal; in Hybrid Nav, b stages one. Its carousel opens on Metrics, the first slide, followed by Workspace with workspace information and reports, Search with the indexing view, and About with the version and project credits. A terminal window has no workspace, so its Dashboard has Metrics and About. A control terminal and a tmux window's panes draw no tab strip and take no Dashboard.

Use the arrows to change cards and the pause control to stop rotation. Hovering or focusing the carousel pauses it while you read. From a terminal, cs dashboard --carousel-off opens it without automatic rotation.

Watch the server process

Metrics shows the chan process that serves the window: Chan Desktop for its own local windows, the devserver for a devserver's windows, and chan serve for the workspace it serves. Its header names the host, the process id, and the chan version and build. Six graphs cover the last ten minutes: CPU, where 100% is one logical core, resident memory, the network receive rate with the send rate beside it, the I/O read and write rates, and running file transfers. Below them, Channels & tunnels counts the gateway tunnels, reverse listeners, and the HTTP/2, yamux, and reverse TCP channels in use, and Storage gives the size of the chan home, ~/.chan unless CHAN_HOME names another directory, with its file count.

The readings are the server process's own. The shells, agents, and other programs it started are not counted, and the network figures are chan's own traffic, not the machine's. The process samples itself once a second and keeps the last ten minutes in memory, whether or not a Dashboard is open, so a Dashboard opened later shows the minutes before it. The chan home is measured only while someone is reading, once a minute. While the first sample is pending, the cards stay in place with n/a readings and a waiting message. A reading the platform cannot give reads n/a.

If a storage scan fails, the card shows Storage scan failed with the reason. When a scan has completed before, its totals and scan time stay visible, with a note that the card is showing the last completed total. If no scan has completed, the sizes and file count read n/a and the time reads Scan pending. A failed scan does not turn an unknown size into zero.

With privacy mode on, the slide hides the host name, the chan home path, and storage scan errors that may name files, each behind its own reveal button; see Open settings. From a shell, chan metrics prints the same readings; see Start the devserver.

Under the hood: docs/metrics.md says what each reading counts, what each platform reports, and how to read the metrics over HTTP.

Follow the index

Each workspace maintains its own index, kept separately from the project files. The index makes workspace content searchable and supplies document relationships to the graph. The dashboard's indexing view shows directory progress: indexed, indexing, or pending. While indexing is underway, a search may not yet include every file.

Open Settings → This workspace for index controls, excluded directories, code reports, and semantic search. The index follows included workspace files as they change; chan respects ignore rules and configured exclusions. Drafts enter the project index only after you save them into the workspace.

Under the hood: crates/chan-workspace/design.md describes the index, the graph and where chan keeps them.

Semantic search

Lexical search is available by default. Semantic search is optional and off by default; enable it in Settings → This workspace, select a model, and allow the model download and embedding work to finish. Settings → Search controls the indexer's resource profile: Conservative, Balanced, or Aggressive.

Code reports are enabled by default and maintained separately from semantic embeddings. Check indexing and report status here when a search, graph, or file report is missing information.
