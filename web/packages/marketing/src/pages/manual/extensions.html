What you can do

  • Add a tool of your own as a tab, written in any language that can serve a web app.
  • Open it from New tab in the command launcher, on this machine or a devserver, over the same connection as the rest of the workspace.
  • Run its commands from the command launcher, and bind them to shortcuts.
  • Let its backend drive chan through cs.

Your tools as tabs

  • An extension is a separate program serving a local web app. chan starts it, passes its traffic through chan's own connection, and lists it under New tab.
  • It runs on the machine serving the workspace, a devserver included. Its tab works over ssh or a gateway, like the rest of the workspace.
  • The tab is sandboxed: it cannot read the window's page, storage or token. The program itself has the access of any program you run.
  • An extension tab needs a workspace window.

Configure an extension

  1. Install it

    Follow the extension's own instructions. Its installer writes a declaration to <chan-home>/extensions/<id>.toml, normally under ~/.chan/extensions/.

  2. Check the declaration

    It names the tab, the command to run, its arguments, and the host capabilities it asks for.

    name = "Echo test"
command = "/absolute/path/to/chan/target/debug/examples/echo-extension"
args = []
capabilities = []

  3. Restart the serving process

    Restart the chan process that serves the workspace, such as Chan Desktop or the devserver, after installing or changing a declaration.

  4. Open it

    Run its name from New tab in the command launcher.

A declaration runs a program as your user. Treat every file in the extensions directory with the care you give a shell profile.

Build your own

  1. Serve a web app on loopback, from any language.
  2. Print chan's startup handshake on stdout.
  3. Write a declaration and restart the serving process.
  4. Connect the frontend through the host bridge, which carries declared commands, keyboard shortcuts, and, if asked for, session context or presentation.
  5. Drive chan from the backend with cs, the same commands you run in a terminal.

The extension authoring guide covers the handshake, the sandbox, the lifecycle and a working example. The configuration reference lists the declaration's fields.

Details and limits
  • chan starts each extension once per serving process, so a devserver with many workspaces runs one copy.
  • A declaration that does not parse, or a program that fails to start or to hand-shake, is logged and skipped. chan still starts.
  • An extension that exits stays down until the serving process restarts; its tab says it is unavailable.
  • chan stops every extension together when it shuts down. They share one three-second grace period, so more extensions do not add more waiting.
  • An extension inherits the serving process's environment and PATH. For a devserver run as a service, run chan devserver restart from a plain shell that has the PATH the extension needs.
  • chan has no marketplace and no installer: each extension's repository ships its own.
