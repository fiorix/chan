What you can do

  • Search a workspace's text, ranked by relevance, with a snippet of each match.
  • Find files, images, contacts, tags and mentions by name in the same list.
  • Type a path to walk the tree, or language:Rust to list a language's files.
  • Go from a tag or a mention to the graph, with it selected.
  • Query, browse and walk the same index from a terminal with cs search, without opening a tab.

Search the workspace

Search opens over the window. Each workspace has its own index, so search needs a workspace window.

Search from a terminal

cs search asks the workspace of the terminal it runs in and prints the result as Markdown. It changes nothing and opens no tab.

$cs search retry backoff{{copyButton}}
FormDoesExample
QUERYSearches content, and every kind of entity by name.cs search retry backoff
--domain KINDLimits the results to one kind. With no query, lists every entity of that kind.cs search --domain tag
--from TYPE:VALUEWalks the graph from one exact entity, one hop unless --depth says more.cs search --from file:notes/design.md --depth 2
--edge-kind KINDKeeps one kind of relationship: link, tag, mention, language or contains.cs search --from tag:design --edge-kind tag
--directionout, in or both. By default a walk goes out from a directory and both ways from any other seed.cs search --from file:a.md --direction in
--json, --prettyPrints the result as JSON, indented with --pretty.cs search --from language:Rust --edge-kind language --json --pretty

A selector is TYPE:VALUE. --domain takes the same six types, plus content.

SelectorValueA walk from it counts --depth in
file:notes/design.mdA path from the workspace root.Hops of links, tags and mentions, in both directions.
tag:designThe # is optional; case does not matter.Hops, in both directions.
mention:alexThe @@ is optional.Hops, in both directions.

Each node a walk reaches comes with its directories up to the root, and each file with its tags, mentions and language: what the graph shows with that entity selected at the same depth.

Details and limits
  • A file added a moment ago is found once the index reaches it; the Dashboard shows indexing progress.
  • A search with no matches while the index is being built reads still indexing - results will fill in. During a rebuild of the index, content search pauses until it finishes.
  • The search panel shows one content row per file and up to 25 of them, and up to eight name matches of each kind.
  • With semantic search on, content is ranked by relevance and meaning together.
  • The graph also joins a symlink to its target and the names of a hardlinked file; a walk follows neither.
  • cs search prints sections named Content, Entities, Graph, Warnings and Errors. A request with structured errors prints them and exits nonzero.
  • Defaults and caps: --limit 20 (at most 100), --node-limit 100 (1000), --edge-limit 250 (2500), --depth at most 10. A larger value is clamped, with a warning.
  • A contact or mention selector that matches more than one entity fails; the JSON error lists the candidates.
  • In a standalone terminal cs search refuses: it needs a workspace window.
  • From any shell, chan workspace search takes the same flags, with --workspace naming a workspace or --all-workspaces.
  • cs search --help has the full rules.
