Install

Chan Desktop is the place to start: a small binary that bundles the terminal emulator and the workspace UI. Grab it for your platform from the install page.

On a Mac, Chan Desktop requires macOS 14 (Sonoma) or later. The app updates itself; an update whose published minimum macOS version is above the running version is refused, leaving the installed app in place. Update macOS before installing that update.

On FreeBSD, Chan Desktop builds from source; there is no package to download. Install the toolkit and the build tools:

#pkg install git rust npm gmake pkgconf webkit2-gtk_41 {{copyButton}}

Then, as your user, build the web bundles and the desktop from a chan checkout:

$git clone https://github.com/fiorix/chan && cd chan {{copyButton}}
$gmake web && cargo build --release -p chan-desktop {{copyButton}}

The web bundles' build tools ship native code for FreeBSD on amd64 only. On arm64, run make web in a checkout on a Linux or macOS machine, copy its web/dist and web-launcher/dist into the FreeBSD checkout, and run only the cargo build.

Run target/release/chan-desktop from an X11 or Wayland session. A source build does not update itself: pull and build again to upgrade.

Default terminal on Linux

Linux desktops that open terminals through xdg-terminal-exec, such as Omarchy, can open them in Chan Desktop: the terminal key binding, TUIs, and installer scripts alike. The Arch, Ubuntu, Fedora, and Nix packages install the desktop entry this needs, chan-desktop.desktop. The AppImage's entry lacks its terminal keys, so the AppImage cannot be chosen.

xdg-terminal-exec runs the first valid entry in ~/.config/xdg-terminals.list. Make Chan Desktop that entry:

$echo chan-desktop.desktop > ~/.config/xdg-terminals.list {{copyButton}}

This replaces the list, as Omarchy's terminal picker does; list other terminals on the lines below it to keep a fallback. A list named for your desktop, such as ~/.config/hyprland-xdg-terminals.list, takes precedence when it exists.

Check the choice. This prints chan-desktop.desktop:

$xdg-terminal-exec --print-id {{copyButton}}

Then open a shell in your home directory, and a program in a window of its own:

$xdg-terminal-exec --dir="$HOME" {{copyButton}}
$xdg-terminal-exec --app-id=TUI.float -e top {{copyButton}}

How Chan Desktop takes each launch:

  • A launch with no command, like Omarchy's Super+Return, opens your shell in the directory --dir names, or in the current one. When Chan Desktop is running, the shell opens in a new terminal window of the running app, one that is not restored at its next launch. Otherwise a launch with --dir opens a window of its own, and a launch with no options at all starts Chan Desktop.
  • A launch with a command runs it in a window and process of its own, apart from a running Chan Desktop, and exits with the command's exit code when it ends. --hold keeps the window open after the command exits, until you close it. A command that is not on your PATH exits with status 127 and opens no window.
  • --app-id sets the window's Wayland app id, or its X11 class, so compositor window rules can match it: Omarchy floats TUI.float. --title sets the window title. Either one also gives the launch a process of its own.

xdg-terminal-exec maps its options onto Chan Desktop's own flags, which also work directly: chan-desktop [--dir=PATH] [--app-id=ID] [--title=TITLE] [--hold] [-e CMD ARGS... | -- CMD ARGS...].

First run: a terminal and the Computers screen

Chan Desktop opens a standalone terminal window on first launch. Your machines, workspaces, and windows live on the Computers screen, which slides in over the window you are in:

  • On macOS, choose View → Toggle Launcher or press Cmd+P.
  • On Windows and Linux, press Ctrl+Shift+P. The menu bar, with the same View item, shows while the Computers screen is open.
  • Press the shortcut again, or Esc, to return to the window.

The Computers screen is a carousel of cards. Turn it with the arrows at its sides or the Left and Right keys:

  • All windows, the first card, lists every window on every machine, shown or hidden.
  • This machine has two buttons: New terminal opens a standalone terminal window, and New workspace registers a directory as a workspace. Its terminals and workspaces are listed below them.
  • Each devserver you add gets its own card, and Add devserver is the last card. See Connect from the main window.

The screen works from the keyboard too; see Windows and the Computers screen.

Chan Desktop runs once per user: starting it again while it is running opens no second copy. On Linux, a second start from the app menu, or chan-desktop with no options in a shell, opens a new terminal window in the running app, one that is not restored at its next launch. On Windows, and wherever the running app does not take the start as a terminal, it brings the running app forward instead: its last focused window is raised, out of the taskbar if it was minimized, or a terminal window opens when no window is shown or about to be. On Windows, a start while the running app is still starting waits for it, up to thirty seconds, and then brings it forward. On macOS, the Dock icon of the running app brings it forward, and opens a terminal window when no window is shown. A start while the running app is quitting waits for it to exit and then starts normally; after twenty seconds of waiting it gives up, opens nothing, and shows a message saying Chan is still shutting down. If the running app does not respond at all, a second start opens nothing either and, within ten seconds (on Windows, forty when the running app never finished starting), shows a message saying Chan is not responding. To start again, quit the running app, or end it if it does not quit (Force Quit on macOS, Task Manager on Windows, the chan-desktop process on Linux), then start Chan Desktop. Started from a terminal, either start prints the reason there instead of showing the message; both exit with status 1.

Workspaces

A workspace is a directory that chan treats as a project:

  • The content is indexed for search.
  • Markdown files get autocompletion for linking to each other.
  • chan builds a project graph from the links, tags, and mentions in your documents, plus language and size stats for the code.
  • Each workspace keeps its own set of windows, panes, and tabs.

Any directory can become a workspace. For a first try, start from an existing git repo. In a chan terminal:

$cd /path/to/your-project {{copyButton}}
$chan open . {{copyButton}}

chan open is the workspace-opening alias of chan serve, the command that registers and serves a workspace. Inside a repository, chan expects its root. To open a subdirectory inside one, add --here.

chan open {path} works anywhere chan runs: in a local terminal it registers the workspace on this machine (the same thing the New workspace button does), and in a devserver terminal it registers the workspace on that devserver, which then shows up under the devserver's card on the Computers screen.

Back on the Computers screen (Cmd+P on macOS, Ctrl+Shift+P on Windows and Linux), the new workspace appears on This machine's card with its power toggle On: the workspace is alive, indexed, and keeping the state of your windows, panes, and tabs. Click New window of your-project and the real power of chan begins:

  • The pane's hamburger menu lists the built-in apps: dashboard, diagram, draft, file browser, graph, slide deck, team, and terminal.
  • The command launcher (Cmd+K on macOS, Ctrl+Alt+K on Windows and Linux) works here too, with the workspace's commands first. Its Computers scope reaches everything on the same machine: a new terminal, a new window of any of its workspaces, and every window to focus, show, hide, or close. See The command launcher.

You can quit and reopen Chan Desktop and your windows and layouts are restored. Local terminals keep their layout, but their shells are restarted.

Everything you can do in Chan Desktop, standalone terminals and workspaces alike, also works on a remote machine through Chan Devserver.

Under the hood: design.md describes what a workspace is made of and how it is served, and crates/chan-workspace/design.md the core behind it.
