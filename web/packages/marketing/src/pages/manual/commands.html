chan

chan serves workspaces, runs devservers and changes chan's settings, from any shell. Add --help to any command for its flags and examples.

A prefix that names one command is enough, at every level: chan w ls is chan workspace ls, and chan de status is chan devserver status. A prefix that fits two commands, such as s for serve and shell, is refused.

chan serve flags

Workspaces explains --standalone, --desktop, --devserver and --on. Chan in a browser explains --port, --host, --no-browser, --here, --timeout, --no-settings and --no-token. The rest:

FlagWhat it does
-4, --ipv4Listens on IPv4 only, on 127.0.0.1 unless --host names another IPv4 address.
-6, --ipv6Listens on IPv6 only, on ::1 unless --host names another IPv6 address.
--search-aggression LEVELSets how hard the indexer works for this run: conservative, balanced or aggressive. It overrides Settings → Search → Search indexing.
--prefix /team/aliceServes under a URL path, so a reverse proxy can put several servers on one host. Each segment takes letters, digits and -.
Details and limits
  • Only a server the command binds itself can enforce --no-settings, so a serve that would hand the workspace to Chan Desktop or a devserver is refused. Add --standalone.
  • --timeout takes a whole number with s, m or h, such as 30s; zero is refused.
  • --devserver=PORT also takes a URL on this machine, such as --devserver=http://127.0.0.1:9999, always with =. A URL of another host is refused.
  • --on NAME takes no other serve flag, and its PATH is a path on that devserver.
  • -4 or -6 with a --host of the other kind is refused.
  • chan serve takes a path only; a URL is refused with a pointer to chan devserver register.
  • A path inside a Git, Mercurial or Subversion working tree exits with status 70. See Troubleshooting.
  • chan close and chan workspace forget exit with status 75 while a workspace is still releasing; run them again.
  • -v, -vv and -vvv raise logging on every command. chan --version prints the release and the build.

cs

cs runs inside a chan terminal and drives the window it runs in: it opens files, terminals and panes, writes to and reads other terminals, and reports a program's status on its tab. chan shell is the same command, and prefixes work the same way: cs te l is cs terminal list.

Details and limits
  • Chan Desktop repairs the names it wrote in ~/.local/bin when they go stale, and leaves alone a name you put there yourself.
  • The chan that Chan Desktop installs hands a workspace to Chan Desktop, and its chan upgrade updates Chan Desktop.
  • The chan-term, chan-files and chan-edit of the chan packages cannot start Chan Desktop; see Standalone.
