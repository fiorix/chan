Open a graph

Open Graph from the command launcher to explore the workspace. Use Graph from here in a file or directory's Details to open the graph with that file or directory selected. The terminal equivalents are:

$cs graph {{copyButton}}
$cs graph src {{copyButton}}

There is one graph: the workspace's directory structure, growing up from the workspace root, with the relationships from documents drawn over it, including links, tags, and mentions, and languages connecting source files through the code reports. A tag, a mention, a contact, or a document is a selection in that graph, not a graph of its own: selecting one shows what refers to it and what it refers to, each on its directories. Select a node to read its Details and follow the actions there.

Navigate directories like a browser

Use the directory graph as a visual file browser: select a directory to inspect it, and double-click a directory node to open or close it. Graph from here opens a new graph tab with that node selected; a directory arrives opened, deep enough to show its files.

The breadcrumb in Details shows the path of the selected file or directory. Click an ancestor to select that directory in the same graph tab, or workspace to select the root. The directories you opened stay open as the selection moves.

The tree's own edges are grey. A symlink is joined to its target by a cyan edge, dashed when the target is missing, and the names of a hardlinked file are joined to each other in lime. Select a symlink to read where it points in Details, including a target outside the workspace. The graph finds symlinks and hardlinks by reading the tree from disk: the first six levels below the workspace root, up to 10,000 entries, and each directory that was open when the graph tab loaded. A symlink or hardlink outside both can be drawn without its edge; Reload graph in the command launcher reads the directories open now. A file given a second name in another directory is joined to it once its own directory changes. A directory git ignores that the graph still draws, such as an ignored out/, is drawn as the tab last read it, since the workspace reports no change inside it; the tab reads it again at Reload graph or whenever it reads its whole tree again, as after a branch switch that rewrites much of it. Directories the workspace excludes, by default node_modules, build, dist and target among others, are not drawn at all.

Use depth for a wider view

Open the graph tab's menu and move Depth. The depth belongs to the selected node. With a directory selected it is how many levels are open below that directory: raise it to open more, lower it to close them, down to zero to close the directory itself. For a view of the whole repository, select the workspace root and increase depth. The rest of the tree stays as you left it.

With a document, a tag, a mention, or a contact selected, depth is how many hops of references to follow from it, in both directions. It starts over at one each time you select another node. What a selection shows this way leaves again when the selection moves, unless its directory is open. A language always shows its files, and the control marks its maximum when there is nothing further to reveal.
