What you can do

  • See a workspace as one tree, its root at the bottom, with the links, tags, mentions and languages of its files drawn over it.
  • Select a file, tag, mention, contact or language to see what refers to it and what it refers to.
  • Open and close directories in place, as in a file browser.
  • Raise the depth to open more levels below a directory or follow more hops of references.
  • Hide kinds of nodes, and copy a link that opens the same view again.

Open a graph

A graph tab needs a workspace window. Every graph tab draws the same graph; opening one on a node opens it with that node selected.

A tag, mention, contact or language is a selection in the graph, not a graph of its own. Selecting one lights what refers to it and what it refers to, each on its directories, and dims the rest.

Use depth for a wider view

Depth belongs to the selected node. Move Depth in the graph menu, or run Increase depth or Decrease depth from the command launcher.

SelectedDepth is
A directoryHow many levels are open below it. Lower it to close them, down to 0 to close the directory itself. The rest of the tree stays as you left it.
The workspace rootLevels open below the root, from 1. Raise it for a view of the whole repository.
A file, tag, mention or contactHops of references followed from it, in both directions, from 1 to 6. It starts again at 1 for each node you select.
A languageFixed at 1: a language always shows its files.

The control reads [max] when there is nothing further to reveal. What hops reveal leaves again when the selection moves, unless its directory is open.

Details and limits
  • Each filter (tag, contact, language, media, folder, markdown, source) hides or shows one kind of node; all are on in a graph tab you open. The command launcher's Filters lists the same.
  • While a graph tab is focused the command launcher also has Select workspace, Copy graph link and Reload graph.
  • The status bar counts the nodes and edges shown out of those loaded, and reads indexing… while the index is not ready.
  • Selecting a symlink shows in Details where it points, including a target outside the workspace.
  • A link to a file that does not exist ends at a node whose Details says so.
  • The graph finds symlinks and hardlinks by reading the tree from disk: the first six levels below the root, up to 10,000 entries, and each directory open when the tab loaded. One outside both can be drawn without its edge until Reload graph.
  • A file given a second name in another directory is joined to it once its own directory changes.
  • A directory git ignores that the graph still draws, such as an ignored out/, is drawn as the tab last read it, until Reload graph or until the tab reads the whole tree again, as after a branch switch.
  • Directories the workspace excludes, by default node_modules, build, dist and target among others, are not drawn, nor are .git and .chan.
  • On a very large tree with hundreds of directories open, reading one level can pass the 10-second request limit. The graph then shows dimmed with the error until the next change or Reload graph.
  • cs search --from walks what the graph shows for a node, but follows neither symlinks nor hardlinks.
