What you can do

  • Open files, terminals and panes from a script.
  • Type into other terminals by name or group, and read their output.
  • Show a program's progress, or that it needs you, on its tab.
  • Read terminals and panes as Markdown or JSON.

Commands

cs, also chan shell, drives the chan window and terminals it runs in. A prefix that names one command is enough: cs te l is cs terminal list. Add --help to any command for its flags and examples.

Where cs works

cs works in every chan terminal, workspace or standalone, on the desktop, in a browser or on a devserver. It acts on the window it runs in, found from variables chan sets, and reads paths from the shell's directory on the terminal's machine.

CHAN1 in every chan terminal.

No variable tells a workspace from a standalone terminal; a workspace command refusing is the test:

cs search --limit 1 x >/dev/null 2>&1 && echo workspace || echo standalone
Details and limits
  • Outside a chan terminal, a window command refuses: not running inside a chan session; this needs $CHAN_WINDOW_ID.
  • When the server that started the terminal has gone, cs says the chan window or server that spawned this terminal is no longer running.
  • When a devserver comes back on another socket, cs looks for the one devserver serving this workspace and uses it.
  • chan sets these variables; read them, do not set them.
  • In an ssh session opened from a chan terminal, only cs terminal status and cs dump-skill work, where cs is installed.
  • A workspace command in a standalone terminal refuses with this is a standalone terminal.
  • cs window rm deletes a window and its saved layout, and refuses one with running terminals unless you add --force; a devserver's window removed from a desktop terminal gets no such check. hide keeps a window to reopen.
  • cs window list is empty under a standalone chan serve, which keeps no windows.
  • se matches both search and session, and t both terminal and tunnel, so neither is accepted as a prefix.
  • -v, -vv and -vvv raise logging.

cs terminal

Commands select terminals by name and group across the whole server, whichever window holds them. --tab-name matches every terminal with that name, --tab-group every terminal of the group, and both together match terminals with both.

  1. Open a named terminal

    $cs terminal new --tab-name build{{copyButton}}

  2. Run a command in it

    No newline is added, so end with \n to run the command.

    $cs terminal write --tab-name build $'make test\n'{{copyButton}}

  3. Read what it printed

    $cs terminal scrollback --tab-name build | tail -20{{copyButton}}
CommandExampleWhat it does
newcs terminal new src --tab-name build --tab-group ciOpens a terminal tab in this window, in a directory, with a name and group. --command runs a program instead of the shell.
writecs terminal write --tab-group ci $'git pull\n'Queues text for every match, delivered when each goes quiet. --submit AGENT also submits it to an agent; --stdin reads the text.
listcs terminal list --json | jq -r '.groups.ci[].name'Lists live terminals by group, with window, pane, agent, program status, queue and directory.
scrollbackcs terminal scrollback --tab-name build > build.logPrints one terminal's recent output, escape sequences included.
restartcs terminal restart --tab-name buildStarts the terminal again with the same name, group and window. --command and --env change what runs.
closecs terminal close --tab-group ciEnds the terminals and frees their names.
surveycs terminal survey --tab-name lead --option Merge --option Wait "Tests pass. Merge?"Shows the question over that terminal's window and prints the answer chosen.
statuscs terminal status done --msg "Tests passed"Reports program status. See Program status.
teamcs terminal team load teams/reviewStarts a team of agents. See Agent teams.
Details and limits
  • write, restart and close need --tab-name or --tab-group, so a forgotten filter cannot reach every terminal. scrollback takes a name that matches exactly one terminal.
  • Matching nothing is an error: no live terminal session matched.
  • Names need not be unique. write, restart and close reach every terminal with the name.
  • write refuses more than 4096 bytes rather than cutting it. Put long text in a file and send its path.
  • Each terminal queues up to 100 entries. A restart drops what is still queued.
  • --submit sends the submit key of the agent you name: agy, claude, codex, gemini, kimi, muse or opencode. One agent per command, so write to a group of mixed agents one terminal at a time. cs terminal list shows each terminal's agent.
  • restart and close ask no confirmation. close hangs up the terminal's program, kills it if it still runs shortly after, and fails if it outlives a 5-second wait.
  • A process that ignores the hangup or left the terminal, such as a nohup job, keeps running after close.
  • scrollback keeps a bounded tail of the output. Send it to a file or a pager, not to a live terminal, which would replay its escape sequences.
  • new queues the tab and returns; the tab appears a moment later. --pane and --side place it, and --env KEY=VALUE adds to its environment.
  • survey takes up to four --option values and waits until someone answers, picks [F] to follow up later, or dismisses it. After 600 seconds, or --timeout, it gives up and exits 124.

Program status

Programs report that they are working, blocked, done or failed with OSC 7501, the Program Status Protocol Superlogical specifies for Rex and other terminals. chan marks the tab, and Details in the tab's right-click menu lists each report. It is on by default, in Settings → Terminal → Program status (OSC 7501). From a script:

$cs terminal status working --id build --app cargo --progress 40{{copyButton}}
$cs terminal status done --id build --msg "Tests passed"{{copyButton}}
ReportIn the tabIn Details
workingThe terminal icon's prompt with a cursor being typed; with --progress, a pie in a ring that fills to the percentage.Working, with its progress.
blockedAn amber mark after the name: a shield for --kind permission, a question mark for question, a key for auth, a pause sign with no kind. It shows even while its tab is in front.Blocked, with its kind.
doneA green check while unseen.Done, seen or not.
errorA red exclamation mark while unseen.Error, seen or not.
idleNo mark.Idle.
clearThe cleared records' marks go.The cleared records go.
Details and limits
  • --kind applies to blocked only, and --progress, a whole number from 0 to 100, to working and blocked.
  • Hover a mark to read the report's state, kind, progress, app, title and message.
  • With several reports standing, the tab shows one mark: blocked over error, error over done, then the latest.
  • A done or error report is seen when it arrives while its tab is in front, or when its tab comes to the front. A seen report keeps no mark and stays in Details.
  • So a report typed at the prompt of the tab in front shows no mark. To watch one, run (sleep 5; cs terminal status done --msg Passed) & and switch to another tab within five seconds.
  • Details is also in the command launcher.
  • Each report replaces its record, optional fields included. --id gives a subprocess a record of its own instead of replacing its parent's. clear --id build removes that record and its children; clear with no --id removes them all.
  • done and error stay until replaced or cleared. working, blocked and idle end with the program that held the terminal when the report arrived, or at the shell's next prompt.
  • --sleep N writes once and waits N seconds, up to 86400, so you can look at a passing state from an interactive shell. Ctrl+C ends the wait and writes nothing more.
  • The report goes to the terminal itself, so it works over ssh in any terminal that supports OSC 7501. With output redirected and no terminal, cs sends it through chan instead.
  • A title holds up to 192 bytes and a message up to 2048.
  • cs terminal list --json carries every record and its text, marked or not.
  • chan marks a terminal the same way while a cs terminal survey, cs export or cs tunnel started there waits.

cs pane

Each pane has two sides, A and B, each a strip of tabs. cs pane changes the window it runs in, or the one given by --window or holding the --tab-name terminal. Changes show at once and survive a reload.

CommandWhat it does
cs pane listLists every pane and both its sides. Plain cs pane does the same.
cs pane new right|bottom [--pane P]Splits the active pane, or P, and prints the new pane's id.
cs pane focus P [--side a|b]Selects a pane, and one of its sides.
cs pane resize DELTA [--pane P]Grows the pane in its split by DELTA, from -1.0 to 1.0. A negative DELTA shrinks it.
cs pane equalize [--pane P]Sets the pane's nearest split to 50/50.
cs pane swap OTHER [--pane P]Swaps everything in two panes, both sides.
cs pane close [P] [--force]Closes the active pane, or P.
cs pane close-tab [--pane P] [--tab T] [--force]Closes one tab, the pane's active one by default.
cs pane close-all [--force]Closes every tab in every pane.

To put a named terminal in a new pane, keep the id new prints:

right=$(cs pane new right)
cs terminal new --pane "$right" --side a --tab-name runner
Details and limits
  • cs open, cs graph, cs dashboard and cs terminal team take the same --window, --pane and --side.
  • Pane ids look like pane-4 and hold only while the window is open. Read them from cs pane list.
  • Without --force, a close stops at unsaved files and running terminals, prints them, and exits non-zero. No dialog asks.
  • Closing the last pane clears its tabs: a window always keeps one pane.
  • In a standalone terminal window, new opens a terminal in the new pane.
  • Each call waits up to 5 seconds for the window, and fails with no reply from the window (is it open in a browser?) when it does not answer.
  • A --tab-name held in two windows is refused, not guessed.

Output and exit codes

Lists print Markdown. terminal list, pane, window list, session and search take --json, and --pretty to indent it. Results go to stdout, such as a new pane's id or a survey's answer; confirmations such as queued at position 1 go to stderr.

ExitMeaning
0Done, or queued to a live window. A queued tab or message arrives a moment later.
1Failed: refused, nothing matched, or a close blocked by unsaved work.
124Nothing answered in time, as when a survey, a copy or paste, or a tunnel waits too long.
69Only from an older devserver, which could refuse a --submit. The text was still queued.
