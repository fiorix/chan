Chan Desktop does not open

  • A second start brings the running copy forward: its last focused window, or a new standalone terminal when none shows.
  • Chan is not responding: quit the running copy, or end its chan-desktop process (Force Quit on macOS, Task Manager on Windows), then start again.
  • Chan is still shutting down: wait for that copy to exit, or end its process, then start again.
Details and limits
  • While the running copy is still starting, a second start opens nothing more: its windows are on their way.
  • Each Windows account runs a copy of its own.
  • On Windows a start waits up to 30 seconds for a copy that is still starting.
  • Started from a terminal, a start that fails prints the reason there instead of showing a dialog, and exits with status 1.

Windows you cannot find or close

  • Show a hidden window from its row on the Computers screen, with h or its eye.
  • With every window hidden, start Chan Desktop again, or click its Dock icon on macOS: a standalone terminal opens.
  • A pane that flips instead of closing has tabs on its other side: close those too.
  • A window the session leader closed is gone, with its terminals. Only the leader shows a window it hid: ask for leadership with cs session handover.

Devserver connections

  • Reconnecting: wait, or press Reconnect to run the script again, or Abandon.
  • Process exited: read why in the control terminal, close it with Ctrl+D, and connect again.
  • Connection lost: press o on the card to disconnect, then again to connect.
  • Did not come up in time: check that the Address matches the local end of the script's tunnel, as in the recipes.
  • Protocol or token: update the older side. After rotate-token, open the URL chan devserver status prints, or paste it into the devserver's Address.
Details and limits
  • An ssh tunnel dies when the laptop sleeps or the network changes; Eternal Terminal reconnects across both.
  • To update a devserver, run chan upgrade, then chan devserver restart, on its machine.
  • A connected devserver's settings are read-only: disconnect before you edit its Address.
  • A devserver with no token in its Address reads the new one from its connect script at the next connect.

cs refuses

  • Run cs in a chan terminal. Over ssh only cs terminal status and cs dump-skill work.
  • No longer running or no CHAN_CONTROL_SOCKET: open a new terminal. If that fails too, the server's start-up log says why.
  • Standalone terminal: open the directory with chan open PATH and run the command in that window.
  • No match: cs terminal list shows every terminal's name and group.
  • No reply: show the window from Computers, or name another with --window.

chan serve and chan open

  • Inside a repository: serve the root the message names, or add --here.
  • Held by another process: chan ps names what serves it, and chan close PATH stops it. When your devserver holds it, chan serve --devserver PATH registers it there.
  • Port in use: add --port 9000, or --devserver=8787 when your devserver holds the port.
  • Live terminals: close them first. --no-settings: add --standalone. Several devservers: add --devserver=PORT.
Details and limits
  • A foreground chan devserver run shares ~/.chan with Chan Desktop, so a workspace Chan Desktop serves shows there as Locked. Give it its own CHAN_HOME.
  • The repository refusal exits with status 70 and prints both commands to run.
  • A chan serve in the foreground also stops with Ctrl+C.
  • Closing a workspace with live terminals has no override.

tmux control mode

  • Turn it on in Settings → Terminal → tmux control mode (tmux -CC), or with chan config set terminal.tmux.enabled true.
  • Use tmux 3.2 or newer where tmux -CC runs.
  • Answer the banner within 60 seconds, or trust the program in front, such as ssh, with terminal.tmux.trust.

Default apps on Linux

  • A list named for your desktop, such as ~/.config/hyprland-xdg-terminals.list, comes before xdg-terminals.list.
  • The AppImage cannot be the default terminal: install the Arch, Ubuntu, Fedora or Nix package.
  • xdg-mime query default text/markdown names the app in effect, and xdg-mime default changes it.
  • The chan package's chan-term, chan-files and chan-edit need Chan Desktop running and a display.
Details and limits
  • xdg-utils 1.1 reads only ~/.config/mimeapps.list.
  • With CHAN_NO_DESKTOP_HANDOFF set, these commands open nothing and say so; unset it.
  • The full setup is in Default terminal and File browser and Markdown editor.
